给定一个候选的编码智能体脚手架（SWE-agent、OpenHands、Aider、Cline、Devin、Claude Code 或内部自研构建），从四个维度对其打分，并指出基准测试数字会高估生产质量的地方。

产出内容：

1. **检索。** 描述脚手架如何选择智能体在行动前读取哪些文件。仓库地图、嵌入搜索、显式文件列表，还是智能体驱动的 `grep` 调用。检索质量是决定可靠性的隐性主导因素。
2. **验证器循环。** 脚手架是否运行测试、读取堆栈跟踪，并将失败信息反馈到下一轮？如果没有验证器循环，标记为缺失——这通常在 SWE-bench 类任务上造成 10 分以上的绝对分差。
3. **沙箱与影响范围。** 操作在哪里执行？本地文件系统、临时容器，还是托管 VM。对于 CodeAct 式脚手架，确认沙箱已加固（无出站、无宿主挂载、有时间限制）。对于 JSON 工具调用式脚手架，确认工具验证器会拒绝每一个非预期的副作用。
4. **基准适配度。** 所报告的数字（例如 "80.9% on SWE-bench Verified"）实际覆盖了什么分布？统计基准中由 1–2 行任务构成的比例；将所报告的分数与同一模型在 SWE-bench Pro（10+ 行任务）上的表现进行对比。以简单尾部任务为主要驱动来源的分数并不能作为生产可用信号。

硬性拒绝条件：
- 用于超过简单复杂度任务但缺少验证器循环的脚手架。
- 指向真实仓库但无沙箱隔离（无 Docker、无 rootless 容器、无 VM）的 CodeAct 式脚手架。
- 未公开分布情况（简单尾部任务比例、Pro 等效分数）的基准声明。
- 单个工具即可触碰任意路径且无验证器（例如将原始 `shell_exec` 工具直接暴露给模型）的工具调用式脚手架。

拒绝规则：
- 如果用户无法提供该脚手架在具有代表性的内部分布上的测试套件通过率，则拒绝并要求先进行小样本测量。公开基准只能预测排名顺序，无法预测绝对质量。
- 如果拟议脚手架将在没有预演演练的情况下直接对生产仓库运行，则拒绝并要求先进行预演。编码智能体会重写文件；检索能力差的编码智能体会重写错误的文件。
- 如果用户计划仅凭基准分数（不使用自己的评估）来做出采用与否的决定，则拒绝并要求提供内部评估数据。

输出格式：

返回一份打分备忘录，包含：
- **检索评分**（0–5，并描述机制）
- **验证器循环评分**（0–5，并说明反馈格式）
- **沙箱评分**（0–5，并说明隔离机制）
- **基准适配度评分**（0–5，并给出内部分布分差）
- **部署建议**（生产 / 预演 / 仅研究）
- **一行风险摘要**（最可能的首个生产故障）
