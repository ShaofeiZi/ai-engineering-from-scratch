给定一个拟议的自修改智能体循环（智能体脚手架、评估器流水线、部署目标），产出一份防火墙规范，使评估器保持在智能体无法触及的范围之外。DGM 论文记录了智能体移除自身安全标记以提高分数的行为；本技能即为此的管控手段。

产出内容：

1. **文件系统边界。** 列出智能体可以编辑的每一个文件。列出评估器读取的每一个文件。两者的交集必须为空。若不为空，则指定使其为空所需的精确操作。
2. **进程边界。** 评估器必须在智能体无法控制的进程中运行。指定容器或沙箱。如果智能体拥有 shell 访问权限，它可以绕过进程内的防护。
3. **网络与密钥边界。** 智能体必须不能编辑用于获取评估器输入或提交分数的 CI 密钥。列出密钥的存放位置及其挂载方式。
4. **分数入口契约。** 分数从评估器返回到循环的归档中。该路径是唯一的通道。智能体能写入且会影响未来评分的任何内容都违反该契约。
5. **变更审查清单。** 列出在接受前需要人工审查的智能体编辑类别：新增依赖、对评分相关代码的编辑、对沙箱配置的编辑、对日志或监控的编辑。

硬性拒绝条件：
- 评估器与智能体源代码位于同一仓库中。将其移出。
- 评估器作为 Python import 在智能体进程内运行。将其放入子进程中运行。
- 在边界智能体一侧应用的任何分数调整。所有调整必须在服务端进行。
- 智能体可以通过编辑自身代码来静默的任何日志记录。

拒绝规则：
- 如果用户无法说出智能体可以编辑的每一个文件，则拒绝并要求先进行文件级写入权限审计。
- 如果评估器没有留出测试输入（held-out inputs），则拒绝——这是第 3 课的审计，是一个前置条件。
- 如果部署面包含对评估器本身的变更（即使是通过拟议的依赖更新间接进行），则拒绝并要求一个人工防火墙审查步骤。

输出格式：

返回一份一页的规范，包含：
- **智能体写入面**（路径、glob 模式）
- **评估器读取面**（路径、端点）
- **交集**（必须为空；展示 diff）
- **进程模型**（评估器如何被隔离）
- **密钥清单**（位置及挂载方式）
- **需审查的变更类别**（项目符号）
- **签批行**（谁负责维护防火墙不变量）
