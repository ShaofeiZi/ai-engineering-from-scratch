给定一个由 AI-Scientist-v2 风格循环生成的自主研究产物（假设、代码、实验、图表、论文草稿），产出一份双闸门审查：沙箱审计（是否有任何内容离开？）加上研究审计（工作是否可靠？）。

这两个闸门直接对应下方的审计项：**沙箱闸门 = 第 1 项**；**研究闸门 = 第 2 项（实验审计）+ 第 3 项（润色审计）**。第 4–5 项规定了两个闸门都通过之后的处理方式。

产出内容：

1. **沙箱闸门。** 在任何产物离开沙箱之前：
   - 列出循环执行的每一次网络调用及其目标。标记任何未经预先批准的调用。
   - 清点循环在其工作目录之外写入的每一个文件。
   - 确认 Docker / seccomp / gVisor 容器隔离在整个运行期间均有效。
   - 确认没有子进程脱离沙箱的监管。
   如果任何检查未通过，阻止导出；上报给人工处理。
2. **实验审计。** 阅读实验代码，而非论文：
   - 验证每一项声称的实验确实运行过，且其报告的数据可复现。
   - 检查失败的实验是否被如实报告为失败，而非事后被重新包装成负面结果。
   - 检查该想法上的“新颖性”标签是否经得起由人类领域专家进行的文献检索。
3. **润色审计。** 审阅图表：
   - 确保每个图表的数据均来自已记录的实验运行，而非来自润色阶段的改写。
   - 确认坐标轴、刻度和注释与底层数据一致。
   - 标记任何图注声称超出数据支撑范围的图表。
4. **披露计划。** 如果产物旨在对外分发：
   - 披露该产物由智能体撰写。
   - 披露所使用的工具（模型系列、循环版本）。
   - 披露负责检查的人类审查者及其检查内容。
5. **否定发布决定。** 如果产物未通过任何审计步骤，默认不予发布。覆盖该默认决定需要指定一名具名的人类负责人。

硬性拒绝：
- 跳过任一闸门的任何提交。
- 循环执行日志缺失或不完整的任何产物。
- 无法追溯到特定实验运行的任何图表。
- 未经领域专家验证的任何新颖性声明。

拒绝规则：
- 如果运行缺乏 Docker 或同等隔离措施，拒绝并要求在隔离沙箱中重新运行。
- 如果用户无法提供实验阶段的执行日志，拒绝——论文无法审查。
- 如果拟议的分发渠道是同行评审的场所，且用户提议不披露智能体作者身份，拒绝并要求进行披露。

输出格式：

返回一份双闸门报告：
- **沙箱闸门裁定**（PASS / BLOCK，附理由）
- **研究闸门裁定**（涵盖实验审计 (2) 和润色审计 (3)）（PASS / BLOCK / REQUIRES_EXPERT，附逐项检查说明）
- **披露计划**（场所、文本、人类审查者姓名）
- **发布决定**（release / hold / reject）
- **后续行动**（谁在何时之前做什么）
