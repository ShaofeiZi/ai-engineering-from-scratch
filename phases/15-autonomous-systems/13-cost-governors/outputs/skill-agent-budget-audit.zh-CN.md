给定一个拟议的智能体部署，对照十二层参考模型审计其成本管控层栈，并标记哪些层级缺失、调参不足或调参过度。

产出：

1. **层级清单。** 对于十二个参考层级中的每一层（单次请求上限、单任务 token 预算、单任务美元预算、单工具上限、迭代上限、按分钟/小时/天/月滚动上限、速率限制、分层路由、prompt caching、上下文窗口化、HITL 检查点、kill switch），说明是否已配置，以及配置为何值。
2. **失效模式映射。** 对于每个时间尺度的失效（失控循环、缓慢渗漏、不良发布、合法激增），指出捕获该失效的具体层级以及响应速度。
3. **工具专属上限。** 列出智能体可调用的每一个工具。对每个工具，给出单会话上限及理由。任何没有显式上限的工具都是一个开放漏洞。
4. **告警阈值。** 与上限分离：在何种花费速率下会触发人工分页？观测到的电商案例（$1,200 → $4,800）是一个周环比增长问题，而非月度上限问题。
5. **Kill-switch 路径。** 当某个上限触发时，会发生什么？干净中止、回滚、告警、重新启用流程。确认 kill switch 位于智能体外部（智能体无法编辑自己的上限）。

硬性拒绝条件：
- 任何没有单任务美元预算的自主部署。
- 任何没有速率限制的无人值守长周期运行。
- 新增工具（<30 天）的工具面没有单工具上限。
- 智能体自身可以修改的 kill switch。
- 仅以月度上限作为唯一上限（其他所有时间尺度均无防护）。

拒绝规则：
- 如果用户无法按当前模型价格为一个最坏情况运行定价，则拒绝并要求提供已核算成本的估算。
- 如果拟议预算超过组织对单次失误的可接受损失，则拒绝并要求设置更低的上限。
- 如果用户将 Auto Mode 分类器（Lesson 10）视为预算的替代品，则拒绝。分类器与成本正交；两层都是必需的。

输出格式：

返回一份成本管控审计，包含：
- **层级表**（层级名称，是否已配置 y/n，值）
- **失效模式覆盖**（4 行：loop / leak / release / surge）
- **工具专属上限**（工具，上限，理由）
- **告警阈值**（速率，负责人，渠道）
- **Kill-switch 路径**（触发条件，动作，重新启用流程）
- **就绪状态**（production / staging / research-only）
