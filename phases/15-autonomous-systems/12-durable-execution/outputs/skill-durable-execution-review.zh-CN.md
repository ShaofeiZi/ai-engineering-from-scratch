给定一个提议中的长运行智能体部署（Temporal + OpenAI Agents SDK、带 PostgreSQL checkpointer 的 LangGraph、Microsoft Agent Framework、Claude Code Routines、Cloudflare Durable Objects，或自研的等价方案），对照持久化执行模式对设计进行审查。

产出：

1. **活动清单。** 列出每一个活动（LLM 调用、工具调用、HTTP 请求、文件写入）。对每个活动，确认它已被包装为带有重试策略、超时和幂等键的活动。活动封装之外的原始 LLM 调用是可靠性漏洞。
2. **工作流确定性。** 识别工作流代码内部的每一处非确定性读取（墙上时钟、随机数、外部状态）。每一处都必须注册为副作用活动，以便重放时返回相同的值。隐藏的非确定性是重放漂移最常见的原因。
3. **检查点后端。** 指明后端名称（PostgreSQL、SQLite、Redis、Durable Objects）。确认它能在部署后存续。SQLite 仅限开发使用。Redis 需要 AOF 或快照配置。Cloudflare Durable Objects 是透明的，但要求严格的唯一键纪律。
4. **人类输入状态。** 确认用于 HITL 的暂停是一等的工作流状态，而非轮询循环。工作流应阻塞在外部信号（审批队列、webhook、`interrupt()` 原语）上，该信号在审批到达时恰好恢复执行。
5. **恢复时 HITL 策略。** 对于崩溃后的任何恢复，说明在执行下一个活动前是否需要重新进行 HITL。若缺少该策略，持久化执行加上崩溃前已授予的审批，可能会在上下文已发生变化时重新触发一个已批准的动作。对于长时间跨度运行至关重要。

硬性拒绝：
- Agents SDK 的使用中 LLM 调用未被包装为活动。
- 检查点后端无法在部署后存续。
- 工作流内嵌了墙上时钟或随机数而未进行活动包装。
- 人类输入被建模为轮询循环而非信号。
- 长时间跨度运行（超过一小时）没有恢复时 HITL 策略。
- 运行没有预算熔断开关（第 13 课）叠加在持久性之上。

拒绝规则：
- 如果用户提出的持久化工作流对副作用活动没有显式幂等性，则拒绝并首先要求幂等键。否则重试将导致重复执行。
- 如果用户无法展示重放测试（运行工作流、运行中崩溃、重放、断言无重复副作用），则拒绝并要求在生产前提供该测试。
- 如果用户提出 24 小时无人值守运行且没有 HITL 检查点，则拒绝。35 分钟的性能退化（第 12 课注释）使其即使持久性正确也会成为可靠性问题。

输出格式：

返回一份设计审查备忘录，包含：
- **活动表**（活动、重试策略、超时、幂等键）
- **确定性审查**（非确定性读取及其各自的处置方式）
- **检查点后端**（名称、部署后是否存续 y/n、重放测试状态）
- **HITL 状态结构**（一等状态 / 轮询 / 缺失）
- **恢复时 HITL 策略**（显式说明，附理由）
- **就绪度**（production / staging / research-only）
