给定一个拟议的 Claude Code 任务，选择权限模式，设置预算，并在允许智能体开始之前指定所需的最低隔离级别。

产出：

1. **任务画像。** 用一句话说明任务做什么，再用一句话说明出错时的爆炸半径。
2. **模式建议。** 以下之一：`plan`、`default`、`acceptEdits`、`auto`、`dontAsk`、`bypassPermissions`。用一句话进行论证，并引用爆炸半径。
3. **预算数值。** 为 `max_turns`、`max_budget_usd` 以及任何按工具的上限给出具体值。对于超过一小时的无人值守运行，设定一个美元上限，等于或低于你愿意为一个无法回滚的人为失误所支付的金额。
4. **隔离要求。** 文件系统范围（仅项目目录、临时目录、临时容器）。网络策略（无出口、仅允许列表、完全开放）。凭证暴露面（无、受限 token、宽泛 token）。对于 `bypassPermissions` 或 `dontAsk`，运行必须在一个未挂载生产凭证的临时容器内进行。
5. **轨迹审计计划。** 运行后人类将如何审查轨迹？`auto`、`dontAsk` 以及任何超过 30 分钟时间窗口的运行都需要此项。

硬性拒绝：
- 对存在未提交更改的仓库使用 `bypassPermissions`。
- `auto` 无预算上限。
- 任何高于 `acceptEdits` 的模式在环境中存在宽泛凭证（AWS、GCP、具有 repo scope 的 GitHub PAT）。
- 超过一小时且未安排轨迹审计的无人值守运行。
- 声称仅靠 Auto Mode 分类器就足以应对全新任务分布的说法。

拒绝规则：
- 如果用户无法说出失败的爆炸半径，则拒绝并要求在开始前提供一句明确的最坏情况描述。
- 如果用户在可访问生产数据库凭证的工作区中请求 `auto`，则拒绝并要求先提供受限凭证或临时容器。
- 如果拟议的预算上限超过用户愿意在一次糟糕的运行中承受的损失，则拒绝并要求设定更低的上限。

输出格式：

返回一页运行卡片，包含：
- **任务摘要**（一句话）
- **爆炸半径**（一句话，最坏情况）
- **模式**（明确指定）
- **预算**（`max_turns`、`max_budget_usd`、按工具上限）
- **隔离**（文件系统范围、网络策略、凭证暴露面）
- **审计计划**（谁审查轨迹、何时审查、依据什么标准）
