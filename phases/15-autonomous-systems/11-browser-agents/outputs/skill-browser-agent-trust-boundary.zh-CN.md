给定一个拟议的浏览器智能体工作流，产出一份信任边界范围界定文档，枚举每一次读取、每一次写入，以及首次运行所需的最低防御栈。

需要产出：

1. **读取面。** 列出智能体将抓取的每一个源站。将每个源站分类为受信（由用户所在组织运营的第一方站点）或非受信（任何第三方、任何用户生成内容、任何搜索结果）。所有非受信读取都必须被视为潜在的提示词注入通道。
2. **写入面。** 列出智能体被授权执行的每一个有后果的操作（提交表单、发布内容、调用后端工具、写入记忆）。针对每一项，说明其影响范围以及该操作是否可逆。
3. **所需防御。** 最低栈：内容净化器、读/写边界（当 content_origin 为非受信时，写入需要重新审批）、按任务配置的工具允许列表、使用受限凭据的会话隔离、持久化记忆上的金丝雀令牌、不可逆操作上的 HITL。
4. **基准到分布的契合度。** 如果智能体报告了 BrowseComp、OSWorld 或 WebArena-Verified 分数，指出基准测试与真实任务之间的分布重叠。高 BrowseComp 分数并不能预测预订流程的可靠性。
5. **已知攻击检查清单。** 确认部署已针对以下攻击进行加固：(a) 可见文本注入，(b) URL 片段 / 查询注入，(c) 记忆绑定攻击（Tainted Memories 类），(d) 针对已认证会话的 CSRF 型攻击，(e) 一键劫持。针对每一项，说明具体的防御措施及其触发位置。

硬性拒绝条件：
- 可访问生产凭据且无会话隔离的浏览器智能体。
- 任何由非受信内容发起的写入不需要重新 HITL 审批的部署。
- 任何仅依赖内容净化器的部署（净化器只能拦截简单攻击；复杂载荷可绕过）。
- 无金丝雀条目的持久化记忆。
- 涉及金融交易或客户数据且写入无 HITL 的工作流。

拒绝规则：
- 如果用户无法说明由注入驱动的错误写入的影响范围，则拒绝并要求其给出明确的陈述句。
- 如果用户提出的浏览器智能体所处技术栈无法提供受限凭据，则拒绝并要求其先提供独立身份。
- 如果用户引用基准测试分数（BrowseComp、OSWorld、WebArena）作为智能体"能"完成生产任务的证据，则拒绝并要求在真实分布上进行内部评估。

输出格式：

返回一份信任边界备忘录，包含：
- **读取面表格**（源站、受信 / 非受信）
- **写入面表格**（操作、影响范围、是否可逆 y/n）
- **防御栈**（已配置层的项目符号列表）
- **基准契合度说明**（如适用）
- **已知攻击检查清单**（五行，每行注明防御措施）
- **部署裁定**（production / staging / research-only）
