给定用户请求和工具目录（名称、输入 schema、描述），生成一个 ReWOO 计划：一个由步骤组成的 DAG，包含工具调用和证据引用（`#E1`、`#E2`、...）。在将计划交给执行器之前先对其进行验证。

产出内容：

1. 一个计划 DAG。每个节点包含 id（`E1`、`E2`、...）、工具名、参数字典（字符串中可包含 `#E<k>` 引用）以及可选的 `parallel_group` 标签。
2. 验证输出。通过拓扑排序进行无环性检查；引用解析检查（每个 `#E<k>` 都有前驱的生产者）；工具存在性检查（每个工具名都存在于目录中）；参数 schema 检查（每个参数都与工具的输入 schema 匹配）。
3. 并行度提示。对于每个拓扑层级，列出可以并发执行的节点。
4. 规划器/求解器拆分建议。如果计划少于 3 个步骤，则推荐使用 ReAct。如果计划有无界循环需求（每一步都需要重新规划），则推荐使用带重规划器的 Plan-and-Execute。如果计划超过 30 个步骤或面向 Web/移动端，则推荐使用带合成计划数据的 Plan-and-Act。

硬性拒绝：

- 包含环的计划。ReWOO 假定 DAG 结构；环是 ReAct 或 LATS 需要处理的问题。
- 在拓扑序中引用尚未存在的 `#E<k>`（其中 `k` 尚未出现）的计划。输出失败的具体边。
- 调用不在目录中的工具的计划。不要为了使计划成立而凭空发明工具。
- 引用的参数类型与工具 schema 不匹配的计划（例如，`#E1` 替换为字符串，但工具期望的是 int）。

拒绝规则：

- 如果任务是开放式探索（需要未知工具、步骤未知），则拒绝并推荐使用 ReAct 或 LATS（第 04 课）。
- 如果工具目录中包含破坏性工具但没有门控审批工具，则拒绝并指向第 09 课（权限、沙箱化）。

输出：一个结构化计划（JSON 或 YAML）、一份验证报告、一份并行度映射，以及一个指向执行器（ReWOO Worker）、重规划器（Plan-and-Execute）或更大轨迹采样循环（Plan-and-Act）的后续动作。

最后以一条"接下来阅读什么"的说明结尾：如果该任务类别此前已被尝试过，则指向第 03 课（Reflexion）；如果计划将受益于搜索，则指向第 04 课（LATS）。
