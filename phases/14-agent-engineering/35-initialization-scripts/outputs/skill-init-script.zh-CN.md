给定一个代码库、智能体产品及其依赖面，产出一份项目专属的初始化脚本和 CI 配置。

需要产出：

1. `tools/init_agent.py`，包含以下探针：运行时版本、已列出的依赖项、测试命令可解析性、所需的环境变量、状态文件新鲜度。
2. `init_report.json` 的 schema 文档放在脚本旁边。每个探针返回 `(name, status: pass|warn|fail, detail)`。
3. `.github/workflows/agent-init.yml`（或等效文件），运行该脚本，并在任何 fail 严重级别的探针失败时阻断智能体任务。
4. 一个 `pre-task` 钩子脚本，供智能体运行时在每次会话开始前调用。
5. 在 `docs/init.md` 中编写文档，列出每个探针、其严重级别以及如何修复失败。

硬性拒绝：

- 没有超时机制就向网络发起调用的探针。初始化必须快速且离线安全。
- 需要 LLM 调用的探针。初始化是确定性的基础工程。
- 被包装器吞掉的非零退出码。大声失败（fail loud）才是全部意义所在。
- 不具备幂等性就触碰状态的探针。连续两次运行必须在除时间戳外产生完全相同的报告。

拒绝规则：

- 如果项目没有测试命令，拒绝交付该脚本。改为将该缺口加入 workbench 审计。
- 如果环境变量列表包含脚本会打印的密钥，拒绝并强制脱敏。初始化报告绝不应携带密钥。
- 如果某个探针在 dry run 中耗时超过三秒，在交付前先披露该耗时发现。过长的探针会把初始化变成繁文缛节。

输出结构：

```
<repo>/
├── tools/
│   ├── init_agent.py
│   └── pre_task.sh
├── docs/
│   └── init.md
└── .github/
    └── workflows/
        └── agent-init.yml
```

- 第 37 课，关于消费已解析测试命令的运行时反馈回路。
- 第 38 课，关于依赖探针通过的验证关卡。
