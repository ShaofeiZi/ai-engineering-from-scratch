给定一个目标运行时、一个主模型以及一个（可能更强的）休眠期模型，产出一个具备显式块类型和异步整合的三层记忆系统。

产出内容：

1. `Block` 类型，包含 `label`、`value`、`limit`、`description`、`version`、`history`。每次写入都会递增 version 并记录旧值。暴露 `near_limit(threshold=0.8)`。
2. 一个 `BlockStore`，至少包含三个默认块：`human`（关于用户的事实）、`persona`（智能体自我认知）和 `task`（当前范围）。允许用户自定义块。
3. 一个 `Recall` 存储——按会话分页的对话日志。每轮自动写入。达到上限时尾部淘汰，但仍可检索。
4. 一个 `Archival` 存储——至少两种后端（向量、KV）。插入操作返回记录 id。遇到矛盾时执行失效而非删除。
5. 一个 `PrimaryAgent`，负责处理对话轮次，只执行原始写入。关键路径上不做摘要。
6. 一个 `SleepTimeAgent`，在对话轮次之间运行：对超过阈值的块进行摘要、使矛盾的归档记录失效、将 `learned_context` 写入共享块。

硬性拒绝条件：

- 任何在面向用户的对话轮次期间同步运行的记忆操作，除直接查找外一律拒绝。摘要、整合、失效属于休眠期流程。
- 遇到矛盾时删除归档记录。应执行失效以保留可审计的历史。
- 未经审查步骤即写入 Persona 或 Safety 块。这些块全局性地影响行为；静默写入会掩盖缺陷。

拒绝规则：

- 如果运行时无法跨会话持久化块，拒绝交付被描述为「记忆」的产品。应降级其声明。
- 如果休眠期智能体没有追踪输出，拒绝。静默整合是调试盲区。
- 如果用户要求「不执行失效，始终信任最新写入」，对于历史声明至关重要的领域（合规、医疗、法律）一律拒绝。

输出：每个组件一个文件，外加一个 `README.md`，说明默认块、休眠期节奏以及矛盾解决策略。以「延伸阅读」结尾：如果智能体需要对记忆进行图推理，指向 Lesson 09；如果产品需要对记忆操作添加 OTel spans，指向 Lesson 23。
