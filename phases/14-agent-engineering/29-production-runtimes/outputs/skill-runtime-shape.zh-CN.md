给定任务类别（预期时长、步骤数、触发类型、延迟预算），选择运行时形态。

决策：

1. < 30s，用户等待 -> **请求-响应**。
2. 渐进式 UX 或语音 -> **流式**。
3. 数分钟到数小时，用户不等待 -> **基于队列**。
4. 对外部事件做出反应 -> **事件驱动**。
5. 周期性维护 -> **cron**。
6. 以上任意一种且重启成本高 -> 增加 **持久化执行**。

产出：

1. 你的技术栈中的形态脚手架。
2. 可观测性：OTel GenAI spans（第 23 课），后端已接入（第 24 课）。
3. 对于队列：DLQ + 重试策略 + 队列深度指标。
4. 对于事件：显式订阅者注册表 + 回放路径。
5. 对于 cron：锁文件或分布式锁以防止运行重叠。
6. 对于持久化：checkpointer 后端 + 恢复语义。

硬性拒绝：

- 对 5 分钟的任务使用同步 HTTP。用户挂起；worker 堆积。
- 基于队列但无 DLQ。失败任务消失。
- 后台工作无 trace 导出。失败不可见，直到用户投诉。
- “无持久化状态，我们直接重试。”长时间跨度必须 checkpoint。

拒绝规则：

- 如果产品有 SLA + 回放需求，拒绝 swarm 拓扑 + 非持久化运行时。
- 如果任务受合规约束，拒绝无审计轨迹的事件驱动。
- 如果用户想要 cron + 无锁，拒绝。重叠的 cron 运行最好的情况是重复工作，最坏的情况是数据损坏。

输出：运行时脚手架 + 可观测性钩子 + 包含 SLA、重试策略、checkpointer 选择的 README。以“下一步阅读”结尾，指向第 23 课（OTel）、第 24 课（可观测性）或第 17 课（Managed Agents 用于托管长时间运行）。
