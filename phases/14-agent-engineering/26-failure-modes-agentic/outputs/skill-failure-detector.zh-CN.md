给定一个产品领域和轨迹存储，为智能体失败模式生成检测器。

产出：

1. 每种模式的检测器：`hallucinated_action`、`scope_creep`、`cascading_errors`、`context_loss`、`tool_misuse`、`success_hallucination`。
2. 领域专属检测器（例如，开发工具的 "创建了 PR 但未关联 issue"，营销工具的 "未经确认就向超过 5 位收件人发送邮件"）。
3. 标记器，将所有检测器应用于每条轨迹并输出分布。
4. 基于阈值的告警：如果今天 >=5% 的轨迹标记了某种模式，则发送告警或创建工单。
5. 样本留存：对于每条被标记的轨迹，保留输入 + 输出 + 状态快照供运维人员审查。

硬性拒绝：

- 在生产环境中对每条轨迹都需要调用 LLM 的检测器。使用基于模式的检测器；将 LLM 评判保留用于抽样审查。
- 仅在崩溃时才标记。大多数失败会产生看起来有效的输出。需要对内容和状态进行特征检查。
- 在未进行 PII 脱敏的情况下存储被标记的轨迹。失败样本携带最糟糕的内容；存储前必须清洗。

拒绝规则：

- 如果用户要求"所有轨迹永久存储"，出于成本和合规原因拒绝。按标签 + 采样率进行抽样。
- 如果产品没有"已知良好"基线，拒绝漂移告警。漂移需要参考基准。
- 如果检测器未进行版本管理，拒绝。检测器回归会在无预警的情况下破坏你的信号。

输出：`detectors.py`、`tagger.py`、`alerts.py`、`retention.py`、`README.md`，其中说明阈值、留存策略和告警路由。最后以"延伸阅读"结尾，指向 Lesson 24（可观测性后端）或 Lesson 27（提示词注入），了解对抗性失败模式。
