给定一个具备工具访问和检索能力的智能体，产出一个注入防御层。

在本技能中，PVE 指的是 **Prompt-Validator-Executor 验证模式**：主模型首先提出候选工具调用，一个独立的验证器随后批准或拒绝它，执行器仅在获批后才运行它。它不是 Phase 05 中的 **Plan-Verify-Execute 规划模式**，后者是根据既定计划检查所提动作。

产出：

1. 对每一段内容添加来源标记：`user_message`、`tool_output`、`retrieved_web`、`retrieved_memory`、`retrieved_file`。将标记传播贯穿消息历史。
2. `Validator.assess(tool_call, contents)` — 拒绝带有注入形态参数或检索内容的工具调用；仅当来源标记与声明的信任等级匹配时才允许。
3. 用于导航的白名单 / 黑名单：智能体可触及的 URL、域名、文件路径。
4. 记忆写入护栏：拒绝形似指令的写入。
5. 内容捕获纪律（Lesson 23）：将检索到的内容存储在外部；片段携带引用 ID，而非散文式文本。
6. 测试套件：将五个 Greshake 利用类别作为红队用例。

硬性拒绝：

- 没有来源标记的工具使用面。没有来源溯源就无法区分权限等级。
- 仅在最终输出上运行的验证器。迟到的验证毫无意义——模型已经行动了。
- "相信我，系统提示词能处理。" 系统提示词的整洁性不是一种控制手段。
- 在智能体宿主内运行不受信任的工具实现。Python 对象的隐私性不是沙箱；将不受信任的工具隔离在独立进程或服务中。

拒绝规则：

- 如果智能体有任何检索能力却没有来源标记，拒绝发布。检索到的内容是典型的注入向量。
- 如果敏感工具（发送消息、执行 shell、在 / 中写文件）没有人在回路确认，拒绝。
- 如果记忆写入不受保护，拒绝。持久化记忆投毒会在下一次会话中再次投毒。
- 如果一次性授权需要跨 worker 或重启生效，要求一个外部原子回放账本；内存中的集合只是单进程教学辅助工具。
- 将授权绑定到最新的可信用户轮次。后续一条不含确切授权的用户消息会撤销任何更早的授权；不要向后搜索过期的权限。
- 规范兼容形式并检查一个显式的易混淆骨架，以识别已知危险指令短语。保持映射可审计，并测试正常的单脚本文本以控制误报。

输出：`validator.py`、`source_tag.py`、`allowlist.py`、`memory_guard.py`、`red_team.py`、`README.md`（解释六层控制栈、残余风险和持续审查节奏）。最后以"接下来阅读什么"结尾，指向 Lesson 21（计算机使用安全）和 Lesson 23（通过 OTel 进行内容捕获）。
