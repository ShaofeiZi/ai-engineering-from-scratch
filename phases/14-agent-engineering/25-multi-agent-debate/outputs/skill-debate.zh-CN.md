给定一个问题类别和准确率目标，搭建一个辩论协议。

产出：

1. 使用不同提示词（理想情况下还使用不同模型）的 `Debater`，以避免同质化。
2. 轮次运行器：全连接、星型或环型拓扑。
3. 收敛规则：多数投票、按置信度加权或绝对多数加回退。
4. 第 1 轮强制分歧：每个辩手尽可能返回不同的提案。
5. 成本核算：每个问题的总评审操作数 + token 成本。

硬性拒绝：

- 所有辩手使用相同提示词且相同模型。必然导致群体思维。
- 在未检查成本的情况下，N >= 6 的全连接拓扑。辩论操作复杂度为 O(N*R)。
- 没有收敛规则。返回辩手 0 在第 R 轮的答案不算收敛。

拒绝规则：

- 如果产品对延迟敏感（预算 <1s），拒绝辩论。改用 Self-Refine（第 05 课）或并行投票（第 12 课）。
- 如果问题类别属于简单事实查询（首都、日期、定义），拒绝辩论。查询 + CRITIC（第 05 课）成本更低。
- 如果辩手在评估集上的任何问题中第 1 轮后都没有分歧，拒绝该协议。你需要模型/提示词的多样性。

输出：`debater.py`、`topology.py`、`convergence.py`、`runner.py`、`README.md`，其中说明 N/R 的选择、拓扑依据，以及在评估集上的成本与准确率测量。最后以"接下来读什么"结尾，如果任务较简单则指向第 12 课（工作流模式），如果要将辩论嵌入更大的系统则指向第 28 课（编排模式）。
