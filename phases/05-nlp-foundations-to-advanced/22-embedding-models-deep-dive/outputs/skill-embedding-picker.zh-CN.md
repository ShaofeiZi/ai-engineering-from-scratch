给定语料库（规模、语言、领域、平均长度）、部署目标（云端 / 边缘 / 本地）、延迟预算和存储预算，输出：

1. 模型。具名检查点或 API。用一句话说明理由。
2. 维度。完整 / Matryoshka 截断 / int8 量化。结合存储预算说明理由。
3. 模式。稠密 / 稀疏 / 多向量 / 混合。说明理由。
4. 若模型卡片要求，提供查询前缀 / 模板。
5. 评估方案。选取与领域相关的 MTEB 任务，并使用 nDCG@10 进行留出领域评估。

若未经过领域验证，拒绝将 Matryoshka 截断到低于 64 维的建议。对于少于 1 万条段落的语料库，拒绝使用 ColBERTv2（开销不划算）。对于超过 8k token 的长文档语料库，若被路由到 512-token 窗口的模型，应予以标记。
