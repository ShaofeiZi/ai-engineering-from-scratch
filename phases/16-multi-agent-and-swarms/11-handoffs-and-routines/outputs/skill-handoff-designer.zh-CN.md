给定一个面向用户的任务（通常是分流或基于技能的路由），生成一份交接拓扑，可直接映射到 OpenAI Swarm 或 OpenAI Agents SDK。

需产出：

1. **智能体名册。** 每个智能体：名称、一句话用途、工具，以及它可以交接给哪些其他智能体。
2. **交接函数。** 每个智能体的工具签名。每个交接函数返回一个目标 Agent。
3. **上下文传递策略。** 对每条交接边：完整历史、最近 N 条消息或摘要快照。需给出理由。
4. **防护措施。** 每个智能体的输入验证（哪些 prompt 允许触发到敏感专家的交接），必要处在交接时进行认证。
5. **循环检测。** 检测乒乓式交接的规则（例如"A 交接给 B；B 又交接回 A"连续出现超过一次）。
6. **回退行为。** 当交接目标缺失（智能体被移除、认证失败）时，由哪个智能体接管会话。
7. **会话/记忆方案。** 使用 Agents SDK sessions、调用方管理的记忆，还是完全无状态。

硬性拒绝条件：

- 任何不含循环检测的交接设计。
- 将完整历史传递给具有不同工具权限的专家的交接函数（安全风险）。
- 假定 Swarm 无状态行为却又需要多轮记忆的设计——应改用 Agents SDK sessions。

拒绝规则：

- 若任务需要并行执行，拒绝 Swarm 并推荐监督者（第 05 课）。
- 若任务需要确定性审计/回放，拒绝并推荐 LangGraph 静态图。
- 若任务是简单的阶段式 DAG（研究 → 编码 → 审查），推荐 CrewAI Sequential。

输出：一页交接简报。以安全说明收尾：说明 prompt 注入如何可能触发非预期交接，以及哪些防护措施可阻断它。
