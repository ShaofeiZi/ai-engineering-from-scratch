给定一个多智能体框架（或使用某框架的代码库），产出四原语映射，使读者能够用一段话理解该框架。

产出内容：

1. **智能体定义。** 智能体是如何构造的？有哪些参数？携带什么状态？命名确切的类或工厂。
2. **交接机制。** 它使用了三种交接模式中的哪一种 — 函数返回、图边，还是发言者选择？如果是混合模式，哪种是主要的？展示触发一次交接的最简代码。
3. **共享状态模型。** 是完整消息池还是投影视图？是内存中还是持久化（检查点）？是否对并发写入线程安全？由谁协调冲突？
4. **编排器类型。** 是静态的、LLM 选择的、交接驱动的，还是队列驱动的？如果是 LLM 选择的，默认用哪个模型？如果是静态的，图是带环的还是 DAG？
5. **跨轴权衡。** 每项一句话：确定性、可扩展性上限、可调试性、典型失败模式。

硬性否决条件：

- 任何声称某抽象是 "新的" 却未展示它不会归约为四个原语之一的映射。如果无法归约，精确指出差距所在，而不是凭空发明第五个原语。
- 仅引用营销文档的框架比较。必须引用框架仓库或官方 cookbook 中的具体代码示例。
- 诸如 "框架 X 更适合智能体" 之类的说法，却未指明该框架优化了哪个原语。

拒绝规则：

- 如果框架是闭源的，且公开文档不暴露智能体-交接-状态-编排器层面，声明在没有内部信息的情况下无法完成映射。
- 如果用户提供的是代码库但没有使用任何框架（手写智能体），则映射该自定义实现，并标记哪个原语设计不足。
- 如果框架早于 2024 年（如原始 AutoGen v0.2、Swarm 之前的版本）且不再维护，附注一行说明其继任者是否保留了该映射。

输出：一页框架简报。以一句话摘要开头（"框架 X 将交接固定为图边，并通过 reducer 暴露共享状态。"），然后是上述五个部分，最后以一段总结收尾，指出该框架的原语最适合哪类生产项目。
