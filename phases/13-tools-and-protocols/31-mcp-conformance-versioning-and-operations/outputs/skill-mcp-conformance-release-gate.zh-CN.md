针对 MCP 客户端、服务器、网关、SDK 或传输层的变更，生成线路级一致性测试套件以及带脱敏证据的发布决策。

## 所需输入

- 支持的现代与遗留协议版本，以及每个部署目标的策略。
- SDK 解码前的原始请求与响应抓包点。
- 镜像的 HTTP 头部、JSON-RPC 报文、状态码、内容类型，以及中间件拓扑。
- 声明的客户端、服务器及扩展能力。
- SDK 名称、版本、归一化值及异常。
- 健康阈值、灰度窗口、最小样本数及基线测量值。
- 精确的回滚版本、准入证据摘要、SHA-256 产物及描述符锁定、Registry 状态、当前健康状况、受信任的发布签名者，以及对完整回滚载荷的证明。
- 脱敏、留存及证据访问策略。

## 操作流程

1. 定义明确的协议时代。现代分支要求存在精确的 `io.modelcontextprotocol/protocolVersion` 和 `io.modelcontextprotocol/clientCapabilities` 键。将 `2025-11-25` 及之前的初始化时代行为放入单独的遗留适配器中。
2. 为每个目标选择严格或有限回退策略。成功的 `server/discover` 或被识别的现代错误可证明现代分支。超时或空响应不能证明任何东西。仅对已配置或已加入允许列表的端点允许遗留探测，然后在验证已锁定的遗留修订版存在正向 `initialize` 结果之后，才选择遗留分支。在 `-32020`、`-32021` 或 `-32022` 之后不得降级。
3. 为已接受的请求、有效的特定方法结果、已声明的扩展结果、选定的遗留行为，以及通知无响应不变式创建黄金记录。
4. 为以下情况创建负面记录：畸形的信封、响应版本或 ID 不匹配、result 与 error 互斥性违反、畸形错误、错误的 HTTP 映射、缺失元数据、头部与报文不匹配、缺失服务器错误响应、不支持的版本、缺失现代 `resultType`、畸形的方法载荷、未知或未声明的结果类型，以及被禁止的通知响应。每当本地校验观察到 `HeaderMismatch` 时，必须自动要求并结构化校验实际的 HTTP 400 JSON-RPC `-32020` 响应。仅凭本地异常不能通过该用例。
5. 首先校验 JSON-RPC 元数据类型。对 HTTP 头部名称进行大小写不敏感匹配，拒绝冲突的重复项，对不安全的 `Mcp-Name` 值解码精确的 Base64 哨兵值，然后在校验对匹配值的支持性之前，将 `MCP-Protocol-Version`、`Mcp-Method` 及适用的 `Mcp-Name` 值与报文进行比较。前导或尾随空白视为不安全，在以原始形式发送时予以拒绝，即使其与报文值相等。
6. 接受已知的现代 `complete` 和 `input_required` 结果。仅当其能力已被声明时才接受扩展判别符。拒绝每个未知或未声明的 `resultType`。然后校验方法载荷，包括 `tools/list` 的完整工具描述符、任务结果所需的声明周期字段，以及 `completion/complete` 的有界字符串值 completion 对象。
7. 在证据中保留原始的附加结果字段和 `_meta` 字段。明确决定每个组件是可以忽略它们还是必须转发它们。
8. 将每条高风险记录通过每个已发布的 SDK 运行。将原始线路语义与归一化返回值进行比较，并报告每个被合成、提升、剥离或更改的字段。
9. 直接执行测试套件，并通过每个生产中间件执行。抓取脱敏的入口、源端和出口证据。检测状态坍塌、JSON-RPC 报文重写、路由头部不匹配、缓冲，以及内容协商变更。
10. 在序列化、哈希、日志记录或上传之前执行脱敏。对字段和头部名称进行大小写折叠并移除分隔符，使 camelCase、连字符、下划线和点号变体共享同一黑名单，然后移除 `Authorization`、`Set-Cookie`、`X-Api-Key`、`accessToken`、`clientSecret` 和 `registrationAccessToken` 等凭证以及特定方法的敏感参数。对脱敏后的证据包进行哈希。
11. 根据非空的确定性记录、SDK 差异和代理证据，以及带有正向最小样本数的预声明健康窗口来评估候选版本。要求来自每个来源的有效证据摘要。省略的边界是门禁失败，而不是通过的空列表。
12. 在升级之前验证一个精确的已准入、已锁定、活跃、健康的回滚目标。校验精确的字段类型和 SHA-256 摘要，然后针对受信任的发布控制器身份加密校验其证明。仅当一致性、SDK、代理、健康和回滚就绪证据均通过时才升级。候选版本失败时，仅回滚到该已验证的目标。否则暂停。

## 所需矩阵

针对每个用例报告：

- 稳定的用例名称和规范性不变式
- 协议时代和选择证据
- 客户端、服务器、SDK、代理和构建版本
- 预期状态码、响应形状、结果类型或错误码
- 观察到的入口、源端和出口证据摘要
- SDK 归一化差异
- 每个边界的通过或失败
- 脱敏策略版本
- 最终原因码

至少包含以下用例：

- 黄金现代发现或方法调用
- 黄金已知 complete 结果（带附加字段）
- 黄金遗留用例（所选遗留时代中缺失 `resultType`）
- 黄金已声明扩展结果
- 黄金有效 `completion/complete` 结果
- 黄金通知（无 JSON-RPC 响应）
- 负面用例：头部与报文不匹配
- 负面用例：缺失能力
- 负面用例：不支持的已匹配版本
- 负面用例：缺失现代 `resultType`
- 负面用例：未知或未声明的 `resultType`
- 负面用例：代理状态或报文转换
- 负面用例：SDK 语义字段丢失
- 负面用例：畸形 `completion/complete` 结果

## 严格拒绝项

- 仅凭 SDK 返回值而无线路证据就声称一致性。
- 单个解析器静默接受现代和遗留两种形状。
- 在识别出现代错误后进行遗留回退。
- 仅基于超时、静默、连接关闭或无法识别的响应进行遗留回退。
- 在未抓取并校验服务器错误响应的情况下通过负面请求用例。
- 在本地检测到 `HeaderMismatch` 后将 HTTP 400 JSON-RPC `-32020` 证据设为可选。
- 在选择遗留时代之前对缺失的 `resultType` 推断为 complete。
- 将未知判别符视为 complete。
- 无保留字段原因就拒绝所有附加未知字段。
- 对通知发送任何 JSON-RPC 响应。
- 接受已知 `resultType` 但未校验特定方法载荷。
- 在未与报文进行相等性校验的情况下授权镜像头部。
- 将 HTTP 字段名称视为大小写敏感，或在不进行精确哨兵解码的情况下比较已编码的 `Mcp-Name`。
- 接受带前导或尾随空白的原始 `Mcp-Name`，而非要求哨兵编码。
- 在无有效有界字符串值 completion 对象的情况下接受 completion 结果。
- 将代理生成的 500 视为等同于源端协议错误。
- 将 bearer token、cookie、密钥或敏感参数写入证据。
- 使用让 camelCase 或分隔符变体绕过规范凭证黑名单的脱敏归一化。
- 声明零样本灰度为健康。
- 将空记录、SDK 或代理证据视为通过的边界。
- 将真值字符串或未认证的回滚字典视为已验证证据。
- 在无精确准入、锁定、状态和健康证据的情况下回滚到某版本。
- 在证明健康回滚目标之前升级生产候选版本。

## 产出内容

返回以下部分：

1. 时代策略：现代证明、严格目标、有限回退触发条件，以及禁止降级信号。
2. 记录矩阵：黄金用例和负面用例及其预期线路结果。
3. 结果兼容性：核心判别符、已声明扩展、附加字段策略，以及遗留推断边界。
4. SDK 差异：原始和归一化摘要，以及被提升、剥离、合成和更改的字段。
5. 代理证据：入口、源端和出口结果，以及精确的失败跳点。
6. 脱敏报告：策略版本、已移除字段类别，以及脱敏证据摘要。
7. 健康窗口：样本数、错误率、延迟、饱和度、持续时间、阈值，以及基线对比。
8. 回滚证明：精确目标、准入摘要、锁定、Registry 状态、健康状况、签名者身份、已验证证明，以及路由恢复计划。
9. 决策：`promote`、`hold` 或 `rollback`，附带稳定的原因码和完整证据摘要。

以第一个失败的边界结尾。如果所有边界均通过，则声明授权全量升级的灰度完成条件。
