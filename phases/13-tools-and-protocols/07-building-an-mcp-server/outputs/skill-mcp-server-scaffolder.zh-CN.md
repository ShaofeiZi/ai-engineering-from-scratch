给定一个领域，产出一个现代 MCP 服务器方案。保持应用状态显式，保持协议行为无状态。

产出：

1. 原语划分。定义原子化的工具（tools）、以 URI 寻址的资源和有用的提示词。当领域确实不需要某个原语时，将其省略。
2. 发现结果。提供 `supportedVersions`、服务器能力、可选的指令、`resultType: "complete"`、缓存提示，以及结果 `_meta` 中的服务器身份。
3. 请求校验器。要求每个 `params._meta` 中包含协议版本和客户端能力。当存在推荐的客户端身份时进行校验。版本不匹配时返回 `-32022`，并附带请求的版本和已支持的版本。
4. 结果包装器。为每个成功响应添加 `resultType: "complete"` 和服务器身份。为发现、列表、模板和资源读取添加 `ttlMs` 和 `cacheScope`。
5. 排序策略。为每个列表响应定义一个稳定的排序键。
6. 状态策略。将持久状态存入数据库，或以显式、不透明的句柄作为普通工具参数返回。绝不在协议会话中隐藏状态。
7. 兼容性边界。如需遗留支持，隔离一个 `2025-11-25` initialize 适配器。仅对遗留流量选择它，并独立测试两个时代。

硬性拒绝项：

- 现代服务器的首个有效方法必须是 `initialize`。
- 复用来自更早请求的能力、身份或版本。
- 在现代 HTTP 流量上返回 `Mcp-Session-Id`。
- 返回不带缓存提示的列表或资源读取结果。
- 将注解当作授权控制来处理。
- 从服务器发送独立的 JSON-RPC 请求。

拒绝规则：

- 如果被请求的资源会在未经授权的情况下暴露密钥，则停止并要求访问策略。
- 如果某个领域没有只读数据，则省略资源，而不是凭空发明。
- 如果某个领域没有可复用模板，则省略提示词，而不是填充凑数的内容。

输出一页架构说明、方法表、校验伪代码、结果示例、确定性排序规则，以及至少六项一致性测试。以应用状态与协议状态之间的边界作为结尾。
