# 评估契约

一个发布候选只有在所有必需的检查面都通过时才算通过：

- 结构：在读取配置之前，物理树预检会拒绝符号链接形式的根目录、父目录或入口、缺失的必需普通文件以及特殊文件。然后目录名需与 frontmatter name 一致，必需的元数据必须存在，运行时扩展必须被显式声明，直接引用必须能解析，包大小和类型限制需通过检查，不得存在明显的密钥特征，输出和失败契约必须存在，且不得附带未被引用的伴随文件。
- 触发：正向提示词应被激活，近似负向提示词应保持未激活。报告混淆计数、精确率、召回率以及每一次运行的原始预测结果。本地完整性将完整的观测序列和路由 fixture 绑定到其来源和 SHA-256 摘要，而不仅仅是第零次运行或聚合比率。
- 稳定性：重复运行每个用例并报告每个用例的通过率。
- 产物：对基线和带技能输出应用相同的断言。技能输出必须通过并展现出改进。生产声明将两份捕获的字符串绑定到其来源和 SHA-256 摘要。
- 脚本：要求确定性脚本测试提供显式的通过/失败证据，包括重复执行。生产证据将完整的脚本和安全检查集合绑定到已捕获的来源和 SHA-256 摘要。
- 安全：要求每个声明的权限边界用例都通过。平均值不能掩盖任何一次逃逸。
- 已安装树：在激活之前，根据记录的文件清单验证干净的已安装副本。要求 `manifestVersion: 1` 和 `algorithm: "sha256"`。将 `assets/manifest.json` 视为保留元数据，并将其排除在自身的 `files` 映射之外；通过受信任的外部发布或注册表通道对该清单进行认证。
- 可移植性：说明每个目标主机是原生的、需要适配器还是不受支持。列出缺失的能力。要求至少一个主机以及一个正向的原生主机阈值。本地完整性将捕获的需求和主机矩阵绑定到其探测来源和 SHA-256 摘要。

将路由评估与确定性测试框架激活保持分离。前者衡量可发现性；后者隔离工作流和产物行为。

随附的 JSON 值是用于学习该门控的确定性 fixture。它们可以设置 `fixturePassed`，但绝不能设置 `productionReady` 或 `passed`。对于真正的发布，需将 `evaluationMode` 设置为 `captured-observations`，将 `artifactMode` 设置为 `captured-artifacts`，将 `evidenceMode` 设置为 `captured-results`，将 `hostMode` 设置为 `captured-capabilities`；每次运行记录一个布尔预测，并将完整的观测集合绑定到其来源和 SHA-256 摘要；用从相同任务和环境中捕获的产物替换基线和带技能字符串；记录非空的捕获来源和匹配的 SHA-256 产物摘要；用捕获的测试结果替换每个证据裁定；将完整的证据集合绑定到其来源和 SHA-256 摘要；用捕获的主机探测结果替换模拟的能力矩阵并绑定到其来源和摘要；重建清单；并安装到干净的目标位置。

这些本地检查可以设置 `localEvidenceReady`。它们不能证明捕获已完成，因为产物包作者可以重新标记 fixture 并重新计算每个摘要。因此，评估者会对完整的五配置证据根进行哈希，并要求一个绑定它的外部 `attestationVersion: 1` JSON 对象。从产物包外部提供该证明，并通过 `--trusted-attestation-sha256` 提供其精确字节的 SHA-256，来源为带外受信任策略。只有六层门控加上本地完整性加上此信任锚点才能设置 `productionReady` 和 `passed`。
