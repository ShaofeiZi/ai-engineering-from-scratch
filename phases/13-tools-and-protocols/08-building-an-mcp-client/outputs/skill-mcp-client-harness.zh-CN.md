给定一组 MCP 服务器传输端点，构建一个优先使用 MCP `2026-07-28` 并隔离遗留兼容性的客户端框架。

需产出：

1. 对等端配置。将稳定的服务器名称映射到一个固定命令或端点、参数、环境变量白名单、授权上下文、传输类型，以及一个默认为 false 的显式 `allow_legacy` 标志。
2. 现代化请求构建器。在序列化之前，立即将协议版本、当前客户端能力以及推荐的客户端标识写入每个 `params._meta`。
3. stdio 版本纪元探测。首先发送 `server/discover`。接受有效的 DiscoverResult，在双方共同支持的现代化版本上重试 `-32022`，并将 `-32020` 与 `-32021` 视为可纠正的现代化错误。
4. 遗留兼容性探测。将无法识别的错误、超时、连接关闭或空响应对应为模糊状态。仅当该对等端确实设置了 `allow_legacy: true` 时，才发送一次带截止期限的 `initialize`。只有在收到相关联的 JSON-RPC 成功响应且其中包含已配置的遗留版本号、对象能力以及非空服务器标识后，才选择遗留模式。否则执行关闭式失败。
5. 工具缓存。遵循协商后授权上下文中的 `ttlMs` 与 `cacheScope`。将缺失的遗留 `resultType` 视为 `"complete"`。
6. 命名空间合并。对对等端和工具进行排序。对冲突的名称添加前缀或予以拒绝。禁止静默覆盖。
7. 路由器。将规范化工具名称映射到对等端及本地名称，创建新的请求 id，发送与版本纪元匹配的请求，并校验响应 id。
8. 恢复。在传输中断时，使进行中的任务失败，重启或重连，重复执行发现与列表操作，重新打开订阅，并仅重试安全策略所允许的操作。

严格拒绝：

- 在未包含当前 `_meta` 的情况下发送现代化请求。
- 在出现已识别的现代化错误后回退到初始化流程。
- 向未显式列入遗留兼容白名单的对等端发送 `initialize`。
- 将超时、连接关闭、空响应、无法识别的错误、格式错误的结果或不支持的版本号视为遗留行为的证据。
- 将进程、连接或 `Mcp-Session-Id` 视为现代化协议状态。
- 在不同授权上下文之间共享私有缓存列表。
- 静默覆盖重复的工具名称。
- 接受不包含 `resultType` 的现代化成功响应。

拒绝规则：

- 拒绝在固定白名单之外生成命令。
- 拒绝在归属不明确时路由工具。
- 拒绝在没有应用幂等键或用户决策的情况下自动重试非幂等调用。

输出一个完整的 Python 客户端框架、至少六个一致性测试，以及一份启动报告，列出对等端、所选版本纪元、所选版本号、缓存范围和规范化工具名称。
