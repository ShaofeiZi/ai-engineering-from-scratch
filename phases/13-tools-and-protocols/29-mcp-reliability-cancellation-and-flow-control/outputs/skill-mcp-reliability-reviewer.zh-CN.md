从请求开始到失败恢复，审查一个 MCP 操作的全过程。

如果缺少以下输入，请主动询问：

1. 传输方式：stdio 或 Streamable HTTP。
2. 操作语义与副作用。
3. 空闲超时与绝对最大超时。
4. 进度 token 行为与速率限制。
5. 重试策略与业务幂等性存储。
6. SSE 缓冲、代理、保活与重连设置。
7. Durable Task 行为（当操作使用 Tasks 扩展时）。

产出以下章节。

## 取消线路

- 对于 stdio，要求客户端发送引用了活跃请求 id 的 `notifications/cancelled` 通知。
- 对于 Streamable HTTP，要求关闭该请求的响应流。拒绝普通的取消 POST。
- 要求取消通知不产生 JSON-RPC 响应。
- 将服务端发送的 `notifications/cancelled` 仅保留用于 stdio `subscriptions/listen` 的拆除。
- 说明当取消未知、格式错误、延迟到达或无法执行时会发生什么。

## 竞态表

给出确定性结果：

| 事件顺序 | 服务端终态 | 最终响应 | 客户端行为 |
|------------|-----------------------|----------------|-----------------|
| 先取消后完成 | 已取消 | 抑制 | 继续恢复 |
| 先完成后取消 | 已完成 | 保留 | 忽略延迟取消 |
| 先超时后延迟响应 | 依赖传输的取消 | 按观测顺序忽略或抑制 | 在不安全重试前对账 |
| 进度期间断开 | 取消进行中的请求 | 无可恢复流 | 重连并重新获取 |

## 截止时间策略

要求同时具备空闲超时与绝对最大超时。仅当进度有效、单调且受速率限制时，才可重置空闲时间。保活注释不计为语义进度。最大超时永不重置。

## 重试分类

每个操作返回一个类别：

- `SAFE`：应用契约证明无副作用。
- `CONDITIONAL`：变更操作具有一个持久化幂等键，且以相同参数复用。
- `UNSAFE`：变更操作缺乏权威去重。

切勿将新的 JSON-RPC id、工具注解或传输重连视为业务幂等性。

对于条件重试，要求存储参数指纹与已提交结果。拒绝以同一键复用但参数已变更的情况。

要求为键声明、参数指纹、业务效果记录与已提交结果设定一个原子、持久化的账本边界。进程局部的字典或锁并非持久化，也无法协调副本。可接受共享数据库事务、事务性发件箱或强制使用同一键的上游提供者。说明实际处于该边界内的效果。

返回已提交结果的防御性副本。切勿暴露账本持有的可变对象。用同键并发夹具、重开夹具与变更别名夹具证明这两项属性。

## 流控

- 设置显式的每流或每客户端容量。
- 合并可替换的进度。
- 将被丢弃的进度标记为需要权威重新获取。
- 保留最终 JSON-RPC 响应。
- 为 SSE 设置 `Content-Type: text/event-stream`、`Cache-Control: no-cache` 和 `X-Accel-Buffering: no`。
- 将保活节奏与操作进度分开定义。
- 拒绝无界队列。

## 重连计划

- 以新 id 开启新请求。
- 恢复订阅过滤器。
- 对于 MCP 2026-07-28，不使用 `Last-Event-ID`。
- 重新获取受影响的资源、列表、提示词或 Tasks。
- 不自动重放不安全的变更操作。
- 使用带抖动的有上限指数退避。

## Durable Tasks

当存在 Task 时，保持 `tasks/cancel` 与请求取消分离。完成确认仅证明取消意图已被接受。轮询或监听直到持久化任务达到终态。

## 必备夹具

至少返回以下可执行场景：

1. stdio 在完成前取消；
2. stdio 在延迟取消前完成；
3. HTTP 流在完成前关闭；
4. 进度重置空闲超时而最大超时仍触发；
5. 两个 JSON-RPC id 且无幂等键的重复变更操作；
6. 同一键且参数相同的重复变更操作；
7. 同一键复用但参数已变更；
8. 慢消费者超出进度缓冲；
9. 流断开后新建订阅并权威重新获取；
10. `tasks/cancel` 确认后工作器延迟取消。
11. 两个独立的账本连接在同一键与相同参数上竞态；
12. 调用方变更返回结果后从持久化记录干净重放。

当重试策略仅描述为“超时即重试”、账本为进程局部、外部效果处于所声称的原子边界之外且无发件箱或上游键、返回记录别名指向可变存储、或队列容量未指定时，拒绝给出生产就绪结论。
