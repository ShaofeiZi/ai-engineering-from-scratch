# 投机解码选择器

帮助工程师在 vanilla 投机解码、Medusa、EAGLE 或 lookahead 解码之间做出选择，并为特定工作负载调优 `N`（草稿长度）。

## 需要收集的输入

1. **验证模型** — 哪个 LLM 产生最终输出。规模很关键（草稿成本必须 < 验证器成本才能带来加速）。
2. **工作负载类型** — 代码、对话、结构化输出、摘要。决定了接受率。
3. **采样策略** — 贪心、低温、高温、束搜索。高温采样会降低接受率。
4. **硬件目标** — 显存预算决定你是否能放下一个独立的草稿模型。
5. **工程预算** — Medusa 和 EAGLE 需要微调；vanilla 和 lookahead 不需要。
6. **延迟目标** — 交互式对话（TTFT <500ms，每 token <50ms）对比批处理（吞吐优先）。

## 决策规则

- **快速上手，无需训练**：使用同家族 1B–3B 模型作为 vanilla 草稿。典型加速 2×。
- **可以微调**：使用验证器隐状态训练 EAGLE-2 或 EAGLE-3。典型加速 3–4×。
- **可以微调但无法同时运行两个模型**：使用 Medusa（在验证器上加额外头）。加速 2–3×。
- **没有训练预算，也没有可用草稿模型**：使用 lookahead 解码。加速 1.3–1.6×。
- **以批处理为主的服务**：连续批处理更重要；随着 batch 增大，投机解码的收益会递减，因为验证器已经饱和。
- **高温或随机采样**：接受率急剧下降。考虑降低 N（2–3）或直接禁用。
- **结构化输出（JSON、代码）**：接受率高。可将 N 提到 7+ 以获得最大加速。

## 调优

- **N（草稿长度）**：从 5 开始。测量接受率。若 α > 0.9，提高到 7；若 α < 0.6，降到 3。
- **草稿温度**：与验证器的温度保持一致。草稿采样不匹配会损失 α。
- **树深度（EAGLE-2 / Medusa）**：3–5 个分支；更宽的树仅在 α > 0.8 时有帮助。
- **草稿模型规模**：选择能达到 α > 0.7 的最小模型。70B 验证器配 1B 草稿是典型配置；不要低于验证器分词器/嵌入的兼容性下限。

## 必须提示的事项

- 检查草稿模型与验证器是否共享分词器。BPE 切分不同会破坏投机解码的保证。
- 投机解码与 vLLM 的连续批处理存在交互：当 batch 已饱和时，单请求加速会下降。
- EAGLE 的隐状态输入需要访问验证器内部；并非总是通过 HF API 暴露。优先使用 vLLM 或 SGLang 运行时。
- Medusa 头需要在验证器自身输出上进行监督微调。数据收集步骤往往是主要成本。

## 输出格式

返回：

1. **推荐方案** — 一个策略名称及调优参数（例如 "EAGLE-2, N=5, tree_depth=4"）。
2. **预期加速** — 附带明确的 α 假设。
3. **兼容性检查** — 分词器匹配、运行时支持、KV cache 回滚支持。
4. **回退方案** — 如果主策略表现不佳，下一步尝试什么。
5. **测量计划** — 如何在代表性样本上验证接受率和加速。
