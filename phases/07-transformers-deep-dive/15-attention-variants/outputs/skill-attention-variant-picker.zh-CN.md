# 注意力变体选择器

帮助开发者为新 transformer 选择并论证一种注意力拓扑，或为已有模型在扩展到更长上下文时做同样的决策。

## 需收集的输入

1. **目标上下文长度**，包括训练时和推理时（二者往往不同——许多模型在 16K 长度下训练，推理时再扩展）。
2. **检索需求**，按 1–5 分衡量：1 = 纯对话，5 = 大海捞针 / RAG / 带长仓库上下文的代码。
3. **推理显存预算**，即每请求 KV 缓存的容忍度（正确的计量单位是每层每 token 字节数）。
4. **训练成本容忍度**——从零训练 SWA 成本低；把差分注意力改造进一个预训练模型则很昂贵。
5. **硬件目标**——Hopper 及以上有完整的 FlashAttention-3，Ada 有 FA2，更老的 GPU 受掩码限制。

## 决策规则

- **上下文 ≤ 16K 且检索 ≤ 3**：使用带 FlashAttention 的全注意力。不要过早优化。
- **上下文 16–128K 且检索 ≤ 3**：混合 SWA + 全局注意力，比例 5:1，窗口 1024（Gemma 3 形态）。在保持检索可用的同时压缩 KV。
- **上下文 > 128K**：使用全 SWA，每 4–6 层加一个全局层，再配合位置插值 / YaRN 缩放（第 04 课）。
- **检索 = 5 且训练预算允许**：考虑仅在最上面 4 层使用差分注意力（KV 翻倍成本减半，同时获得大部分消除 sink 的收益）。
- **你即将发布公开 API**：优先选择稳定方案（全注意力、SWA、Gemma-3 混合）。除非你有算子工程师，否则跳过 native-sparse / DIFF。
- **无法更改基座模型**：SWA 可在推理时通过掩码改造实现；差分注意力和稀疏注意力则不能。

## 始终需要提示

- 7B 以下的纯 SWA 模型在推理基准上常有可观测的下降。建议不要这样做。
- 窗口大小 < 512 几乎从不是正确选择。要么调大，要么改用其他拓扑。
- 差分注意力的论文报告基于小模型（3–7B）。截至 2026 年初，规模放大后的证据仍不充分。
- 每个变体都与 RoPE / YaRN 缩放（第 04 课）存在相互作用。需明确说明位置编码方案。

## 输出格式

返回：

1. **推荐方案**——单个命名的拓扑（例如 "Gemma-3 mix, W=1024, 5:1 SWA:global"）。
2. **论证依据**——将每个输入映射到上面的决策规则。
3. **KV 缓存估算**——在目标上下文下的每层每 token 字节数，以及 batch 1 时的 GB 数。
4. **迁移路径**——如果基座模型已训练完成，如何进行改造。
5. **已知风险**——哪些基准测试 / 工作负载可能出现回退。
