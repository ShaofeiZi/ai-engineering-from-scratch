# 对齐方法选择器

在为语言模型选择对齐方法时，使用该框架评估你的数据、算力和质量要求，然后选择最适合你约束条件的方法。

## 输入要求

提供以下信息：
- **基础模型**（例如 Llama 3 8B、Mistral 7B、Qwen 2.5 72B）
- **起点**（基础模型，还是已经经过 SFT？）
- **可用数据**（指令对、偏好对、非成对评分，或无）
- **算力预算**（GPU 小时数、GPU 数量）
- **质量目标**（足以用于原型、与开源竞争、达到业界最先进水平）
- **时间线**（天、周、月）

## 决策矩阵

### 快速选择

| 你的情况 | 推荐方法 | 原因 |
|---------------|-------------------|-----|
| 没有偏好数据，只有指令对 | 仅 SFT | 没有偏好信号就无法对齐 |
| < 5,000 偏好对，算力有限 | DPO | 流水线更简单，在少量数据上表现良好 |
| 非成对反馈（仅点赞/点踩） | KTO | 唯一不需要成对比较的方法 |
| 希望在一次训练运行中完成对齐 | ORPO | 合并 SFT + 对齐，无需参考模型 |
| 内存受限（无法容纳参考模型） | SimPO | 不需要参考模型 |
| 大规模、多目标对齐 | RLHF (PPO) | 独立的奖励模型可捕获复杂偏好 |
| 使用在线数据进行迭代对齐 | RLHF (PPO) | 可在循环中生成、评分并重新训练 |
| RLHF 之后的精修 | DPO | 在有针对性的偏好上微调 RLHF 模型 |

### 详细对比

| 方法 | 数据要求 | 内存中的模型 | 训练循环数 | 稳定性 | 最佳规模 |
|--------|-----------------|-----------------|----------------|-----------|------------|
| SFT | 指令对 (10K+) | 1 | 1 | 高 | 任意 |
| RLHF | 偏好对 (20K+) | 3-4 | 3 | 低 | 大规模 (70B+) |
| DPO | 偏好对 (5K+) | 2 | 2 (SFT + DPO) | 高 | 小到中 (7B-70B) |
| KTO | 非成对评分 (5K+) | 2 | 2 (SFT + KTO) | 高 | 任意 |
| ORPO | 偏好对 (10K+) | 1 | 1 | 高 | 小到中 |
| SimPO | 偏好对 (5K+) | 1 | 2 (SFT + SimPO) | 高 | 小到中 |

## 各方法专属配置

### SFT

- **何时停止**：在 1-3 轮之后，或当验证损失停止下降时
- **关键超参数**：学习率（1e-5 to 5e-5，模型越大值越低）
- **关键细节**：在损失中屏蔽指令 token
- **陷阱**：超过 3 轮会导致记忆化；混入 2-5% 的预训练数据

### RLHF (PPO)

- **何时使用**：你有 20K+ 比较对、需要多目标对齐，或希望进行迭代式在线学习
- **关键超参数**：KL 系数 (0.01-0.05)、PPO 裁剪比率 (0.1-0.3)、学习率 (5e-6 to 3e-5)
- **关键细节**：奖励模型应 >= 策略模型规模
- **陷阱**：PPO 不稳定；持续监控 KL 散度和奖励曲线

### DPO

- **何时使用**：你有偏好对，并希望使用比 RLHF 更简单的流水线
- **关键超参数**：Beta (0.1-0.5；值越低 = 允许偏离参考越多)
- **关键细节**：参考模型必须是 SFT 检查点的冻结副本
- **陷阱**：对 beta 非常敏感；在 [0.05, 0.1, 0.2, 0.5] 上做一次扫描

### KTO

- **何时使用**：你只有"好"或"坏"的标签，没有成对比较
- **关键超参数**：Beta（与 DPO 相同）、损失厌恶乘子（对坏响应为 1.5 倍）
- **关键细节**：需要大致平衡的好/坏样本（40-60% 划分）
- **陷阱**：没有成对，梯度信号较弱；可能需要比 DPO 更多的数据

### ORPO

- **何时使用**：你希望完全跳过 SFT，直接从基础模型到对齐
- **关键超参数**：Lambda（偏好项相对于 SFT 项的权重）
- **关键细节**：需要在同一数据集中同时有指令标签和偏好对
- **陷阱**：组合目标可能难以平衡；如果 SFT 损失占主导，对齐就会变弱

### SimPO

- **何时使用**：内存受限、无法容纳参考模型的场景
- **关键超参数**：Beta、gamma（长度归一化指数）
- **关键细节**：长度归一化可防止模型偏向短响应
- **陷阱**：没有参考模型锚定，模型可能漂移得更远；需仔细监控

## 流水线模板

### 模板 1：快速原型（1-2 天）

```
Base Model -> SFT (1 epoch, 10K examples) -> DPO (3 epochs, 5K pairs)
```

算力：在 A100 上对 7B 模型约 4 GPU 小时
质量：稳健的指令遵循，基本的偏好对齐

### 模板 2：生产质量（1-2 周）

```
Base Model -> SFT (2 epochs, 50K examples) -> DPO (5 epochs, 20K pairs) -> Eval -> Iterate
```

算力：7B 约 40 GPU 小时，70B 约 200 GPU 小时
质量：与开源 RLHF 模型具有竞争力

### 模板 3：业界最先进水平（1-3 个月）

```
Base Model -> SFT (2 epochs, 100K+ examples) -> RLHF (PPO, 50K+ pairs) -> DPO (targeted refinement) -> Eval -> Iterate
```

算力：70B 约 500+ GPU 小时
质量：接近前沿模型对齐水平

### 模板 4：最少数据（1-2 天）

```
Base Model -> SFT (1 epoch, 5K examples) -> KTO (unpaired thumbs up/down from users)
```

算力：7B 约 2 GPU 小时
质量：优于仅 SFT，数据采集开销最小

## 评估协议

对齐之后，在以下维度上进行评估：

1. **偏好胜率**：由人类评判在 200+ 测试提示上比较对齐模型与 SFT 模型。目标：> 60% 胜率。
2. **基准保持**：MMLU、HumanEval 或领域专属基准。相对于 SFT 基线下降不应超过 5%。
3. **MT-Bench 或 AlpacaEval**：标准对齐质量基准。与已发表的基线进行比较。
4. **安全评估**：针对对抗提示、越狱和有害请求类别进行测试。
5. **响应多样性**：在 100 个提示上测量响应的熵。熵低 = 模式崩溃。

## 常见失败模式

| 症状 | 原因 | 方法专属修复 |
|---------|-------|-------------------|
| 冗长、堆砌的响应 | 奖励模型 / 隐式奖励偏好长度 | DPO：提高 beta。RLHF：加长度惩罚。SimPO：调整 gamma。 |
| 模型对一切都附和 | 偏好数据偏置导致的谄媚 | 加入正确响应与用户意见相左的偏好对 |
| 拒绝良性请求 | 安全数据上过度对齐 | 降低安全样本比例，加入更多良性-拒绝配对 |
| 输出与 SFT 几乎相同 | beta 过高 (DPO/KTO) 或 KL 系数过高 (PPO) | 降低 beta / KL 系数；模型没有学到东西 |
| 训练损失震荡 | 学习率过高或数据不足 | 将 lr 降低 2-3 倍；增加偏好数据 |
