# 分词器的选择与实现

在启动一个 LLM 项目时,请应用以下决策框架来选择分词器。

## 各分词器的适用场景

**字节级 BPE (tiktoken):** 你要基于 GPT 系列模型构建或进行微调。你需要对任意输入字节序列都能可靠处理。你不希望出现未知 token。

**WordPiece (Hugging Face):** 你在使用 BERT 系列模型做分类、NER 或嵌入任务。你需要 "##" 续接前缀,因为下游任务依赖词边界信号。

**SentencePiece (BPE 或 Unigram):** 你在从零训练。你需要与语言无关的分词。你的数据包含 CJK 语言、泰语或其他没有空白词边界的文字。LLaMA、T5 以及大多数多语言模型使用这种方式。

## 词表大小指南

- 32K tokens:适合单语言模型的良好默认值,能保持嵌入层规模较小
- 50K-64K tokens:更适合多语言或代码密集型模型
- 100K+ tokens:仅当你拥有海量训练数据并希望序列更短时使用

更大的词表意味着更短的序列(推理更便宜),但嵌入矩阵中的参数更多。对于 100K 词表、4096 维嵌入的模型,仅嵌入层就有 400M 参数。

## 重要的预分词规则

1. 在 BPE 之前按空白切分,以防跨词合并
2. 若希望模型学会算术运算,则将数字逐位拆分
3. 分词前做 Unicode (NFC) 归一化,以获得一致行为
4. 为你的使用场景添加特殊 token:`<pad>`、`<eos>`、`<bos>`、`<unk>`,以及任何任务专用标记

## 分词器行为的危险信号

- 目标语言的繁殖率高于 2.0:模型在浪费上下文窗口
- 常见领域词被拆成 3 个及以上 token:应使用领域数据重新训练
- 数字分词不一致:检查数字拆分规则
- 词表很大但许多 token 只被使用一次:应缩小词表

## 构建自定义分词器 — 清单

1. 收集具有代表性的训练数据(目标领域至少 1GB 文本)
2. 选择算法:通用场景用 BPE,多语言用 Unigram
3. 按上述指南设定词表大小
4. 配置预分词:空白切分、数字处理、标点
5. 添加特殊 token
6. 使用 Hugging Face tokenizers 库训练(Rust 后端,速度快)
7. 验证:在所有目标语言的留出文本上检查繁殖率
8. 测试边界情况:空字符串、超长输入、二进制数据、emoji、RTL 文本
9. 保存分词器并与模型检查点一起做版本管理
