给定一个长上下文预训练运行规格（目标上下文、基础架构、可用训练 token、GPU 拓扑、部署目标），产出一份 NSA 集成计划。

产出：

1. 压缩块大小 `l`。选 32、64 或 128。依据目标上下文论证：16k-32k 用 `l = 32`，64k-128k 用 `l = 64`，256k 及以上用 `l = 128`。更大的 `l` 意味着更少的压缩键，但更粗的路由信号。
2. Top-k 选择数。在 8 到 32 之间选择。论文默认为 16。依据目标任务组合论证：推理重的任务（数学、代码）受益于更高的 `k`，因为选择精度更重要。检索重的任务可在更低 `k` 下工作。
3. 滑动窗口 `W`。选 256、512 或 1024。默认 512。对结构化程度高的内容（代码，局部上下文已足够）更短；对散文更长。
4. Gate MLP。指定宽度和初始化。默认：从 `hidden` 到 3 的线性层，带 `sigmoid` 或 `softplus` 激活。若 gate 权重崩塌到偏向某一分支，则发出警告——这表明 `l`、`k` 或 `W` 失调。
5. 内核选择。确认目标加速器上 Triton 或 CUDA 内核可用。拒绝在推理时回退到稠密注意力（NSA 的全部意义在于节省 decode 计算）。若只有前向内核而没有反向内核，则拒绝预训练并推荐在现有稠密检查点上继续训练。

硬拒绝：
- 在以稠密注意力预训练的模型上、未做继续预训练就加 NSA。无法在推理时硬加上去。
- 目标上下文低于 16k。三分支开销占主导。
- 在没有 NSA 内核支持的栈上做仅推理部署。推荐改为 MLA 或滑动窗口注意力。

拒绝规则：
- 若长上下文评估数据（RULER、LongBench、needle-in-haystack）不可用，则拒绝并先要求校准数据。
- 若训练数据上下文分布被短序列主导，则拒绝并推荐在集成 NSA 之前先做数据重加权。
- 若加速器早于 A100，则拒绝——NSA 的内核优势假设 H100/H200/MI300 的内存层次。

输出：一页集成计划，列出 `l`、`k`、`W`、gate 配置、内核路径，以及目标上下文下的期望计算节省。以一段"成功标准"收尾：会证明保留 NSA 合理的特定 RULER 或 LongBench 数值（相对匹配的稠密注意力基线的百分点）。包含一个回滚触发器——应将架构回退到 MLA 或稠密 GQA 的指标阈值。
