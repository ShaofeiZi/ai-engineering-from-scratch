# LLM 预训练数据质量检查器

在为 LLM 预训练构建或审计数据流水线时,使用此框架在问题到达模型之前发现它们。

## 流水线输出的危险信号

**去重移除的网页数据不到 20%。** Common Crawl 通常包含 30-40% 的重复内容。如果去重步骤移除量不到 20%,说明你的 MinHash 参数过于保守或阈值过高。检查:shingle 大小 k、哈希函数数量、LSH band 数量、Jaccard 阈值。

**压缩率低于 2.0 字符/token。** 这意味着你的分词器切分过于激进。要么用更多合并重新训练、增大词表,要么检查预分词是否在过度碎片化文本。

**压缩率高于 6.0 字符/token。** 你的分词器学到了非常领域专用的合并,可能无法泛化。对于领域专用模型没问题,但对通用模型而言是警示信号。

**序列利用率低于 90%。** padding 过多。要么你的文档过短(过滤它们或提高最小文档长度),要么序列打包效率低(从简单 padding 切换为多文档打包)。

**词表利用率低于 50%。** 超过一半的词表在该语料上未被使用。要么词表相对于你的领域过大,要么分词器是在差异很大的数据上训练的。

## 质量过滤器校准

在每个流水线阶段对 1,000 篇文档的随机样本运行以下检查:

1. **清洗后阅读 20 篇随机文档。** 它们是否残留 HTML、JavaScript、导航文本或样板内容?如果有,说明 HTML 剥离不彻底。

2. **阅读 20 篇通过质量过滤器的随机文档。** 是否有垃圾内容、关键词列表或机器生成内容?如果有,应收紧过滤阈值。

3. **阅读 20 篇未通过质量过滤器的随机文档。** 是否有真正优质的内容?如果有,说明过滤器过于激进。应放宽阈值或对特定模式添加例外。

4. **阅读 20 对来自去重的近似重复文档。** 它们是否确实相似?如果不相似,应降低 Jaccard 阈值或增加哈希函数数量。

## 数据混合比例

没有通用公式。以下面的基线为起点,并根据评估调整:

| 类别 | Llama 3 比例 | 起点 |
|----------|--------------|----------------|
| 网页文本 | 50% | 50% |
| 代码 | 25% | 15-25% |
| 书籍/学术 | 13% | 10-15% |
| 数学 | 8% | 5-10% |
| 多语言网页 | 4% | 5-10% |

如果模型需要在编程方面表现强,则提高代码比例。如果推理能力重要,则提高数学比例。如果需要更少噪声,则降低网页比例。更改比例后务必在基准测试上评估。

## 规模估算

对于给定的目标 token 数:

- 1T tokens 来自网页:预期约 3-5TB 原始文本,清洗去重后约 1.5-2TB
- 分词速度(Rust):每核约 100M tokens/秒
- 分词速度(Python):每核约 1-10M tokens/秒
- MinHash 去重(128 个哈希、16 个 band):每核约 10K 篇文档/秒
- 序列打包:I/O 受限,对 10GB 以上的语料使用内存映射文件

对于 15T tokens(Llama 3 规模),需规划约 30-50TB 原始输入数据,在 64 核机器上预处理 1-2 周,以及 100TB 以上的中间文件磁盘空间。

## 训练前清单

1. 总 token 数与你的算力预算匹配(以 Chinchilla 缩放定律或 Llama 3 过训练比例作为参考)
2. 去重移除了 30-40% 的网页数据
3. 质量过滤器移除了剩余数据的 10-20%
4. 英文压缩率为 3-5 字符/token
5. 序列利用率高于 95%
6. 在每个流水线阶段的随机抽检显示文本干净、连贯
7. 数据混合比例已在小规模训练运行中验证
8. PII 移除已在样本上验证
9. 所有二进制格式(打包序列、token ID 数组)通过往返编码/解码测试
10. 流水线可复现:固定随机种子下相同输入产生相同输出
