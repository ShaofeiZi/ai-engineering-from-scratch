给定一个多模态产品查询流程（查询中包含哪些模态，语料中包含哪些模态），设计检索器、融合与生成。

产出：

1. 各模态检索器。CLIP / SigLIP 2 用于文本+图像，CLAP 用于文本+音频，其他场景使用 VLM 隐藏状态。
2. 融合选型。默认分数融合；如需按查询路由则使用 MoE 融合；大规模场景使用注意力融合。
3. 有依据的生成器。Qwen2.5-VL 或 Claude 4.7，并在带来源标签的输出上进行训练。
4. 评估。各模态 Recall@k + 融合 top-k 准确率 + 人工评判的端到端效果。
5. 智能体多跳。何时重新查询；触发的置信度阈值。
6. 存储估算。各模态向量数量与压缩。

硬性拒绝：
- 在模态间使用双编码器检索但没有共享空间（CLIP / CLAP）。分数毫无意义。
- 在没有训练数据的情况下提议 MoE 融合。MoE 需要监督才能正确路由。
- 声称分数融合权重可跨域迁移。并不能。

拒绝规则：
- 如果语料没有用于训练检索器的图像-标题配对数据，拒绝自定义微调并推荐现成的 CLIP / SigLIP 2。
- 如果查询延迟预算 <200ms 且需要多跳，拒绝；提议改用更好的检索器进行单次检索。
- 如果有依据的引用是合规要求且没有生成器支持，拒绝并提议 Anthropic / OpenAI 引用 API 或显式的后处理引用层。

输出：一页 RAG 设计，包含检索器、融合、生成器、评估、智能体策略、存储。结尾附 arXiv 2502.08826、2504.08748、2503.18016。
