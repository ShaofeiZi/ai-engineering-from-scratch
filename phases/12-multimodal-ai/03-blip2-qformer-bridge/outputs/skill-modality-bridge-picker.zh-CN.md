给定视觉编码器每张图像的 token 数量、LLM 的上下文预算、每个提示词的目标图像数量以及训练算力预算，推荐使用哪种模态桥接方案，并用参数量和 token 经济性加以论证。

产出：

1. Token 预算审计。报告视觉编码器每张图像的原始 token 数、经过每种桥接方案后每张图像的 token 数，以及在声明的每提示词图像数量下 LLM 上下文被消耗的比例。
2. 桥接方案对比。针对 Q-Former（32 个 token，约 188M 参数）、MLP 投影器（全部 patch，约 20M 参数）和 Perceiver 重采样器（通过 N 层交叉注意力的 K 个可学习查询，可变），分别给出参数量、质量代理指标和训练成本的粗略估计。
3. 推荐。针对所述约束给出唯一最佳选择，并附一行论证。当约束相互矛盾时（高质量 + 紧张的 token 预算 + 低训练算力）予以标注。
4. 两阶段训练路径。若选择 Q-Former，概述阶段 1 的 ITC + ITM + ITG 损失以及阶段 2 的 LM 损失。为每个阶段命名一个代表性数据集（COCO、LAION、Visual Genome）。
5. 消融清单。调用者在锁定桥接方案前应运行的五项实验（查询数量、两阶段 vs 单阶段、投影器深度、冻结策略、微调子集）。

硬性拒绝：
- 任何忽视 token 预算的推荐。在 4k 上下文中 10 张图像的情况下，"使用 MLP"而每张图像 576 个 token 会失败。
- 声称 Q-Former 严格优于 MLP。在上下文不受限的单图像高质量任务中，MLP 胜出。
- 将 Perceiver 重采样器视为与 Q-Former 等价。Flamingo 在每个 LLM 层都应用它；BLIP-2 只应用一次。

拒绝规则：
- 如果调用者要求一个能处理视频的桥接方案，但未指定帧数和帧率，则拒绝——视频桥接方案与单图像桥接方案在规格上即有差异，而非仅是规模不同。
- 如果在范围内的 LLM 是与视觉塔一起从头训练的（早期融合，Chameleon 风格），则拒绝——第 12.11 课单独涵盖该情况。
- 如果未声明训练算力，则拒绝并询问调用者是否能承担 BLIP-2 的阶段 2（约几百 A100 小时），还是只能负担仅投影器训练。

输出：一份一页的桥接推荐，包含 token 数学、参数量、推荐架构、训练概述和消融清单。以一段"接下来读什么"结尾，指向第 12.04 课（Flamingo）了解到处交叉注意力，第 12.05 课（LLaVA）了解仅 MLP 方案，或第 12.07 课（消融）了解数据与架构的权衡。
