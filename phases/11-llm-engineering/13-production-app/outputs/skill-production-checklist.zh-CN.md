# 生产环境 LLM 清单

发布 LLM 应用时，请按顺序逐项核对本清单。每个小节都带有具体阈值的通过/失败标准。

## 1. 安全性（发布阻断项）

本节每一项都必须通过，才能进行任何部署。

| 检查项 | 通过标准 | 如何验证 |
|-------|--------------|---------------|
| API 密钥存放于环境变量 | 代码库中无任何硬编码密钥 | `grep -r "sk-" --include="*.py"` 无任何返回 |
| 输入护栏已启用 | 提示词注入模式被拦截 | 发送 "Ignore all previous instructions"——返回被拦截的响应 |
| PII 脱敏 | SSN、信用卡、邮箱模式被捕获 | 发送 "My SSN is 123-45-6789"——在调用 LLM 前 PII 已被脱敏 |
| 输出过滤 | 危险内容被拦截 | 模型无法返回 `DROP TABLE`、`rm -rf`、`exec()` 等模式 |
| 速率限制 | 每用户请求上限被强制执行 | 同一用户在 10 秒内发起 100 次请求——后 50+ 次被拒绝 |
| 所有端点已鉴权 | 不存在未鉴权的 LLM 访问 | 不带 token 调用 `curl /v1/chat` 返回 401 |
| CORS 已受限 | 仅允许生产域名 | `Origin: evil.com` 请求被拒绝 |
| 输入 token 上限 | 超限请求被拒绝 | 发送 50K token 的输入——返回 413 或被截断 |

## 2. 可靠性（首周生存项）

这些项能防止你的第一次值班事故。

| 检查项 | 通过标准 | 如何验证 |
|-------|--------------|---------------|
| 带退避的重试 | 5xx 错误重试 3 次，指数退避延迟 | 在请求中途杀掉 LLM mock——日志中可见重试 |
| 降级模型链 | 链中含 2 个以上模型 | 主模型不可用——响应仍从降级模型返回 |
| 请求超时 | 所有外部调用上限 30 秒 | 慢速 LLM mock（60s）——请求在 30s 超时 |
| 优雅降级 | 缓存/RAG 失效不会导致服务崩溃 | 停用缓存——请求仍成功（更慢、更贵） |
| 健康检查端点 | 返回依赖项状态 | `GET /health` 返回 `{"status": "healthy", "cache": ..., "llm": ...}` |
| 流式可用 | 首 token 在 500ms 以内 | 测量首 token 时间，稳定 < 500ms |
| 错误信息安全 | 内部错误不外泄给用户 | 强制 500 错误——用户看到通用错误，而非堆栈跟踪 |

## 3. 成本控制（首月经济项）

这些项能防止你收到 $50K 的意外账单。

| 检查项 | 通过标准 | 如何验证 |
|-------|--------------|---------------|
| 单请求成本可追踪 | 每个请求记录 token 数 + 美元成本 | 请求日志含 `input_tokens`、`output_tokens`、`cost_usd` 字段 |
| 语义缓存已启用 | 重复模式的命中率 > 20% | 1000 次测试请求后缓存统计显示命中率 |
| 缓存 TTL 已配置 | 条目过期（默认：1 小时） | 插入条目——TTL 后不再返回 |
| 每用户成本追踪 | 成本按 user_id 聚合 | 仪表盘/API 展示按成本排名的前 10 用户 |
| 成本告警 | 达到日预算 80% 时告警 | 设 $10 日预算，发送 $8.50 的请求——告警触发 |
| 按成本路由模型 | 低复杂度查询使用更便宜的模型 | 简单问题路由到 gpt-4o-mini，复杂问题路由到 gpt-4o |
| 输出 token 上限已设置 | 每个模板的响应有上限 | max_output_tokens=512 的模板——响应绝不超过该值 |

**成本估算公式：**
```
Monthly LLM cost = DAU x queries_per_user x 30 x (1 - cache_hit_rate) x (avg_input_tokens x input_price + avg_output_tokens x output_price) / 1,000,000
```

**按规模的基准阈值：**

| DAU | 目标成本/请求 | 月度预算 |
|-----|-------------------|----------------|
| 1K | < $0.005 | < $750 |
| 10K | < $0.003 | < $4,500 |
| 100K | < $0.001 | < $15,000 |

## 4. 可观测性（生产环境调试）

你看不到的东西就修不了。

| 检查项 | 通过标准 | 如何验证 |
|-------|--------------|---------------|
| 结构化 JSON 日志 | 每个请求产生一行 JSON 日志 | 日志含：request_id、user_id、model、tokens、latency_ms、cost |
| 请求追踪 | 带组件耗时的端到端追踪 | 单个请求展示：guardrail（5ms）+ cache（2ms）+ llm（3200ms）+ eval（1ms） |
| 延迟追踪 | P50、P95、P99 已测量 | 1000 次请求后：P50 < 2s，P99 < 10s |
| 错误率监控 | 错误被计数并分类 | 仪表盘展示：0.5% API 错误，0.1% 护栏拦截，0.01% 超时 |
| 缓存指标 | 命中率、未命中率、条目数可见 | `GET /v1/cache/stats` 返回当前数值 |
| A/B 测试指标 | 每变体的质量指标已记录 | 每个请求记录 prompt_template + 版本以便对比 |
| 评估日志 | 每个请求记录质量信号 | 响应长度、延迟、模型、模板版本被存储以供离线分析 |

## 5. 提示词管理

提示词即代码。请像对待代码一样对待它们。

| 检查项 | 通过标准 | 如何验证 |
|-------|--------------|---------------|
| 版本化模板 | 每个模板含名称 + 版本字符串 | 模板变更创建新版本，旧版本保留 |
| A/B 测试支持 | 按确定性用户哈希分流 | 同一用户在同一实验内始终看到同一变体 |
| 回滚能力 | 1 分钟内回退到上一版本 | 修改实验配置——流量立即切换 |
| 模板校验 | 渲染前校验变量 | 模板中缺失变量抛出明确错误，而非 KeyError |
| 系统提示词分离 | system 与 user 消息在不同字段 | 系统提示词不拼接到用户消息中 |

## 6. 扩展准备

上线时不需要，达到 10 倍负载时需要。

| 检查项 | 通过标准 | 如何验证 |
|-------|--------------|---------------|
| 异步 LLM 调用 | API 调用不阻塞线程 | 50 个并发请求——服务器 CPU 保持 < 30% |
| 连接池化 | HTTP 连接复用 | 网络追踪显示到 LLM 提供方的持久连接 |
| 水平扩展 | 无状态服务器设计 | 负载均衡器后 2 个实例——所有请求成功 |
| 队列支持 | 非实时任务进入队列 | 摘要请求返回 job_id，结果可通过轮询获取 |
| 已进行负载测试 | 100 并发用户，错误率 < 5% | `wrk` 或 `locust` 在目标并发下通过 |

## 新项目的实施顺序

1. **第 1 天：** API 服务器 + 提示词模板 + 带重试的单次 LLM 调用
2. **第 2 天：** 输入护栏 + 输出护栏 + 错误处理
3. **第 3 天：** 语义缓存 + 每请求成本追踪
4. **第 4 天：** 流式传输（SSE）+ 健康检查端点
5. **第 5 天：** 结构化日志 + 请求追踪 + 评估日志
6. **第 2 周：** A/B 测试 + 提示词版本管理 + 回滚
7. **第 3 周：** 降级模型链 + 优雅降级
8. **第 4 周：** 负载测试 + 异步优化 + 水平扩展

## 快速诊断

生产环境出问题时，按以下顺序排查：

1. **用户抱怨报错？** 检查健康端点，然后查看日志中的错误率，再查看 LLM 提供方状态页
2. **响应慢？** 检查 P99 延迟，然后查看缓存命中率，再查看追踪中的 LLM 响应时间
3. **成本飙升？** 检查每请求成本趋势，然后查看缓存命中率，再查看按成本排名的前列用户，最后排查导致 token 数增加的提示词模板变更
4. **质量下降？** 检查是否部署了新提示词版本，检查 RAG 检索准确率是否变化，检查模型提供方是否更改了默认模型版本
5. **安全事件？** 检查护栏拦截率（骤降 = 护栏被禁用），检查请求日志中的异常模式，立即轮换 API 密钥
