# 推理技术选择指南

当你需要 LLM 推理解答一道题时，先选择技术，再编写提示词。技术决定推理架构，提示词填充其中。

## 快速决策树

1. 该任务是简单的事实查询或单步分类吗？
   - 是：使用 **zero-shot**。CoT 只增加成本，不提升准确率。
   - 否：继续。

2. 该任务需要多步推理（数学、逻辑、规划）吗？
   - 是：使用 **Chain-of-Thought**。继续到第 3 步。
   - 否：如果格式重要则使用 **few-shot**，否则使用 zero-shot。

3. 单个推理错误可以接受吗？
   - 是：使用 **few-shot CoT**（单次采样，temperature 0.0）。
   - 否：在留出集上评估 **self-consistency**。将 N=5 与 temperature 0.7 仅作为实验起点，然后分别调参，仅当其质量增益能证明所测得的推理成本合理时才保留该技术。继续到第 4 步。

4. 该问题是一个存在多条可能路径的搜索/规划问题吗？
   - 是：使用 **Tree-of-Thought**。
   - 否：self-consistency 足矣。

5. 该任务需要外部信息或计算吗？
   - 是：使用 **ReAct**（推理 + 工具调用）。
   - 否：纯推理技术足矣。

## 技术矩阵

| 技术 | 需收集的质量证据 | 相对推理工作量 | 最适用于 |
|-----------|-----------------------------|-------------------------|----------|
| Zero-shot | 留出集基线 | 一次生成 | 简单任务、事实问答 |
| Few-shot | 比较示例集及其顺序 | 一次更长的生成 | 格式匹配、分类 |
| Zero-shot CoT | 与直接答案对比 | 一次更长的生成 | 快速推理实验 |
| Few-shot CoT | 测试超越示范样本的迁移 | 一次更长的生成 | 数学、逻辑、多步 |
| Self-Consistency | 绘制质量随采样数变化的曲线 | N 次独立生成 | 高风险推理 |
| Tree-of-Thought | 跟踪节点数、求解率与剪枝错误 | 每个探索节点一次生成 | 搜索、规划、谜题 |
| ReAct | 跟踪工具准确率和任务成功率 | 多轮模型/工具交互 | 知识接地任务 |
| Prompt Chaining | 校验每个中间契约 | 每个链步骤一次生成 | 复杂多部分任务 |

## 针对模型的指引

### GPT-4o / GPT-4.1
- 基线推理能力强。Zero-shot CoT 通常足够。
- 在目标工作负载上对直接答案、显式推理和 few-shot CoT 进行基准测试；不要从不同的模型快照或提示词迁移准确率数字。
- 仅当独立采样的路径能将留出集质量提升到足以证明额外推理成本合理时，才添加 self-consistency。
- 原生支持结构化输出，便于答案抽取。

### Claude 3.5 Sonnet / Claude 3.7 Sonnet
- 极擅长遵循结构化的提示词格式（XML 标签）。
- 带有 XML 分隔示例的 few-shot CoT 效果最佳。
- 扩展思考（Claude 3.7）是原生 CoT——无需再提示。
- 对于 self-consistency 实验，temperature 0.7 是起点而非默认值；调参以获得有用的路径多样性，并在留出任务上验证质量增益和推理成本。

### Llama 3.1/3.3 70B
- 从 few-shot CoT 获益最大（相对 zero-shot 的准确率差距更大）。
- 对于推理任务，将 N=5 的 self-consistency 视作实验起点；根据留出集质量和实测推理成本确定最终采样数。
- 比商用模型需要更显式的格式指令。
- ToT 在本地推理上代价高昂——仅考虑用于批处理。

### Gemini 2.5 Pro
- 开箱即用的多步推理能力强。
- Thinking 模式提供内置 CoT，无需提示词工程。
- Few-shot 示例对格式一致性的帮助大于对准确率的帮助。
- 大上下文窗口（1M）使示例密集的 few-shot 切实可行。

## 反模式

**对简单任务使用 CoT**：问 "What is 2+2? Let's think step by step" 浪费 token。模型无需推理痕迹即可做对简单算术。CoT 在有 3 步以上时才有帮助。

**在 temperature 0.0 下使用 self-consistency**：确定性解码不会有意创造多样的推理路径。用非零温度（0.5-0.8 是有用的搜索范围）启动实验，然后对照留出集质量、一致性率和推理成本调参，而非把该范围当作通用推荐。

**处处使用 ToT**：ToT 需要 O(b^d) 次 LLM 调用，其中 b=分支因子、d=深度。一棵 b=3、d=3 的树最多需要 39 次调用。留给更廉价技术失效的问题。

**使用糟糕示例的 few-shot**：含推理错误的示例会教模型犯同样的错误。每个示例都必须经过校验。一个错误示例对准确率的损害可能超过没有示例。

**没有一致格式地抽取答案**：self-consistency 需要跨样本比较答案。如果答案格式各异（"$18"、"18 dollars"、"eighteen"），投票会失败。始终强制："The answer is [number]."

## 成本优化

用提供商当前的价格与应用实测的输入、输出和推理 token 数来衡量成本。不要把通用准确率断言与厂商价格配对：两者都随模型快照、工作负载、提示词和日期而变。

| 技术 | 需记录的成本输入 | 需记录的质量输入 |
|-----------|-----------------------|-------------------------|
| Zero-shot | 一次生成的输入和输出 token | 留出集基线 |
| Few-shot CoT | 示范 token 加上生成的推理 | 确切示例集对应的留出集结果 |
| Self-Consistency | 每样本 token 乘以采样数 | 多数投票结果和一致率 |
| Tree-of-Thought | 跨每个生成和评估节点的 token | 求解率与探索的节点数 |

从最廉价的实测基线开始。仅当观测到的质量增益能证明额外推理工作量合理时，才添加示例或 self-consistency。

## 与 Prompt Chaining 的集成

推理技术与 prompt chaining 组合使用：

**链步骤 1**（抽取）：zero-shot，temperature 0.0
**链步骤 2**（推理）：few-shot CoT，temperature 0.0
**链步骤 3**（验证）：self-consistency；N=3 与 temperature 0.7 是在留出任务上调参的实验起点

该链能捕获抽取与推理错误，并暴露验证投票的一致率。其成本取决于调定的采样数和观测到的 token 用量，因此仅当留出集质量增益能证明该实测成本合理时才保留。

## 何时超越提示词

如果你花在工程化提示词上的时间超过编写应用代码的时间，考虑：

1. **微调**：如果你有 500+ 标注示例且任务范围狭窄
2. **DSPy 编译**：如果你想要自动化提示词优化
3. **Agent 框架**：如果任务需要多轮工具使用（Phase 14）
4. **RAG**：如果模型需要访问私有/最新知识（Lessons 06-07）

提示词技术是基础。它们适用于任何模型、任何提供商，且无需训练数据。但它们有极限。知道何时进阶到下一层级，与掌握技术本身同样重要。
