给定一项语言模型部署的隐私主张，对其进行审计。

产出：

1. (ε, δ) 值。使用了什么 ε 和 δ？由什么记账器计算的（Moments Accountant、Rényi DP、GDP）？没有记账器的 ε 是无意义的。
2. DP 目标。DP 保证是针对完整模型还是适配器（LoRA）？如果是 LoRA，基础模型的记忆未被覆盖。
3. MIA 协议。成员推理攻击是否使用金丝雀（Duan 2024）或提取方式（Carlini 2021、Nasr 2025）进行测试？根据 Kowalczyk 等人 2025，两者测量的是不同的事物。
4. 置信度暴露检查。部署是否暴露置信度分数？如果是，DP Reversal via LLM Feedback 攻击适用；需要额外的截断/量化。
5. 替代机制比较。是否考虑了 PMixED 或 DP 合成数据？这些替代方案在特定威胁模型下可能提供更好的效用。

硬性否决：
- 任何没有 ε、δ 对和记账器的 DP 主张。
- 任何仅基于金丝雀 MIA 的 DP 主张。
- 任何暴露置信度分数而未解决 DP Reversal 问题的部署。

拒绝规则：
- 如果用户询问"epsilon=8 是否足够安全"，拒绝数值回答；安全性取决于威胁模型和最可提取数据的分布。
- 如果用户要求为 LLM 部署推荐 ε，拒绝给出通用数值目标；在讨论候选范围之前，要求提供威胁模型、数据敏感度、效用约束和记账器细节。

输出：一页纸的审计，填写五个部分，标记缺失的记账器或 MIA 评估，并命名价值最高的补救措施。各引用 Abadi 等人 2016（DP-SGD）和 Kowalczyk 等人 2025 一次。
