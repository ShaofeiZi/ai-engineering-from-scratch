# 物理合理性检查

生成视频的生产部署需要自动化的护栏机制。人工审查无法扩展;物理检查能够捕获经典的失败模式。

## 何时使用

- 任何从文本或图像提示生成视频的产品。
- 对视频生成 API 端点进行自动化 QA。
- 在微调或基础模型更新后,监控视频模型的质量漂移。

## 输入

- `video`:一个形状为 `(T, H, W, 3)` 的张量,或一个 mp4 路径。
- 可选的参考信息:预期物体数量、初始场景描述。

## 检查项

### 1. 物体持久性
使用 SAM 3.1 Object Multiplex 在各帧间跟踪每个检测结果。当稳定的跟踪轨迹消失 ≤3 帧后再次出现时进行标记——这意味着模型暂时丢失了该物体。当物体在帧中心附近(而非边缘)消失时,判定为硬失败;在边缘消失则为软失败。

### 2. 运动平滑性
连续帧之间的光流应基本连续。每像素光流的突然尖峰表明出现了"瞬移"现象。使用 RAFT 计算光流;当某帧的第 99 百分位光流幅值超过中位数的 10 倍以上时,标记该帧。

### 3. 重力/支撑
对于被检测为固体(食物、球、工具)的物体,在没有抬升动作的情况下,检查其垂直位置是否不上升。除非在物体附近检测到"抓取的手",否则标记向上漂移的情况。

### 4. 身份一致性
对于人物或角色,在各帧间使用人脸识别嵌入向量。对于持续的身份,余弦相似度在 5 帧窗口内应保持在 > 0.8。低于阈值意味着角色发生了形变。

### 5. 手和四肢
运行姿态估计器(第 21 课)。在以下情况下标记帧:一只手有 > 5 或 < 4 根可见手指;两帧之间手臂长度翻倍;肢体穿过某个表面与身体相交。

### 6. 文本渲染(如果提示要求渲染文本)
如果用户提示中包含带引号的字符串,对生成的帧进行 OCR,并根据所请求的字符串计算 CER。当 CER > 20% 时进行标记。

## 报告

```
[plausibility]
  video frames:           <T>
  permanence violations:  <N>
  smoothness violations:  <N>
  gravity violations:     <N>
  identity drift:         <N of 5-frame windows>
  limb anomalies:         <N>
  OCR CER vs requested:   <float>

[verdict]
  ship | hold | reject

[samples for review]
  frame ranges where each failure occurred
```

## 规则

- 不要因任何单一检查而硬性拦截;应汇总各项分数,当总异常数超过阈值时,将视频保留以供审查。
- 对身份漂移和物体持久性违规赋予最高权重——用户会最先注意到这些问题。
- 随时间记录每项检查的失败率;上升趋势通常意味着基础模型已更新或提示分布发生了偏移。
- 绝不删除被标记的视频;保留它用于模型调试和事后分析。
- 对于敏感内容(人物、儿童、公众人物),无论评分如何,都要求对每个视频进行人工审查。
