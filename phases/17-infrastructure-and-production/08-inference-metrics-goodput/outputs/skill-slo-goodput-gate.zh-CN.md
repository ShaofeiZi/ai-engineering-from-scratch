给定工作负载（模型、硬件、目标并发数、面向用户的交互类型——流式对话 / 单次请求 / 语音 / 智能体），产出一份基于 goodput 的 SLO 闸门方案用于 CI/CD。

产出内容：

1. SLO 规范。三个阈值：TTFT P99 上界、TPOT P99 上界、E2E P99 上界。根据交互类型选择可辩护的值（流式对话：TTFT 500 ms、TPOT 25 ms、E2E 3 s；语音：TTFT 300 ms 更严格；智能体：E2E 5 s 更宽松）。
2. 基准测试方案。工具选择（LLMPerf 或 GenAI-Perf——指明你选哪个及原因）。Prompt 分布（输入和输出 token 的均值 + 标准差）。并发扫描（目标值的 25%、50%、100%、150%）。
3. Goodput 计算。公式：同时满足全部三个约束的请求占比。目标 >= 99%（生产），>= 95%（灰度）。
4. 百分位报告。对每个指标报告 P50、P90、P99（绝不仅报告均值）。仅在合理性检查时标注均值。
5. 工具陷阱说明。声明该工具是否将 TTFT 计入 ITL。在跨团队比较前先统一定义。
6. 闸门逻辑。CI 通过条件为在目标并发下 goodput >= 目标值。如果 100% 到 150% 并发之间 goodput 下降超过 5 个百分点则标记——说明负载测试余量不足。

硬性拒绝条件：
- 仅以吞吐量作为闸门。拒绝并要求使用 goodput。
- 报告均值而未报告 P99。拒绝。
- 未注明工具名称和工具版本。拒绝。
- 仅在目标并发下做基准测试；必须进行扫描。

拒绝规则：
- 如果用户没有书面 SLO，拒绝并首先根据交互类型制定一个 SLO。
- 如果 prompt 分布为"循环使用相同 prompt"，拒绝——这是 prompt 均匀化陷阱。要求使用真实合成数据。
- 如果基准测试运行次数 < 30 或每次运行请求数 < 100，拒绝，因样本量在统计上不足。

输出：一份单页 SLO 闸门规范，列出阈值、基准测试方案、工具选择、百分位报告模板和 CI 通过/失败规则。以一段"下一步测量什么"收尾，根据已知薄弱环节指出 goodput vs 并发曲线、prompt 分布敏感性或 chunked-prefill 开关尾部比较中的某一项。
