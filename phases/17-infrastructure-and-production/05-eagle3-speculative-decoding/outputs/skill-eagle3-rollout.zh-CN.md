给定目标模型、硬件（GPU 型号与数量）、流量描述（通用对话 / 代码 / 专用领域）、并发目标以及当前基线指标（TTFT、ITL、吞吐量），制定一份分阶段 EAGLE-3 上线计划。

产出内容：

1. 基线测量计划。选择哪种基准测试（LLMPerf、GenAI-Perf 或生产影子流量），使用哪种 prompt 分布，在哪个并发点上测量，记录哪些指标（TTFT 均值/P99、ITL 均值/P99、吞吐量、并发数）。
2. 草稿头选择。通用对话场景使用基于 ShareGPT 训练的 EAGLE-3。专用流量（代码、医疗、法律）使用领域定制的 EAGLE-3，或在上线前决定训练一个。
3. 配置。给出 vLLM `speculative_config` 的确切字段（method、model、num_speculative_tokens）。注意 v0.18.0 的兼容性：草稿模型投机解码不能与 `--enable-chunked-prefill` 同时使用；V1 中的 N-gram GPU 投机解码是例外。
4. Alpha 闸门。目标 alpha >= 0.55（生产并发下）。测量流程：影子流量运行 24 小时，记录 vLLM `spec_decode_metrics`，用接受的 token 数除以请求的草稿长度。如果任意 1 小时窗口内 alpha 低于 0.45，触发熔断开关。
5. 尾部监控。绘制 P99 ITL 变化量（开启投机 - 关闭投机）。如果变化量为正，说明被拒绝草稿的二次验证模式正在拖累延迟。此时应降低 K 或在该工作负载上禁用投机解码。
6. 盈亏平衡检查。在报告的并发量下，根据当前验证开销计算盈亏平衡 alpha。仅当实测 alpha 高于盈亏平衡点至少 0.1 时才上线。

硬性拒绝条件：
- 未在生产流量上测量 alpha 即上线。拒绝并要求 24 小时影子测量。
- 在不命名实测 alpha 的情况下声称 2-3 倍加速。
- 对延迟非瓶颈的离线批量任务启用投机解码。
- 在 vLLM v0.18.0 上将草稿模型投机解码与 chunked prefill 同时启用。属于硬性不兼容。

拒绝规则：
- 如果流量以极短输出（均值低于 50 token）为主，拒绝。草稿开销占主导；应直接使用普通目标模型。
- 如果硬件为消费级（RTX 4090 / 5090）且 batch size 低于 8，建议使用普通目标模型——验证开销的 batch 摊销需要该硬件无法提供的并发能力。
- 如果用户在没有测量闭环的情况下要求自动调优 K，拒绝。K 基于实测 alpha 加验证开销来选择；没有自动调优能替代测量。

输出：一份单页分阶段上线计划，按基线 → 配置 → alpha 闸门 → 尾部监控 → 盈亏平衡确认的顺序列出。以一段"下一步测量什么"收尾，根据诊断结果指出领域定制 EAGLE-3 训练、降低 K、或回退为普通目标模型。
