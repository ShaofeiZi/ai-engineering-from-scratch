# 国际化 (i18n)

英文课程是权威版本。翻译后的**课程** Markdown **从不提交到 `main` 分支** —— 它存放于单独的配置分支(默认为 `translations`),站点在运行时以与获取英文相同的方式免费(`raw.githubusercontent.com`)拉取它。大多数已启用的语言是由机器生成的;简体中文(`zh`)由人工维护,且工作流拒绝覆盖它。不使用 Vercel 函数,不使用 KV,也没有按访问次数计费的成本。各语言的 **README** 文件同样为质量而手工撰写,并提交到 `main` 分支(见下文)。

此流水线仅覆盖 `phases/` 下的课程。认证课程仍仅提供英文,故意在机器翻译和书籍生成中被排除在外。

机器管理语言的默认引擎是 **NLLB-200**([No Language Left Behind,Meta AI,2022](https://arxiv.org/abs/2207.04672)),这是一个覆盖 200 种语言的开源翻译模型,它**在 GitHub Actions runner 内运行,无需 API key,无需付费**。计算资源是免费的 CI runner;完全没有翻译 API 的成本。付费 LLM 提供商(Anthropic/OpenAI)和 DeepL 仍可通过 `--provider` 作为可选的更高质量升级路径。人工维护的语言不能传递给翻译脚本。

## 组成部分

`languages.json` 注册表驱动课程翻译和站点切换器。各语言的 **README 是独立的**:其语言集合和翻译块位于 `scripts/readme_translations.py`,为质量而手工撰写,独立于注册表。

| 组成部分 | 位置 | 提交到 main? |
|-------|-------|--------------------|
| 语言注册表 | `languages.json` | 是(一个小文件) |
| 课程翻译脚本 | `scripts/translate_lessons.py`(仅遍历散文;拒绝 `manual` 语言) | 是 |
| README 生成器 + 翻译 | `scripts/build_readme_i18n.py` + `scripts/readme_translations.py`(手工撰写) | 是 |
| CI 工作流 | `.github/workflows/translate.yml`(按语言 × 阶段分片) | 是 |
| 已翻译的课程 Markdown | 配置的翻译引用(默认 `translations`),`i18n/<lang>/…/<lang>.md` | 否(独立分支) |
| 已翻译的 README | `i18n/<lang>/README.md`,从 `README.md` 的头部链接 | **是** |
| 已翻译的书籍 | `scripts/build_book.py --lang <code>` 从本地恢复的完整 `i18n/<lang>/` 树构建,若缺少任何课程、已过时、结构无效或会回退到英文则失败关闭;发布工作流目前仅发布英文 | 否 |
| 切换器选项 | `site/langs.js`(由 `build.js` 从已发布的 `source`/`ci`/`manual` 条目生成) | 否(被 gitignore,如同 `data.js`) |
| 站点切换器 | `site/lesson.html` | 是(UI + 获取逻辑) |

## 添加一种语言

向 `languages.json` 添加一个条目,这是唯一的真实来源。字段:

- `code` —— 用于文件名、URL 和切换器值的标签。
- `name` —— 英文名称,用于 LLM 提供商的提示。
- `native` —— 在切换器中显示的标签。
- `nllb` —— FLORES-200 代码(例如 `zho_Hans`、`tur_Latn`);默认 NLLB 提供商**必需** —— 如果请求的语言没有该字段,`translate_lessons.py` 将退出。
- `ci` —— `true` 将一个非源、非人工维护的语言加入自动推送触发的构建矩阵。`workflow_dispatch` 可请求任何已注册的机器管理语言。
- `manual` —— `true` 表示课程翻译由人工维护。该语言会出现在站点切换器中,但自动和手动派发的机器翻译任务都会拒绝它。

翻译矩阵选择 `ci: true` 且非 `manual` 的条目。站点切换器发出 `source`、`ci` 和 `manual` 条目,因此已发布的人工维护语言仍可被选择,而不会进入机器翻译队列。README 栏是独立的:它可以列出 `readme_translations.py` 覆盖的任何语言。

## 运行方式

1. 推送到 `main` 且更改了 `phases/**/docs/en.md`、`languages.json` 或翻译工作流本身时,会触发 `.github/workflows/translate.yml`。认证课程的更改不会触发它。即使是 `workflow_dispatch` 请求时,人工维护的语言也会被排除。准备任务会校验 `AIFS_TRANSLATION_REF`;仅当 `AIFS_TRANSLATION_REPOSITORY` 是当前仓库时才启用发布,否则记录所配置的外部源为只读并跳过翻译矩阵。
2. 对于启用了发布的机器管理语言,矩阵是**每(语言, 阶段)一个任务**。一次完整的 523 课语言运行在 CPU runner 上约需 27 小时,远超 6 小时的任务时限,因此按语言的整任务在发布前总会超时。按阶段拆分使最大任务(阶段 19,85 课)保持在约 4.5 小时,远低于时限。每个任务从配置的仓库/引用恢复其语言先前的输出,运行 `translate_lessons.py --phase <phase>`,审计已完成的阶段,并通过一个获取-重试循环仅将其自己的 `i18n/<lang>/phases/<phase>/` 分片推送回同一引用,因此不相交的分片可无冲突地合并。
3. 站点的语言切换器设置 `?lang=<code>`;`fetchLesson` 从配置的翻译仓库和引用拉取 `i18n/<lang>/…/<lang>.md`,如果该翻译尚未发布,则**回退到权威英文**。英文(`lang=en`)仍绑定到活动的部署仓库和引用,因此 fork 预览会渲染其自身的英文编辑。

## 已发布的翻译源

站点构建、课程审计和翻译发布器共享两个配置名:`AIFS_TRANSLATION_REPOSITORY`(`owner/repository`)和 `AIFS_TRANSLATION_REF`(分支名)。它们的默认值分别是正在构建或检查的仓库和 `translations`。将这两个名称作为 GitHub Actions 仓库变量和部署环境变量(例如在 Vercel 中)设置为相同的值。发布器通过该精确引用的一个专用 remote 进行恢复、变基和推送;生成的站点元数据将此翻译源与 `ACTIVE_REPOSITORY` 以及用于英文的活动预览引用保持分离。

内置发布器刻意使用 `github.token`,其写入权限限定于工作流的当前仓库。当 `AIFS_TRANSLATION_REPOSITORY` 是当前的 `github.repository` 时它会运行,包括当 `AIFS_TRANSLATION_REF` 选择非默认分支时。如果 `AIFS_TRANSLATION_REPOSITORY` 指向别处,该源对此工作流为**只读**:准备任务发出明确通知并跳过翻译矩阵,而不是生成无法发布的工作或静默推送到当前仓库。因此,发布到外部仓库需要一个单独的、带有显式凭据的工作流;站点和课程审计可继续消费该外部源。

在 fork 发布其配置的翻译分支之前,课程任务会记录该分支缺失并跳过课程审计。它不会隐藏网络、认证或其他远端失败。该语言在站点上仍可选择,但缺失的已翻译文件会从活动的仓库/引用回退到英文。一旦配置的分支存在,CI 会获取该精确仓库/引用,翻译审计即变为阻塞性的。

## GitHub Pages 镜像

`.github/workflows/deploy-pages.yml` 构建 `site/` 并在每次推送到 `main` 时用官方 GitHub Pages 制品工作流发布它,外加手动派发。构建会读取 GitHub Actions 的仓库和分支元数据,因此 fork 服务于其自身的英文源,并默认为同一仓库的 `translations` 分支。请先于 `main` 发布该分支;否则已翻译课程的请求会回退到英文,直到该分支可用。

Pages 部署是一个静态镜像。权威站点仍是 `https://aiengineeringfromscratch.com`,其权威 URL、Open Graph、sitemap 和 `llms.txt` URL 刻意保留该来源。GitHub Pages 不实现 `vercel.json` 中声明的 Vercel 重写、响应头或 `/api/markdown` 内容协商;在镜像上请使用显式的 `.html` 路由。在首次部署前启用 **Settings → Pages → Source: GitHub Actions**。

## 绝不浪费一次运行

对于机器管理的语言,每节课以其英文源的 `sha256` 和生成它的提供商为键,存放在按(语言, 阶段)的缓存(`i18n/<lang>/.cache/<phase>.json`)中,在 runner 中逐课写入,并**在任务完成时发布到配置的翻译引用**。遗留的裸哈希条目被翻译器视为 NLLB 输出,并在重新生成时升级为感知提供商的记录,但审计器和已翻译书籍的预检要求当前的结构化记录。人工维护的语言使用一个单独的严格记录,包含将已审校散文绑定到其输入所需的三个必填字段:`source_sha256`、`output_sha256` 和 `provider: "manual"`。源哈希使用经通用换行符规范化后的权威英文文本;输出哈希覆盖已翻译文件的实际字节。裸哈希、缺失字段、其他提供商标记、过时的英文或被修改的已翻译字节都会使审计失败。`manual` 刻意不是一个机器翻译提供商,无法通过 `translate_lessons.py` 选择。因此:

- 对于机器管理语言,首次运行会一次性翻译所有内容。后续运行仅当某课的英文哈希和提供商与缓存匹配、其输出存在且完整性检查通过时才跳过该课。更改源或提供商、删除输出或完整性检查失败都会重新生成该课。
- 一个被取消或中断的机器翻译阶段任务不会发布,因此会丢失该任务在 runner 本地的进度,下次运行会从**上次已发布**的缓存恢复该阶段。由于每个分片是单一阶段,它能在任务时限内从容完成并发布。
- 对于人工维护语言,更改英文源或已翻译文件都会使审计失败,直到有人审校翻译并在其结构化溯源记录中刷新两个哈希。

## 各语言 README

README 是落地页,因此其翻译为**手工撰写**(最高质量)而非机器生成,存放于 `main` 的 `i18n/<lang>/README.md`。`scripts/readme_translations.py` 以精确的英文块为键保存散文和标题翻译。简体中文还使用 `i18n/zh/catalog/*.json` 覆盖全部 20 个阶段描述和 523 个课程标题,以及 `i18n/zh/readme-structural.json` 覆盖普通散文块之外的可见列表、表格、徽章和 HTML 文案。`scripts/build_readme_i18n.py` 从权威英文 README 重新构建每个文件。代码围栏、命令、标识符、语言名称和链接/图片目标保持不变;仓库根相对目标会加上所需的 `../../` 前缀。其他语言可能回退到英文,但简体中文按合同是完整的:每一个当前的散文片段、课程行、阶段和其他可见的结构行都必须被翻译或显式加入白名单,过时的键会被拒绝。

`python3 scripts/build_readme_i18n.py --check` 在 CI(`curriculum.yml`)中运行,若有任何已提交的 README 过时则失败。当简体中文会回退到英文、缺失任何 523 个课程标题或 20 个阶段条目、留下未分类的可见结构行,或包含过时的清单键时,它也会失败。README 计数 bot 在每次同步英文统计块时会重新生成已翻译的 README。

使用 `python3 scripts/audit_translations.py --lang zh` 可直接从普通克隆的本地 `origin/translations` 远程跟踪引用审计人工维护的课程树,而无需检出它。CI 会继续获取由 `AIFS_TRANSLATION_REPOSITORY` 和 `AIFS_TRANSLATION_REF` 选择的源,并将该精确引用传递给审计器。审计要求一对一的课程路径集合、完整的结构化溯源键、当前的英文和已翻译输出的 SHA-256 值、有效的非空 UTF-8 中文内容、无未解决的保护哨兵、无实质性的逐字英文散文,并保留标题、围栏、表格、原始 HTML、代码、数学、链接和 URL 结构。传入 `--translation-ref <ref>` 以匹配不同的已发布源,`--phase <phase-directory>` 以检查某个 CI 分片,或 `--translation-root <directory>` 以审计本地恢复的 `i18n/` 树。

## 翻译期间受保护的内容

NLLB 是句子翻译器,不是指令遵循模型,因此遍历器从不让它看到除散文以外的任何内容。它逐行处理课程:围栏代码块、原始 HTML、展示数学和元数据行(`**Type:** … **Time:**`)逐字通过。Markdown 表格结构和分隔行保持固定,而可见的单元格文本被翻译。在散文和表格单元格中,行内代码、行内数学、图片/链接目标、技术标记和 URL 受到保护;可见的强调和链接/图片标签仍可翻译。人工维护的翻译必须保留权威课程使用的每一个英文元数据键(`Type`、`Language` 或 `Languages`、`Prerequisites`、`Phases exercised`、`Time` 和可选的 `Related`),但可以本地化其值。围栏解析遵循标记字符和起始长度,单行 `$$ … $$` 数学不会隐藏其后跟随的散文。

这一点被机械地验证:用一个恒等"翻译"运行遍历器会逐字节重现全部 **523 课**,因此真实运行只能更改散文。如果某个占位符无法往返,该课保留其英文(故障安全)。

## 成本

默认提供商 `nllb`:对机器管理语言**免费**。NLLB-200 在 GitHub Actions runner 中运行 —— 无 API key、无密钥、无按 token 计费。唯一的资源是免费的 CI 计算;模型在运行间被缓存,且未更改的课程仅在其源哈希、提供商、输出和完整性检查仍匹配时才被复用。Vercel 成本不变。

可选升级(`--provider anthropic|openai|deepl`)以每种语言每个完整流程数 十美元 级别提供更高流畅度,如果你日后想打磨高流量语言的话。这些提供商从 `LLM_API_KEY` 环境变量读取 key(DeepL 使用同一变量作为其认证 key)。NLLB 始终是零成本默认。

## 质量示例

以下是 `05 · 03 Word Embeddings` 的节选,展示散文读起来自然,而代码、数学、`king - man + woman`、技术术语和元数据头保持不变。简体中文(`zh`)节选是**人工维护示例**,而非由 NLLB 或 Anthropic 生成的输出。土耳其语节选展示了可选 LLM 提供商可达到的流畅度;免费的 NLLB-200 默认通常更朴素。

### 简体中文 (zh)

> # 词嵌入 —— 从零实现 Word2Vec
>
> > 词以其所处的语境为意。用一个浅层网络训练这个想法,几何结构便会自然浮现。
>
> **Type:** Build · **Languages:** Python · **Prerequisites:** 阶段 5 · 02(BoW + TF-IDF)、阶段 3 · 03(从零实现反向传播) · **Time:** 约 75 分钟
>
> **问题** —— TF-IDF 知道 `dog` 和 `puppy` 是不同的词,但不知道二者含义几乎相同。在 `dog` 上训练的分类器无法泛化到讨论 `puppy` 的评论。你可以靠列举同义词勉强弥补,但这在罕见词、领域术语,以及所有你未曾预料的语言上都会失效。
>
> 你想要的是这样一种表示:`dog` 和 `puppy` 在空间中彼此靠近;`king - man + woman` 落在 `queen` 附近;在 `dog` 上训练的模型能免费地把部分信号迁移到 `puppy`。
>
> **核心概念** —— **分布假说**(Firth,1957):"要了解一个词,就看它与哪些词为伴。" Word2Vec 有两种形式:**Skip-gram** 给定中心词预测周围词(窗口为 2 时 `cat -> (the, sat, on)`);**CBOW(连续词袋)** 给定周围词预测中心词。网络只有一个隐藏层且无非线性:输入是词表上的 one-hot 向量,输出是 softmax,训练后丢弃输出层,隐藏层权重即为嵌入。诀窍是用**负采样(negative sampling)**把对 10 万词的 softmax 转成二分类。

### Türkçe (tr)

> # Kelime Gömmeleri —— Word2Vec'i Sıfırdan
>
> > Bir kelime, birlikte bulunduğu kelimelerden ibarettir. Bu fikri sığ bir ağ ile eğitin, geometri kendiliğinden ortaya çıkar.
>
> **Type:** Build · **Languages:** Python · **Prerequisites:** Aşama 5 · 02 (BoW + TF-IDF), Aşama 3 · 03 (Sıfırdan Geri Yayılım) · **Time:** ~75 dakika
>
> **Problem** —— TF-IDF, `dog` ve `puppy`'nin farklı kelimeler olduğunu bilir ama neredeyse aynı anlama geldiklerini bilmez. `dog` üzerinde eğitilen bir sınıflandırıcı, `puppy` hakkındaki bir yoruma genelleme yapamaz. Eş anlamlıları listeleyerek geçiştirebilirsiniz, ama bu; nadir terimlerde, alana özgü jargonda ve öngöremediğiniz her dilde başarısız olur.
>
> `dog` ve `puppy`'nin uzayda birbirine yakın düştüğü, `king - man + woman`'ın `queen`'e yakın indiği bir temsil istiyorsunuz. Word2Vec bunu verdi: iki katmanlı bir ağ, trilyon token'lık eğitim, 2013'te yayımlandı.
>
> **Kavram** —— **Dağılımsal hipotez** (Firth, 1957): "Bir kelimeyi birlikte bulunduğu kelimelerden tanırsın." İki tür: **Skip-gram** merkez kelimeden çevredekileri tahmin eder (pencere 2 ile `cat -> (the, sat, on)`); **CBOW** çevredekilerden merkezi tahmin eder. Ağın doğrusal olmayan aktivasyonu olmayan tek bir gizli katmanı vardır: girdi one-hot vektör, çıktı softmax'tır; eğitimden sonra çıktı katmanı atılır, gizli katman ağırlıkları gömmelerdir. Püf nokta, 100 bin kelimelik softmax'ı **negatif örnekleme (negative sampling)** ile ikili sınıflandırmaya çevirmektir.

注意 `dog`、`puppy`、`king - man + woman`、`softmax`、`one-hot`、`Skip-gram`、`CBOW`、`TF-IDF`、`Word2Vec` 以及 `**Type:** / **Time:**` 标签在两种语言中均逐字保留,而周围的散文被完全本地化。机器管理的输出受保护/恢复检查约束,而人工维护的 `zh` 树由翻译审计以相同的结构不变量加以约束。
