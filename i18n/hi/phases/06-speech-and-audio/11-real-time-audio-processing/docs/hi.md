# वास्तविक समय में ऑडियो प्रोसेसिंग

> बैच पाइपलाइन एक फ़ाइल को संसाधित करते हैं। वास्तविक समय पाइपलाइन अगले 20 मिलीसेकंड आने से पहले अगले 20 आने से पहले संसाधित करते हैं। हर वार्तालाप AI, प्रसारण स्टूडियो, और टेलीफोन बॉट इस विलंब बजट के द्वारा जीवित और मर जाता है।

**Type:** Build
**Languages:** Python
**Prerequisites:** Phase 6 · 02 (Spectrograms), Phase 6 · 04 (ASR), Phase 6 · 07 (TTS)
**Time:** ~75 minutes

## समस्या

आप एक आवाज सहायक चाहते हैं जो जीवित महसूस करता है। मानव वार्तालाप टर्न-टेक लेटेंसी ~ 230 एमएस (चुपचाप-से-जवाब) है। 500 एमएस से ऊपर की कोई भी चीज रोबोटिक लगती है; 1500 एमएस से ऊपर टूट लगता है। पूर्ण के लिए बजट **सुनें → समझें → जवाब दें → बोलें** 2026 में लूप हैः

| चरण | बजट |
|-------|--------|
| माइक्रो → बफर | 20 ms |
| VAD | 10 ms |
| ASR (streaming) | 150 ms |
| LLM (पहला टोकन) | 100 ms |
| TTS (पहला टुकड़ा) | 100 ms |
| रेंडर → स्पीकर | 20 ms |
| **कुल** | **~ 400 ms** |

मोशी (क्यूताई, 2024) ने 200 एमएस फुल-डप्लक्स की घड़ी बनाई। GPT-4o-realtime (2024) घड़ियों ~ 320 ms. 2022 में 2500 ms पर कैस्केड पाइपलाइनें शिप की गईं। 10x सुधार तीन तकनीकों से आयाः (1) हर जगह स्ट्रीमिंग, (2) आंशिक परिणामों के साथ असिनक्रोनस पाइपलाइन, (3) इंटरट्यूबल जनरेशन।

## अवधारणा

![रिंग बफर के साथ स्ट्रीमिंग ऑडियो पाइपलाइन, VAD गेट, विराम](../assets/real-time.svg)

**फ्रेम / टुकड़ा / खिड़की।** वास्तविक समय में ऑडियो प्रवाह निश्चित आकार के ब्लॉक के रूप में। आम विकल्पः 20 एमएस (320 नमूने 16 पर) kHz) नीचे की ओर सब कुछ इस गति के साथ रहना चाहिए।

**रिंग बफर.** फिक्स्ड साइज सर्कुलर बफर। निर्माता धागा नए फ्रेम लिखता है, उपभोक्ता धागा पढ़ता है। हॉट पथ में आवंटन को रोकता है। आकार ≈ अधिकतम विलंबता × नमूना दर; 2 सेकंड 16 kHz ring = 32,000 नमूने.

**VAD (आवाज गतिविधि का पता लगाना)** गट्स डाउनस्ट्रीम काम जब कोई नहीं बोल रहा है. VAD 4.0 (2024) runs <1 30 एमएस फ्रेम पर ms CPU. `webrtcvad` यह पुराना विकल्प है।

**स्ट्रीमिंग ASR.** ऑडियो आने पर आंशिक प्रतिलेखन emit मॉडल.CTC-0.6B स्ट्रीमिंग मोड में (NeMo, 2024) 25% है WER 320 एमएस विलंबता पर विस्मय-प्रवाह (Macháček et al., 2023) ~ 2 सेकंड विलंबता पर निकट-प्रवाह के लिए विस्मय-प्रवाह के टुकड़े।

**एक विराम।** जब उपयोगकर्ता सहायक बोल रहा है, तो आपको (ए) बारगे-इन का पता लगाना होगा, (बी) TTS, (ग) शेष को त्याग दें LLM 100 एमएस के भीतर, या उपयोगकर्ता बहरे सहायक को महसूस करता है।

**WebRTC ओपस परिवहन.** 20 एमएस फ्रेम, 48 kHz, अनुकूलन बिटरेट 8128 kbps. ब्राउज़र और मोबाइल के लिए मानक। LiveKit, डेली.कॉ, पियान आवाज अनुप्रयोगों के निर्माण के लिए 2026 स्टैक हैं।

**जेटर बफर.** नेटवर्क पैकेट आदेश से बाहर / देर से आते हैं। jitter बफर रीऑर्डर और चिकनी; बहुत छोटे → श्रव्य अंतराल, बहुत बड़ा → विलंबता। 6080 ms आम है।

### सामान्य गॉथ

- **धागे का विवाद।** Pythonहै GIL + भारी मॉडल ऑडियो थ्रेड को भूख से मार सकते हैं। एक सी-कॉलबैक ऑडियो लाइब्रेरी (ध्वनि डिवाइस, PortAudio) और रख Python गर्म पथ से दूर.
- **नमूना रूपांतरण दर लटेंसी।** पाइपलाइन के अंदर पुनः नमूनाकरण 520 ms जोड़ता है। या तो अग्रिम में पुनः नमूनाकरण करें या शून्य विलंबता पुनः नमूनाकरण (PolyPhase, `soxr_hq`).
- **TTS प्रिमिंग।** और भी तेजी से TTS कोकोरो के रूप में पहली मांग पर 100 से 200 ms वार्मिंग है. कैश मॉडल + पहले वास्तविक मोड़ से पहले एक डमी रन के साथ इसे गर्म करें।
- **इको रद्द.** बिना AEC, TTS आउटपुट माइक्रो में वापस प्रवेश करता है और ट्रिगर ASR बॉट की अपनी आवाज पर। WebRTC AEC3 खुला स्रोत डिफ़ॉल्ट है।

## इसे बनाओ

### चरण 1: रिंग बफर

```python
import collections

class RingBuffer:
    def __init__(self, capacity):
        self.buf = collections.deque(maxlen=capacity)
    def write(self, frame):
        self.buf.extend(frame)
    def read(self, n):
        return [self.buf.popleft() for _ in range(min(n, len(self.buf)))]
    def level(self):
        return len(self.buf)
```

क्षमता अधिकतम बफरिंग विलंबता निर्धारित करता है। 32,000 नमूने 16 पर kHz = 2 एस.

### चरण 2: VAD द्वार

```python
def simple_energy_vad(frame, threshold=0.01):
    return sum(x * x for x in frame) / len(frame) > threshold ** 2
```

सिलेरो से बदलें VAD उत्पादन मेंः

```python
import torch
```

## फंदे

- **सुरक्षित होने के लिए 500 एमएस बफरिंग।** बफर *है* अपने विलंब तल. इसे छोटा.
- **धागे नहीं लगा रहे हैं।** प्राथमिकता से कम-से-कम पर ऑडियो कॉलबैकUI thread = glitches लोड के तहत।
- **TTS बहुत छोटे टुकड़े.** 200 एमएस के तहत टुकड़े Vocoder कलाकृतियों को श्रव्य बनाते हैं। 320 एमएस टुकड़े सबसे अच्छा बिंदु हैं।
- **कोई जिक्र बफर नहीं।** वास्तविक नेटवर्क घबराहट में हैं; बिना सुचारू किए आप पॉप प्राप्त करते हैं।
- **एक शॉट त्रुटि हैंडलिंग।** ऑडियो पाइपलाइनों को दुर्घटना-प्रूफ होना चाहिए. एक अपवाद सत्र को मारता है.

## व्यायाम

1. **- आराम से।** दौड़ें `code/main.py`. Simulates a ring buffer + energy VAD; एक नकली 10 सेकंड धारा के लिए चरण विलंबता प्रिंट करता है।
2. **मध्यम।** उपयोग करना `sounddevice`, एक पार करने के माध्यम से लूप बनाने जो 20 ms फ्रेम और छवियों में अपने माइक्रोसॉफ्ट को संसाधित VAD प्रत्येक फ्रेम पर स्थिति।
3. **कठिन.** एक पूर्ण दोहरे इको परीक्षण का निर्माण करें `aiortc`: ब्राउज़र → WebRTC → Python → WebRTC → ब्राउज़र. 1 के साथ ग्लास-टू-ग्लास विलंबता मापें kHz धड़कन।
