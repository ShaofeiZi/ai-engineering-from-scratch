# A2A एजेंट-एजेंट प्रोटोकॉल

> गूगल ने घोषणा की A2A अप्रैल 2025 में; अप्रैल 2026 तक विनिर्देश https://a2a-protocol.org/latest/specification/ और 150 से अधिक संगठनों का समर्थन करते हैं। A2A क्षैतिज पूरक है MCP (पाठ 13): जहां MCP ऊर्ध्वाधर है (एजेंट  उपकरण), A2A यह एजेंट कार्ड (खोज) , कलाकृतियों (पाठ, संरचित डेटा, वीडियो), अस्पष्ट कार्य जीवन चक्र, और लेखक के साथ कार्यों को परिभाषित करता है। उत्पादन प्रणालियों को तेजी से जोड़ना MCP के साथ A2A. गूगल क्लाउड रोल A2A वर्टेक्स में समर्थन AI एजेंट बिल्डर के दौरान 2025-2026।

**Type:** Learn + Build
**Languages:** Python (stdlib, `http.server`, `json`)
**Prerequisites:** Phase 16 · 04 (Primitive Model)
**Time:** ~75 minutes

## समस्या

आपके एजेंट को दूसरे एजेंट को दूसरे सिस्टम पर कॉल करने की आवश्यकता है। HTTP अंत बिंदु, एक कस्टम परिभाषित JSON एजेंटों के प्रत्येक जोड़े एक कस्टम एकीकरण बन जाता है.

A2A मानक खोज, मानक कार्य मॉडल, मानक परिवहन, मानक कलाकृतियों की तरह। HTTP+REST लेकिन पहले श्रेणी के नागरिकों के रूप में एजेंटों के लिए।

## अवधारणा

### चार तत्व

**एजेंट कार्ड.** A JSON पर दस्तावेज `/.well-known/agent.json` एजेंट का वर्णन करनाः नाम, कौशल, अंत बिंदु, समर्थित मोडलिटीज, लेखक आवश्यकताएं। कार्ड पढ़ने से पता चलता है।

```
GET https://agent.example.com/.well-known/agent.json
→ {
    "name": "code-review-agent",
    "skills": ["review-python", "review-typescript"],
    "endpoints": {
      "tasks": "https://agent.example.com/tasks"
    },
    "auth": {"type": "bearer"},
    "modalities": ["text", "structured"]
  }
```

**कार्य.** कार्य की इकाई. जीवन चक्र के साथ एक असिनक्रोनस, राज्यपूर्ण वस्तुः `submitted → working → completed / failed / canceled`. एक ग्राहक एक कार्य भेजता है, सर्वेक्षण करता है या अद्यतन के लिए सदस्यता लेता है।

**कलाकृतियाँ।** किसी कार्य द्वारा उत्पन्न परिणाम प्रकार। JSONकलाकृतियों को टाइप किया जाता है तो विभिन्न मोडलिटी प्रथम श्रेणी हैं।

**अस्पष्ट जीवन चक्र।** A2A निर्धारित नहीं करता है *कैसे* रिमोट एजेंट कार्य को हल करता है। क्लाइंट राज्य संक्रमण और कलाकृतियों को देखता है; कार्यान्वयन किसी भी ढांचे का उपयोग करने के लिए स्वतंत्र है।

### इन MCP/A2A विभाजित

- **MCP** (पाठ 13): एजेंट  उपकरण। एजेंट पढ़ता/लिखता है JSON-RPC एक उपकरण सर्वर पर। डिफ़ॉल्ट रूप से देशहीन.
- **A2A**: एजेंट  एजेंट. पीयर प्रोटोकॉल; दोनों पक्ष अपने तर्क के साथ एजेंट हैं।

उत्पादन बहु-एजेंट सिस्टम दोनों का उपयोग करते हैं। A2A सहकर्मी कॉल MCP उसके पक्ष पर उपकरण. विभाजन दोनों चिंताओं को साफ रखता है.

### खोज प्रवाह

```
Client                     Agent server
  ├──GET /.well-known/agent.json──>
  <──Agent Card JSON─────────────
  ├──POST /tasks {skill, input}──>
  <──201 task_id, state=submitted
  ├──GET /tasks/{id}──────────────>
  <──state=working, 42% done──────
  ├──GET /tasks/{id}──────────────>
  <──state=completed, artifacts──
```

या स्ट्रीमिंग के साथः SSE सदस्यता `/tasks/{id}/events` पुश अद्यतन के लिए.

### लेखक

A2A तीन आम पैटर्न का समर्थन करता हैः

- **धारक टोकन** — OAuth2 या अस्पष्ट।
- **mTLS** पारस्परिक TLSसंगठन एक दूसरे के साथ पहचान साबित करते हैं।
- **हस्ताक्षरित अनुरोध** — HMAC उपयोगिता लोड पर.

एजेंट कार्ड में लेखक घोषित किया गया है; ग्राहक पता लगाते हैं और अनुपालन करते हैं।

### 150+ organizations by April 2026

उद्यम गोद लेने की चाल A2A शीर्षक: A2A गूगल क्लाउड ने वर्टेक्स को एक नए तरीके से लॉन्च किया है। AI एजेंट बिल्डर A2A समर्थन; Microsoft एजेंट फ्रेमवर्क इसका समर्थन करता है; अधिकांश प्रमुख फ्रेमवर्क (LangGraph, CrewAI, AutoGen) जहाज A2A एडाप्टर।

### कहाँ A2A जीतता है

- **क्रॉस-संगठन कॉल.** कंपनी ए के एजेंट कंपनी बी के एजेंट को कॉल करता है A2A, प्रत्येक जोड़ी एक कस्टम अनुबंध है.
- **विभेदित ढांचे।** LangGraph एजेंट कॉल CrewAI एजेंट कस्टम कॉल Python एजेंट. A2A सामान्य हो जाता है।
- **टाइप कलाकृतियों.** वीडियो परिणाम, संरचित JSON, ऑडियो  सभी प्रथम श्रेणी.
- **लंबे समय तक चलने वाले कार्य।** अस्पष्ट जीवन चक्र + मतदान घंटों तक चलने वाले कार्यों को सरल बनाता है।

### कहाँ A2A संघर्ष

- **लटेंसी-संवेदनशील माइक्रो-कॉल.** A2Aउप-मिलीसेकंड एजेंट-टू-एजेंट फिट नहीं होता है; सीधे उपयोग करें RPC.
- **प्रक्रिया में निकट संबद्ध एजेंटों।** यदि दोनों एजेंटों एक ही में भागते हैं Python प्रक्रिया, A2Aहै HTTP घूमने-फिरने की यात्रा बहुत अधिक है।
- **छोटी टीमें।** विशिष्ट ओवरहेड वास्तविक है; केवल आंतरिक एजेंटों को औपचारिकता की आवश्यकता नहीं हो सकती है।

### A2A vs ACP, ANP, NLIP

2024-2026 में कई संबंधित विनिर्देश सामने आएः

- **ACP** (IBM/Linux संस्था)  पूर्ववर्ती A2A, संकीर्ण क्षेत्र।
- **ANP** (एजेंट नेटवर्क प्रोटोकॉल)  सहकर्मी-खोज-भारी, विकेन्द्रीकृत-पहले।
- **NLIP** (इकमा प्राकृतिक भाषा बातचीत प्रोटोकॉल, मानकीकृत दिसंबर 2025)  प्राकृतिक भाषा सामग्री प्रकार।

A2A अप्रैल 2026 तक सबसे अधिक अपनाया गया सहकर्मी प्रोटोकॉल है। arXiv505.02279 (Liu et al., "ए सर्वे ऑफ एजेंट इंटरऑपरेबिलिटी प्रोटोकॉल") तुलना के लिए।

## इसे बनाओ

`code/main.py` एक A2A-minimal सर्वर और क्लाइंट का उपयोग `http.server` और JSON. सर्वरः

- उजागर `/.well-known/agent.json`,
- स्वीकार करता है `POST /tasks`,
- कार्य स्थिति का प्रबंधन करता है,
- पर कलाकृतियों को लौटाता है `GET /tasks/{id}`.

ग्राहक:

- एजेंट कार्ड लाता है,
- एक कार्य प्रस्तुत करता है,
- मतदान पूरा होने तक,
- कलाकृतियों को पढ़ता है।

दौड़ें:

```
python3 code/main.py
```

स्क्रिप्ट पृष्ठभूमि थ्रेड में सर्वर शुरू करता है, फिर क्लाइंट को इसके खिलाफ चलाता है. आप पूरा प्रवाह देखते हैंः खोज, सबमिट, सर्वेक्षण, कलाकृतियों।

`outputs/skill-a2a-integrator.md` एक डिजाइन A2A एकीकरणः एजेंट कार्ड सामग्री, कार्य योजनाएं, लेखक चयन, स्ट्रीमिंग बनाम मतदान।

## इसे भेजें

चेकलिस्टः

- **स्पेसिफिकेशन संस्करण को पिन करें।** A2A अभी भी विकसित हो रहा है; एजेंट कार्ड प्रोटोकॉल संस्करण घोषित करना चाहिए।
- **अक्षम कार्य निर्माण।** दोहरी प्रस्तुतियाँ (नेटवर्क री-ट्रेस) एक कार्य उत्पन्न करना चाहिए।
- **कलाकृतियों के योजनाओं.** एजेंट द्वारा लौटाए गए आकारों की घोषणा करें; उपभोक्ताओं को सत्यापित करना चाहिए।
- **Rate limits + auth.** A2A सार्वजनिक है; मानक वेब सुरक्षा लागू करें।
- **असफल कार्यों के लिए मृत पत्र।** आवर्ती विफलता प्रकारों के लिए समय के साथ पैटर्न की जांच करें।

## व्यायाम

1. दौड़ें `code/main.py`. पुष्टि करें कि ग्राहक सर्वर की खोज करता है और सही कलाकृतियों प्राप्त करता है.
2. सर्वर में एक दूसरा कौशल जोड़ें (जैसे, "संक्षेप में") एजेंट कार्ड को अपडेट करें। एक क्लाइंट लिखें जो कार्य प्रकार के आधार पर कौशल का चयन करता है।
3. एक SSE स्ट्रीमिंग एंडपॉइंटः `/tasks/{id}/events` ग्राहक को अलग से क्या करने की जरूरत है?
4. पढ़िए A2A विनिर्देश (https://a2a-protocol.org/latest/specification/) तीन चीजों की पहचान करें जो इस डेमो में लागू नहीं किए जाते हैं।
5. तुलना करें A2A (एजेंट कार्ड की खोज) MCP (सेवर पक्ष क्षमता सूची via `listTools`) स्वयं-वर्णन एजेंटों और क्षमता परीक्षण के बीच क्या अंतर है?
