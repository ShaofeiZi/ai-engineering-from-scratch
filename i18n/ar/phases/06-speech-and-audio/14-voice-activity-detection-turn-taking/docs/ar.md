# اكتشاف نشاط الصوت وتحويل الدوام  سيلرو وكوبرا وخدعة الفلاش

> كل وكيل صوتي يعيش أو يموت على قرارين: هل المستخدم يتحدث الآن، وهل انتهت؟ VAD يرد على الأول.VAD + صمت-توقف + نموذج النقطة النهائية الترجمية) يجيب على الثانية. إما أن تكون خاطئة ومساعدك إما يقطع المستخدمين أو لا يخرس أبدا.

**Type:** Build
**Languages:** Python
**Prerequisites:** Phase 6 · 11 (Real-Time Audio), Phase 6 · 12 (Voice Assistant)
**Time:** ~45 minutes

## المشكلة

ثلاثة قرارات مختلفة يقوم بها وكيل الصوت على كل 20 ميس:

1. **هل هذه خطاب الإطار؟** — VAD. ثنائي، لكل إطار.
2. **هل بدأ المستخدم في تصريح جديد؟** اكتشاف بداية
3. **هل انتهى المستخدم؟** الإشارة النهائية (التحول النهائي).

الجواب البطيء (الحدّ الطاقة) يفشل في أي ضجيج  حركة المرور، لوحة المفاتيح، حركة الجمهور. الجواب 2026: سيلرو VAD (فتح، متعمق) + نموذج للكشف عن التحول (التوجيه النهائي المفروض) + VAD-calibrated الصمت الكبيرة.

## المفهوم

### الدرجة الثلاثية VAD السقوط

**المستوى الأول: بوابة الطاقة** أرخص شيء، عتبة RMS عند -40 dBFS. يُصفّر الصمت الواضح، لكنه يُطلق النار على أي ضجيج فوق العدالة.

**المستوى الثاني: سيلرو VAD** (2020-2026, MITملامح 1م. تدرب على 6000+ لغة. تعمل في ~ 1ms لكل 30ms قطعة على واحدة CPU الحبل: 87.7٪ TPR في 5٪ FPR. المصدر المفتوح الافتراضي

**المستوى الثالث: جهاز كشف التحول** LiveKitنموذج الكشف عن التحول (2024-2026) أو تصنيفك الصغير الخاص. يفرق بين "وقف في منتصف الجملة" و"تحدثاً قد تم". يستخدم السياق اللغوي (التعبير + الكلمات الأخيرة) ، وليس مجرد الصمت.

### المعلمات الرئيسية وتعديلاتها

- **عتبة** سيلرو يخرج احتمال ؛ تصنيف الخطاب عند &gt; 0.5 (الديفال) أو &gt; 0.3 (الحساسة). أقل threshold = fewer كلمات أولى، المزيد من الإيجابيات الكاذبة.
- **الحد الأدنى من مدة الكلام** رفض الكلام أقصر من 250 ms  عادة السعال أو ضجيج الكرسي.
- **الصمت (التوجيه النهائي)** بعد VAD يعود إلى 0، انتظر 500-800 ثانية قبل الإعلان عن نهاية التحول. قصيرة جدا → توقف المستخدم. طويل جدا → يشعر بطيئة.
- **-مُساعد قبل التدفق** إبق 300-500 ملم من الصوت قبل VAD الحرائق، يمنع "هي" من التقطيع

### خدعة التسرب (كيوتاي 2025)

التدفق STT النماذج لديها تأخير في النظر إلى الأمام (500 ms بالنسبة إلى كيوتاي STT-1B، 2.5 ثانية STT-2.6Bعادةً ما تنتظرين هذا الوقت بعد نهاية الخطاب لنسخة النص VAD "إنهار النار" **إرسال إشارة للاستفادة من STT** الذي يفرض الخروج الفوري. STT العمليات في ~ 4 × الوقت الحقيقي، لذلك 500 ms المضخة تنتهي في ~ 125 ms.

نهاية إلى نهاية: 125 ms VAD + flush STT = conversational التأخير

### 2026 VAD المقارنة

| VAD | TPR @ 5% FPR | التأخير | رخصة |
|-----|--------------|---------|---------|
| WebRTC VAD (جوجل، 2013) | 50.0% | 30 ms | BSD |
| سيلرو VAD (2020-2026) | 87.7% | ~ 1 سم | MIT |
| كوبرا VAD (Picovoice) | 98.9% | ~ 1 سم | التجارية |
| التقسيم على الملاحظات | 95% | ~ 10 ميس | MIT-ish |

سيلرو هو الاختيار المسبق، كوبرا هو تحديث الامتثال/الادقة، الطاقة فقط VAD لا مكان له في الإنتاج عام 2026.

## بناءها

### الخطوة الأولى: بوابة الطاقة

```python
def energy_vad(chunk, threshold_dbfs=-40.0):
    rms = (sum(x * x for x in chunk) / len(chunk)) ** 0.5
    dbfs = 20.0 * math.log10(max(rms, 1e-10))
    return dbfs > threshold_dbfs
```

### الخطوة الثالثة: آلة الحالة التحولية

```python
class TurnDetector:
    def __init__(self, silence_hangover_ms=500, min_speech_ms=250):
        self.state = "idle"
        self.speech_ms = 0
        self.silence_ms = 0
        self.silence_hangover_ms = silence_hangover_ms
        self.min_speech_ms = min_speech_ms

    def update(self, is_speech, chunk_ms=20):
        if is_speech:
            self.speech_ms += chunk_ms
            self.silence_ms = 0
            if self.state == "idle" and self.speech_ms >= self.min_speech_ms:
                self.state = "speaking"
                return "START"
        else:
            self.silence_ms += chunk_ms
            if self.state == "speaking" and self.silence_ms >= self.silence_hangover_ms:
                self.state = "idle"
                self.speech_ms = 0
                return "END"
        return None
```

### الخطوة الرابعة: هيكل الحيلة

```python
def flush_on_end(stt_client, audio_buffer):
    stt_client.send_audio(audio_buffer)
    stt_client.send_flush()
    return stt_client.recv_transcript(timeout_ms=150)
```

## الفخاخ

- **عتبة ثابتة** يعمل في الهدوء، يفشل في الضوضاء إما أن يُعدل على الجهاز أو أن يُحول إلى "سيلرو".
- **صمت قصير جداً** الوكيل يقاطع منتصف الجملة 500-800 ميس هو المكان المفضل للخطاب المحادث
- **-السكك الساخن الطويل جداً** يبدو بطيئًا اختبار A/B مع المستخدمين المستهدفين
- **لا يوجد مسدس قبل التدفق** أول 200-300 ملم من صوت المستخدم ضائع دائماً حافظ على التدفق قبل التدفق
- **تجاهل الإشارة النهائية** "دعني أفكر" تحتوي على توقفات طويلة المستخدمون يكرهون أن يقطعوا في منتصف التفكير LiveKitجهاز كشف التحول أو ما شابه ذلك

1. **-بسهولة** أركض `code/main.py`إنه يحاكي خطبة + صمت + خطبة + السعال تسلسل و يختبر ثلاثة VAD مستويات
2. **متوسط** إثباط `silero-vad`، معالجة تسجيل لمدة 5 دقائق، ضبط عتبة لتقليل كل من المقاطع الكلمة الأولى والتحفيزات الكاذبة.
3. **صعب** بناء جهاز تحديد التحول الصغير: سيلرو VAD + a 3-layer MLP على إدخال آخر 10 كلمات (استخدم محولات الجملة). تدريب على مجموعة بيانات التحول المُشيرة يدوياً. هزيمة Silero فقط بنسبة 10% F1.

## الشروط الرئيسية

| المدة | ما يقوله الناس | ما يعنيه هذا في الواقع |
|------|-----------------|-----------------------|
| VAD | جهاز كشف الصوت | ثنائي لكل إطار: هل هذه الخطاب؟ |
| كشف التحول | الإشارة النهائية | VAD + silence-hangover + semantic endpoint. |
| صمت الخمر | الانتظار بعد الكلام | وقت الانتظار قبل إعلان نهاية التحول: 500-800 ms. |
| المقبل | عازف قبل الكلام | حافظ على 300-500 ms الصوت قبل VAD حرائق |
| خدعة التدفق | كيوتاي هاك | VAD -الـ "فلاش"STT → 125 ms بدلا من تأخير 500 ms. |
| نقطة نهاية تعبيرية | "هل كانوا يقصدون التوقف؟" | ML تصنيف يبحث عن الكلمات، وليس فقط الصمت. |
| TPR @ FPR 5% | ROC نقطة | القياسية VAD المرجعية: 87.7% بالنسبة لـ Silero، 50% WebRTC. |
