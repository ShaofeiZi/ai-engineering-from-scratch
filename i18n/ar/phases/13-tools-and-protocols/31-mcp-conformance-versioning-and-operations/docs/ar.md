# MCP هندسة التوافق: الإصدارات والأدلة والعمليات

> الخادم ليس متوافقًا لأن مسار سعادته عمل من خلال واحد SDK. تعيش التوافق عند الأسلاك، عند حدود الإصدار، من خلال الوسطاء، وخلال التداول.

**Type:** Build
**Languages:** Python
**Prerequisites:** Phase 13 · 09 (transports), Phase 13 · 17 (gateways), Phase 13 · 30 (registry admission)
**Time:** ~100 minutes

## أهداف التعلم

- تحوّل إلى القواعد MCP القواعد إلى النصوص الذهبية والسلبية
- إبق صارم `2026-07-28` سلوك منفصل عن التراجع المحدود
- تمييز حقل غير معروف من غير صالح غير معروف `resultType`.
- مقارنة الخام JSON-RPC دليل مع SDK-normalized منظر
- إثبات سلامة الرأس والجسم عبر حدود الوكالة الحقيقية.
- إصدارات البوابة مع النسخة المحذوفة، الصحة، والدليل على التراجع.

## المشكلة

موكلك يتصل `tools/list` من خلال SDK ويحصل على الأدوات، ويمضي اختبار التكامل

هذا النتيجة تترك أسئلة مهمة دون إجابة:

- هل كان الطلب يحمل بيانات متطابقة حديثة لكل طلب؟
- لقد فعلت `MCP-Protocol-Version`, `Mcp-Method`و `Mcp-Name` يطابق JSON-RPC الجثة؟
- هل كانت الإجابة تحتوي على `resultType` على السلك، أو فعل SDK -إختلط واحدة؟
- هل سيحافظ العميل على حقل مضيف مستقبلاً؟
- هل خطأ معترف به في عصرنا الحديث سيؤدي بالخطأ إلى ضغط يد متكرر؟
- هل حافظ وكيل على حالة الأصل JSON-RPC خطأ؟
- هل أصدرت المُسلسلة الإخطارية ردة فعل محظورة؟
- هل يمكن أن تثبت العمليات لماذا تم تعزيز الإفراج أو إرجاعه دون تخزين أسرار؟

التوافق هو مجموعة من الخيارات غير المتغيرة الملاحظة. قم ببناء حلقة تسجل هذه الخيارات غير المتغيرة قبل أن يتم اكتشافها من قبل حركة الإنتاج.

```figure
mcp-conformance-operations
```

## ابدأ مع نسخة العصور

MCP `2026-07-28` يستخدم البيانات المتحركة لكل طلب. `params._meta.io.modelcontextprotocol/protocolVersion` و `params._meta.io.modelcontextprotocol/clientCapabilities`المفاتيح المحددة التي تمتد بين الاسماء مهمة `protocolVersion` أو `clientCapabilities` التسميات غير المشكولة. عندما تكون عناوين التوجيه المرئية موجودة في HTTP الحدود، يجب أن تكون قيمها متوافقة مع JSON-RPC النتائج الناجحة الحديثة تحمل `resultType`.

الإصدارات من خلال `2025-11-25` استخدم عصر التبني السابق. نتيجة سابقة بدون `resultType` يتم تفسيرها ككاملة فقط بعد أن يختار العميل تلك الفترة السابقة.

لا تخلق مؤكدة إذن واحدة تقبل كلا الشكليين في وقت واحد. استخدم فرعين:

| فرع | دليل الدخول | مفقود `resultType` | التشغيل |
|---|---|---|---|
| الحديثة | ناجح `server/discover` أو رد المعترف به الحديث | غير صالحة | ليس المسار الافتراضي |
| التراث | قائمة الإذن المثبتة بالإضافة إلى إرث صالح `initialize` النتيجة بعد صفقة حديثة غير حاسمة | تفسيرها ككل | ما يتطلبه ذلك العصر |

إن الفصل يمنع أقرانه المعاصرين المعاصرين من أن يتلقوا مكافأة بتأكيد أضعف.

### وضع صارم

وضع صارم يتطلب إثبات السلوك الحديث `server/discover` يثبت أن الفرع الحديث JSON-RPC خطأ يثبت ذلك أيضاً. تصحيح الطلب أو توقف. لا تخفض أبداً لأن الخادم عاد `-32020`, `-32021`أو `-32022`.

### وضع التراجع

وضع Fallback يؤدي صفقة حديثة واحدة محدودة. فترة توقف، رد فارغ، اتصال مغلق، أو رد غير معروف غير حاسمة. لا يثبت أن النسخة نفسها هي التراث. فقط نقطة نهاية محددة صراحة أو مسموحة للتوافق يمكن أن تتلقى صفقة متواجدة محددة، ويتم اختيار العميل لقعة متواجدة فقط بعد التحقق من أن الصفقة التي `initialize` نتيجة وتفاوض مراجعة التراث.

لا يتم إعادة التقييم بعد أي خطأ. يحتوي خطأ حديث معترف به على معلومات تصحيح مفيدة. يمكن أن تخفيض الترتيب بعد ذلك إخفاء عدم مطابقة الرأس أو إعلان القدرة المفقودة أو الإصدار غير المدعوم.

هذا يمنع المهاجم أو التوقف أو تصفية النظام الأساسي من إقناع التراجع من خلال إسقاط الاستجابة الحديثة. سجل سياسة نقطة النهاية، وملاحظة حديثة غير حاسمة، والدليل الإيجابي الدقيق التراث، والعصر المختار معا.

سجّل العصر المحدد بجوار كل نسخة، وبدون هذه الحقيقة، يمكن أن يبدو حقل مفقود مقبولًا في تجربة واحدة وغير صالحًا في تجربة أخرى.

## بناء نسخة

ويقوم جهاز النسخ بتسجيل ما تجاوز الحدود، ليس فقط SDK اتصل:

```json
{
  "name": "golden-modern-list",
  "era": "modern",
  "headers": {
    "MCP-Protocol-Version": "2026-07-28",
    "Mcp-Method": "tools/list"
  },
  "request": {
    "jsonrpc": "2.0",
    "id": 1,
    "method": "tools/list",
    "params": {
      "_meta": {
        "io.modelcontextprotocol/protocolVersion": "2026-07-28",
        "io.modelcontextprotocol/clientCapabilities": {}
      }
    }
  },
  "responseStatus": 200,
  "responseBody": {
    "jsonrpc": "2.0",
    "id": 1,
    "result": {
      "resultType": "complete",
      "tools": []
    }
  }
}
```

إبقَ فئتين من الأجهزة

### النسخ الذهبية

النصوص الذهبية تثبت السلوك المقبول:

- طلب اكتشاف حديث أو طريقة مع بيانات أساسية ومعاقل متطابقة
- النتيجة الكاملة مع الحقول المطلوبة
- `input_required` النتيجة عندما يمكن للنهج طلب المزيد من المدخلات
- نتيجة التوسع فقط بعد إعلان القدرة المقابلة
- نتيجة إرث بدون `resultType`، ولكن فقط في عصر التراث المختار
- معالجة الإخطار بدون JSON-RPC ردود فعل

النسخة الذهبية دقيقة، ليست كبيرة IDs وخطوط زمنية تحديدية أو تطبيعها قبل المقارنة.

### النسخة السلبية

النسخة السلبية تثبت سلوك الرفض:

- عدم مطابقة الرأس والجسم
- إمكانات المفقودة حسب الطلب
- نسخة بروتوكول متطابقة غير مدعومة
- المفقودين الحديثة `resultType`
- غير معروف أو غير مدعوم `resultType`
- ردود فعل `jsonrpc` غير `2.0` أو ID التي تختلف في القيمة أو JSON النوع
- رد يتضمن كلا `result` و `error`أو لا أحد منهم
- خطأ بدون عدد كامل `code` و الخيط `message`
- خطأ بروتوكول معروف تم تعريفه إلى الخطأ HTTP الوضع
- رد صادر عن إخطار
- غير مصممة JSON-RPC غلاف
- انهيار النظام الأساسي لخطأ بروتوكول

لكل حالة سلبية، تأكد من حد رفض ورمز الخطأ المستقر. فشل الاتصال ضعيف جدا. 500 واصل `-32020` يمكن أن تبدو كفشل بينما تخبر المستخدمين قصص مختلفة تماما.

يجب أن يحتوي جهاز التطابق غير المتماثل للقائمة على الخادم الفعلي HTTP 400 JSON-RPC رد مع طلب المطابقة ID و رمز الخطأ `-32020`. تطبيق ذلك تلقائياً كلما لاحظ المؤكد المحلي `HeaderMismatch`لا تجعل من التحقق من الاستجابة علامة إضافية اختيارية. HTTP 500 و لا يوجد جسم يفشل حتى عندما يكون رمز الرفض المحلي صحيحاً. قناة تتوقف بعد أن يرمي مؤكدة طلبها الخاصة اختبرت نفسها فقط، وليس سلوك الخادم.

المسؤول MCP مشروع التوافق مفيد كمتعة خارجية ومرجح نسخة. الحفاظ على النسخ المحلية أيضا. SDK، التوثيق، التوسعات، و طريق الإفراج، الذي لا يمكن أن يعرفه مجموعة عامة.

## يجب أن تتطابق قيم العنوان RPC الجسم

في المقطع التسريمي الحديث HTTPيمكن للمساومين توجيه أو إنفاذ السياسة باستخدام عناوين مرآة. JSON-RPC لا يزال الجسم مصدر البروتوكول للحقّة، عدم الملاءمة هو فشل في النزاهة، وليس إشارة للاختيار من قيمة واحدة.

تصحيح في هذا الترتيب:

1. تحليل وتصديق JSON-RPC أنواع الملفات والمعايير.
2. مقارنة `MCP-Protocol-Version` مع `params._meta.io.modelcontextprotocol/protocolVersion`.
3. مقارنة `Mcp-Method` مع `method`.
4. عندما يكون للطريقة اسم توجيه، مقارنة `Mcp-Name` مع القيمة الجسدية المقابلة.
5. بعد أن يتم تأسيس المساواة، قم بتحديد ما إذا كانت الإصدار المماثل ومجموعة القدرات مدعومة.

هذا النظام يميز عدم التطابق `-32020` من نسخة غير مدعومة `-32022`كما أنه يمنع البوابة من تفويض اسم العنوان بينما يقوم المصدر بتنفيذ اسم جسم آخر.

HTTP أسماء المجال غير حساسة للحالة، في حين أن قيمها تظل حساسة للحالة.ASCIIأو مساحة بيضاء متقدمة أو متتابعة `Mcp-Name`، فك رمز الدقة `=?base64?{Base64EncodedValue}?=` UTF-8 الحارس قبل مقارنته مع الجسم. رفض الحارس غير كامل، غير صالح Base64غير صالحة UTF-8أو قيمة غير آمنة خامة `-32020`. المساحة البيضاء المحيطة بالبنية غير صالحة حتى عندما تحتوي الجسم على نفس العلامات لأن هذه القيمة تتطلب تشفير الحارس قبل النقل.

يمكن للمساوم رفض الملفات HTTP قبل وصول طلب إلى MCP الخادم، لذلك فشله قد يكون HTTP خطأ بدون JSON-RPC. تحديد ما إذا كان الرفض جاء من الوسيط أو من المنشأ MCP يجب على الخادم استخدام عقد الخطأ البروتوكول عندما يتعامل مع JSON-RPC طلب

## الحقول غير المعروفة ليست نتائج غير معروفة

تتطلب التوافق الآجل قواعد مختلفة.

### الحقول غير المعروفة الإضافية

كائنات النتيجة و `_meta` يمكن لخرائط الحصول على حقل. يجب على المؤكد الحفاظ على حقل إضافي أو تجاهله وفقا لدوره ، ما لم ينتهك الحقل عقد محجوز. يحتفظ العينة بالنتيجة الخام الكاملة في الأدلة ويقبل `futureHint` إلى جانب نتيجة معروفة

إذا كنت وكيلًا مرئيًا ، فإن الحفاظ على حقل مجهول عادةً ما يكون أكثر أمناً من إزالته. إذا كنت عميلًا للتطبيق ، فإن تجاهله يمكن أن يكون صالحًا. يجب أن يكشف اختبار التفاضل الخاص بك SDK لقد غفلت عن ذلك لذا السلوك متعمد

### غير معروف `resultType`

`resultType` هو تمييز. النتائج الحديثة الأساسية استخدام `complete` أو `input_required`. يمكن لمتوسع إضافة قيمة أخرى فقط عندما تم الإعلان عن قدرته. `task` في سياق القدرة المفاوضة.

لا يمكن التعامل مع المتميّز الذي لا يعرفه أو لا يُعلن عنه بأمان ككامل. العميل لا يعرف دورة الحياة التي سيتمّ إلقائها. رفضها.

لذلك يمكن أن تحتوي نفس الاستجابة الخام على حقل غير معروف مقبول ونوع غير مقبول من النتائج غير معروفة. اختبر كلتا الحالتين.

المتميز هو فقط الطبقة الأولى. تأكيد الحمل المفيد المحدد للنهج بعد ذلك. `tools/list` النتيجة تحتاج إلى `tools` صف الذي يحتوي وصفاته على أسماء غير فارغة فريدة، وصف مفيد، وجذر الموضوع `inputSchema` القيم `task` النتيجة صالحة فقط للاستحقاق `tools/call` مع القدرة على المهام ويتطلب `taskId`، الوضع المعروف، إنشاء وتحديث العلامات الزمنية، `ttlMs`، بالإضافة إلى فترة اختيارية صالحة للتصويت `completion/complete` النتيجة تتطلب `completion` كائن لا يزيد عن 100 قيمة سلسلة، وهو عدد كامل غير سلبي اختياري `total` لا تقل عن القيم المرجعة، وبدون خيار بولي `hasMore`-حرفيّة جيدة `resultType` لا يمكن أن تصنع تحميل مفيد غير مصمم

## تغييرات في الإخطار

A JSON-RPC الإخطار لا `id`لا يجوز للمستلم إرسال JSON-RPC رد فعل النجاح أو الخطأ.

لـ (المُقبل) HTTP شكل الإخطار، والحبل يتوقع HTTP `202` مع جسم فارغ MCP `2026-07-28` لا تعريف إشعارات العميل إلى الخادم الأساسية عبر Streamable HTTP. تستخدم العينة إشعار تمديد المسار مع مساحة الأسماء فقط لاختبار عدم تغير المسلسلات المتسلسلة ذات الاتجاه الواحد. لا تعرضها كطريقة أساسية جديدة.

اختبر المُسلسل، ليس فقط المُتعامل `None` بينما البرمجيات المتوسطة تغلفها في JSON كائن النجاح، قم بتسجيل البايتات النهائية

## إضافة SDK التفاوت

SDKs في كثير من الأحيان تحويل الأشياء السلكية إلى أنواع لغة مريحة. هذا مفيد، ولكن لا يمكن للموضوع المعتاد أن يثبت ما تم تلقي.

لكل جهاز ذو مخاطر عالية، التقاط:

1. حالة الخام، العناوين، وهيئة الاستجابة قبل SDK -تفكيك
2. SDK-normalized قيمة العائد أو الاستثناء.
3. التنبؤات المنتظرة للفترة المختارة
4. الحقول التي رفعها أو sintetized أو stripped أو تغيرها من قبل SDK.

تصريحات العينة SDK-only إزالة الحسابات المعرفة مثل: `resultType`, `_meta`, `ttlMs`و `cacheScope` بينما مقارنة الحمل المفيد للتطبيق. `futureHint` لأن هذا الحقل المجهول المفاهيمي اختفى.

لا تفترض أن كل فرق هو SDK الحالة هي جعل التحول مرئي. تحديد ما إذا كان مكونك هو نقطة نهاية التطبيق، والتي قد تتجاهل حقل إضافي، أو وسيط شفاف، والذي يجب أن يحافظ عليه.

إضغط على الفارق ضد كل SDK و النسخة التي ترسل. إذا اثنان SDKs أن تكون نفس النص المطبوع مختلفة، سياسة الإفراج يجب أن تقول أي سلوك مقبول بدلا من اختيار الخروج الأكثر ملاءمة بعد الحقيقة.

## التقاط أدلة وكالة

معظم الإنتاج MCP تحدث أخطاء في أكثر من عملية واحدة. سجّل ثلاث مشاهدات:

| المشاهدة | الحد الأدنى من الأدلة |
|---|---|
| الإدخال | طلبات الرؤوس، JSON-RPC جسم، نوع المحتوى، مسار مصادقة، وقت استلام |
| الأصل | الرأس والحشيش المنتقل، وضع الأصل، الرأس والحشيش المنتقل |
| إغريس | حالة مرئية للعميل، الرؤوس، الجسم، وقت إرسال |

يكتشف العينة اثنين من التحوّلات الشائعة:

- أصل HTTP 400 أو 404 JSON-RPC الخطأ يصبح وكيل عام
- الخروج JSON-RPC الهيئة تختلف عن الهيئة الأصلية

إضافة تصريحات محددة للتنفيذ لنوع المحتوى، `Accept`، الضغط ، على درجة الطلب SSE، رؤوس التخزين ، وتحقيق التواصل. TLS الإيقاف عندما تسمح السياسة، لا تسجيل الإثباتات فقط لإثبات المسار

## إعادة كتابة قبل أن تترك الأدلة الذاكرة

إعادة التدوين هو جزء من عمليات التوافق، وليس عمل تنظيف لاحقا. تطبيقها قبل التسلسل، التشويش، السجلات، أدوات الاختبار، أو تحميل الفشل.

يضع القياس العينية أسماء المفاتيح ويزيل المفصلات قبل التطابق، ثم يستبدل القيم بشكل متكرر تحت المفاتيح مثل: `Authorization`, `Cookie`, `Set-Cookie`, `X-Api-Key`, `accessToken`, `clientSecret`, `registrationAccessToken`, `token`, `password`, `secret`و `api_key`يجب أن تستخدم الشكل نفسه camelCaseلا يمكن أن تتجاوز التغيرات المختصرة، المختصرة، والمتميزة، والمتقطعة سياسة بعضها البعض. يجب على جمع الإنتاج إضافة سياسة الحجج الخاصة بالطرق، لأن مفتاح غير ضار مثل `query` لا يزال يمكن أن يحتوي على بيانات شخصية أو تنظيمية.

قم بتحديد مجموعة الأدلة المحذوفة. احتفظ بالقطعات الخامة فقط في نظام مصرح به قصير العمر عندما يتطلب ذلك تحقيق محدد. يثبت التمريض التي دفعت إلى اتخاذ القرار؛ فإنه لا يكشف عن القيمة المزودة.

## اجعل الصحة والرجوع جزءا من البوابة

إن الامتثال للبروتوكول ضروري ولكن ليس كافياً للتسريع. لا يزال المرشح المتوافق يمكن أن يخرج الوقت أو يسرق الذاكرة أو يفرض عبءًا زائدًا على الإعتماد.

تحديد نافذة صحية قبل الإطلاق:

- الحد الأدنى من العينات
- معدل الخطأ القصوى
- الحد الأقصى لعدد المئات
- حدود الاكتفاء أو الموارد
- مدة المراقبة
- مقارنة مع خط أساسية مسموح بها

تحديد دليل التردد قبل التنفيذ أيضاً:

- النسخة السابقة بالضبط
- إضافة دليل القبول
- SHA-256 أدوات الأثرية و أدوات تصفية
- حالة السجل الحالية
- النتيجة الصحية الحالية
- إجراء استعادة الطريق
- شهادة على تلك الحقول الدقيقة من هوية مراقب الإفراج الموثوق بها

تطلب أن يتم التحقق من هدف إعادة التدريب والصحة قبل الترقية، وليس فقط بعد فشل المرشح. الإصدار الناجح دون مسار استعادة قابلة للاستخدام ليس جاهزاً للإنتاج.

إذا فشل المرشح وفقًا لهذه الأدلة، فاعمل على إيقاف حركة المرور بدلاً من التخمين.

لا تقلل من الاستعداد للتحقق من الصدق مثل النسخة غير الفارغة، `healthy: "yes"`أو سلسلة أدلة تعسفية. SHA-256 المخطوطات، وقائم موثوق به، وموثوق HMAC-SHA-256 شهادة على كامل الحمل المفيد التردد. مفتاح التجربة الحتمي هو جهاز غير السري. حقن مفتاح محمي، KMS نتيجة التحقق أو مؤكد التحقق من المفتاح العام عند الحد الإفصالي في الإنتاج.

بوابة الإفراج أيضاً ترفض النسخة الفارغة SDK كل مصدر يجب أن يحمل إضافة دليل صحيحة. نافذة صحية خضراء لا يمكن أن تملأ حدود لم يتم ملاحظتها أبدا.

```bash
cd phases/13-tools-and-protocols/31-mcp-conformance-versioning-and-operations

```

تمتلك الاكتشاف خمسة عشر نسخة ذهبية سلبية، بما في ذلك نتائج الانتهاء صالحة ومخطئة، وتقارن النتيجة الخام مع SDK يرى، يفتش وكيل الذي انهار خطأ من أصل، يقيّم الصحة، يصدق الأدلة الاحتمالية، ويحدد هذا الهدف.

الشكل المتوقع:

```json
{
  "transcriptsPassed": 15,
  "transcriptsTotal": 15,
  "sdkDroppedFields": ["futureHint"],
  "proxyIssues": [
    "proxy collapsed a protocol error into HTTP 500",
    "proxy changed the origin JSON-RPC body"
  ],
  "releaseAction": "rollback",
  "evidenceDigest": "..."
}
```

اقرأ `code/main.py` في هذا الترتيب:

1. `validate_request()` يفرض طلباً محدداً في العصر وقواعد العنوان.
2. `validate_result()` يفرق بين المتميزين القديمة المفقودة والقيم الحديثة القائمة والمتوسعات والقيم غير المعروفة.
3. `select_era()` تنفذ سياسة صارمة ومحدودة للرد على التداعيات.
4. `run_transcript()` يُقيّم الدرجات الذهبية والسلبية.
5. `compare_sdk_view()` يظهر اختلافات التطبيع.
6. `inspect_proxy()` يُقارن الدخول والصعود والخروج
7. `redact()` يزيل الأسرار الواضحة قبل إختراق الأدلة
8. `rollback_evidence_ready()` يصدق حقول الحبرة الدقيقة وشهادة الإفراج الموثوق بها.
9. `ReleaseGate.evaluate()` يضم التوافق غير الفارغ، SDK، وكيل، الصحة، والدليل على التراجع

## استخدمها

أطلق الحزام في أربع نقاط:

1. في كل تغيير تنفيذي مع مُعدّل اختبار في العملية.
2. ضد المشترك المُبني والخادم الثنائي على النقل الحقيقي
3. عبر النظام الأساسي أو البوابة المستخدمة في بيئة التنسيق.
4. أثناء إطلاق القناريات مع صحة حية و أدلة إعادة التدفق

حافظ على نفس الأسماء المستقرة على جميع الطبقات `negative-header-body-mismatch` يجب أن يعني نفس الثابتة في تقارير الوحدة، من نهاية إلى نهاية، وكالة وكالة الأمن. سوف تختلف هضم الأدلة لأن الحدود قد تغيرت؛ لا يجب أن يكون هذا الطلب.

تخزين مخططات الإصدارات في التحكم في الإصدارات تخزين أدلة تشغيل محذورة في نظام الإصدار تخزين التقاطات الخام قصيرة الأجل فقط تحت التحكم في الوصول إلى الحوادث

النتيجة الأولى تحافظ على `futureHint`.الثاني يرفض لأن عامل التمييز في دورة الحياة غير معروف.

### المختبر (ج): فحص SDK التحويل

قرر ما إذا كان المكون الخاص بك يمكن تجاهله `futureHint` أو يجب أن يتم إرسالها. اكتب هذا الخيار في سياسة الإفراج. لا تمحى بشكل صامت الفرق.

### المختبر D: إصلاح الوكيل

تعديل تبادل التجربة حتى يحتفظ الخروج بحالة الأصل والجسم `python3 main.py` يجب أن تختفي مشكلات الوكالة، لكن SDK التفاضل لا يزال يمنع الترويج. ثم تشمل `futureHint` في SDK النظر والملاحظة التغيير في العمل `promote` عندما يمر كل دليل

## تحقق من ذلك

إشغال مجموعة التجربة والتحديد:

```bash
cd phases/13-tools-and-protocols/31-mcp-conformance-versioning-and-operations
python3 code/main.py
python3 -m unittest discover -s code/tests -v
```

يجب أن تثبت التحقق:

- كل نسخة ذهبية و سلبية تضمنت يصل إلى النتيجة المتوقعة
- الطلبات الحديثة تتطلب مفاتيح البيانات المعدة المعدة بالأسماء بالضبط
- HTTP أسماء العناوين متطابقة غير حساسة للحالة ومدفوعة `Mcp-Name` يتم فك القيم بالضبط
- عدم مطابقة الرأس والجسم يعيد رمز عدم مطابقة الحديث
- نسخة الاستجابة ID، حصرية النتيجة أو الخطأ ، شكل الخطأ ، و HTTP يتم التحقق من التحقق من الخرائط
- يتم تطبيق متطلبات قائمة الأدوات الخاصة بالطرق والمهام والحموم المفيدة لإكمالها
- كل ما يُلاحظ `HeaderMismatch` يتطلب HTTP 400 JSON-RPC `-32020` ردود فعل
- خام `Mcp-Name` يتم رفض الفضاء الأبيض أثناء رحلات ذهاب وإياب الفضاء الأبيض المشفّر بالرسالة
- مفقود `resultType` صالح فقط في عصر التراث المحدد
- الحقول الإضافية تتجاوز التحقق الخام بينما تفشل أنواع النتائج غير المعروفة
- أنواع النتائج التوسعية تتطلب قدرةها المعلنة
- الأخطاء الحديثة المعترف بها لا تسبب أبداً إعاقات التراث
- الإخطارات لا تنتج JSON-RPC ردود فعل
- SDK يتم التمييز بين إزالة الحسابات وخسارة الحقل التفسيري
- يتم الكشف عن انهيار خطأ النظام الأساسي وتحذير الإثباتات بشكل متكرر عبر camelCase وفرق الفصل
- الترويج يتطلب نسخة غير فارغة، SDK، وكيل، والدليل التشغيلي الصحي
- الترويج والإعادة التأهيل يتطلبان هدفًا مصحّحًا ومُثبتًا ونشطًا وصحيحًا للإعادة التأهيل

## أساليب فشل الإنتاج

| الفشل | ما تقرير الاختبار الضعيف | ما يجب أن يثبته الحزام |
|---|---|---|
| SDK يجمع المُتمييز المفقود | أدوات/قائمة تم تمريرها | النتيجة الحديثة الخام كانت لا تصل `resultType` و غير صالحة |
| خيارات التراجع بعد `-32021` | جربة إعادة التراث عملت | الخطأ المعترف به في الوقت الحاضر يحظر الانحراف |
| نوع النتيجة غير معروفة المعالجة ككامل | الرد تحليل | يتم رفض تمييز دورة الحياة غير المعلنة |
| الوكيل يسمح بأداة واحدة و الأصل يقوم بتنفيذ آخر | طلب وصل إلى الخادم | `Mcp-Name` يساوي اسم الجسم في كل قفزة |
| القيادة قبل قراءة استجابة الخادم | تمت اختبار عدم مطابقة الرأس | HTTP 400 and JSON-RPC `-32020` يتم تسجيل الاستجابة وتصديقها |
| الوكالة تحول 400 من أصل إلى 500 عام | خطأ فوق التيار | وضع الأصل والخروج JSON-RPC يتم الحفاظ على الجثث |
| إصدارات البرمجيات المتوسطة للإخطار `{result: null}` | لم يعيد المدير أي شيء | الجثة النهائية هي فارغة ولا يوجد JSON-RPC وجود رد فعل |
| SDK يزيل حقل إضافي | متطابقة الأشياء المميزة | الرؤية الخامة والطبيعية تظهر الحقل المفقود بالضبط |
| الفشل الأثاث تسرب رمز حامل | حزمة إزالة التحذير تم تحميلها | حدث إعادة التحرير قبل التشغيل أو تسجيل الحسابات أو تحميلها |
| أسلوب مفتاح الإئتمان يتجاوز تحرير | denylist يحتوي على api_key | CamelCase وتشاطر المتغيرات المفصلة شكلًا واحدًا من أشكال دينيل القنوني |
| لا يوجد لدى القناري عينات ولكنه يبدو صحياً | صفر الأخطاء | يتم فرض الحد الأدنى لعدد العينات |
| الـ Rollback يختار إعداد غير معروف | تعيد التنفيذ السابق | نسخة الهدف، إضافة القبول، الرموز، الحالة، والصحة موجودة |
