# A2A بروتوكول وكيل إلى وكيل

> MCP هو وكيل إلى أداة. A2A (Agent2Agent) هو بروتوكول مفتوح للسماح للعملاء غير المرونة المبنين على أطر مختلفة بالتعاون. أصدرتها جوجل في أبريل 2025 ، والتي تُتبرع بمنح Linux المؤسسة في يونيو 2025، والتي تصل إلى v1.0 في أبريل 2026 مع 150 + مؤيدين بما في ذلك AWS، سيسكو ، مايكروسوفت ، سيلزفورس SAPو ServiceNow. لقد استوعبت IBM- نعم ACP وأضاف AP2 هذه الدروس تتناول بطاقة العميل، دورة حياة المهمة، والترابطين النقلين

**Type:** Build
**Languages:** Python (stdlib, Agent Card + Task harness)
**Prerequisites:** Phase 13 · 06 (MCP fundamentals), Phase 13 · 08 (MCP client)
**Time:** ~75 minutes

## أهداف التعلم

- التمييز بين العامل إلى الأداة (MCP) من وكيل إلى وكيل (A2A) حالات الاستخدام.
- نشر بطاقة العميل في `/.well-known/agent.json` مع المهارات و البيانات المعدنية النهائية.
- إرسال دورة حياة المهمة (المقدم → العمل → مطلوب المدخل → اكتمل / فشل / إلغاء / رفض).
- استخدم رسائل مع الأجزاء (النص، الملف، البيانات) والقطع الأثرية كمخرجات.

## المشكلة

وكيل خدمة العملاء يحتاج إلى تفويض كتابة التقرير إلى وكيل كاتب متخصص.A2A:

- العرف REST API. يعمل ولكن كل زوجة واحدة
- قاعدة شفرة مشتركة تتطلب من العملاء أن يستخدموا نفس الإطار
- MCP. لا يناسب: MCP هو للدعوة إلى أدوات، وليس لعاملين يتعاونونون مع الحفاظ على التفكير الداخلي غير الشفاف لكل عامل.

A2A يملأ الفجوة. إنه يقلد التفاعل عندما يرسل وكيل واحد مهمة إلى آخر ، مع دورة حياة ، رسائل ، والقطع الأثرية. تبقى الحالة الداخلية للوكيل المطلقة غير واضحة  يرى المتصل فقط عمليات انتقال حالة المهمة والمخرجات النهائية.

A2A هو بروتوكول "دع العاملين عبر الإطار يتحدثون مع بعضهم البعض". MCP؛ هذان الإثنان يكملان بعضهما البعض.

## المفهوم

### وكيل بطاقة

كلّ شخص A2A-compliant وكيل ينشر بطاقة في `/.well-known/agent.json`:

```json
{
  "schemaVersion": "1.0",
  "name": "research-agent",
  "description": "Summarizes academic papers and drafts citations.",
  "url": "https://research.example.com/a2a",
  "version": "1.2.0",
  "skills": [
    {
      "id": "summarize_paper",
      "name": "Summarize a paper",
      "description": "Read a paper PDF and produce a 3-paragraph summary.",
      "inputModes": ["text", "file"],
      "outputModes": ["text", "artifact"]
    }
  ],
  "capabilities": {"streaming": true, "pushNotifications": true}
}
```

اكتشاف هو URL-basedاحضر البطاقة، تعلم URL من A2A نقطة نهاية، إدراج المهارات.

### بطاقات العميل الموقعة (AP2)

المُسَمِع AP2 إضافة توقيعات رمزية إلى بطاقات وكيل. JWTيُحقق المستهلكون. يمنع التمثيل.

### دورة حياة المهمة

```
submitted -> working -> completed | failed | canceled | rejected
             -> input_required -> working (loop via message)
```

العملاء يبدأون مع `tasks/send`. العميل المُتصل ينتقل عبر الدول . العملاء يشتركون في تحديثات الدولة عبر SSE أو استطلاع.

### الرسائل والأجزاء

رسالة تحمل واحدة أو أكثر من الأجزاء:

- `text` محتوى واضح
- `file` — base64 بُلب مع mimeType.
- `data` المخطوطة JSON الحمل المفيد (المدخول المهيكلي للوكيل المشارك).

مثال:

```json
{
  "role": "user",
  "parts": [
    {"type": "text", "text": "Summarize this paper."},
    {"type": "file", "file": {"name": "paper.pdf", "mimeType": "application/pdf", "bytes": "..."}},
    {"type": "data", "data": {"targetLength": "3 paragraphs"}}
  ]
}
```

### الأثاث

المخرجات هي الأثاث، وليس السلاسل الخام. الأثاث هو المخرج المسمى، المخطط:

```json
{
  "name": "summary",
  "parts": [{"type": "text", "text": "..."}],
  "mimeType": "text/markdown"
}
```

يمكن نشر الأثاث كجزء من الكائنات

### إرتباطان في النقل

1. **JSON-RPC على HTTP.** `/a2a` نقطة النهاية POST للطلبات، اختياري SSE للتدفق، التزامن الافتراضي
2. **gRPC.** لبيئات المؤسسات حيث gRPC هو محلي

كلتا الارتباطات تحمل نفس شكل الرسالة المنطقية.

### الحفاظ على الكفاءة

مبدأ تصميم رئيسي: الحالة الداخلية للعميل المطلوب غير واضحة. يرى المدعو حالة المهمة والقطع الأثرية. سلسلة الفكر للعميل المطلوب، ودعوات أدائه، وفوضته الفرعية للعميل  غير مرئية. هذا يختلف عن MCPحيث تكون المكالمات الشفافة

الأسباب: A2A يسمح للمنافسين بالتعاون دون الكشف عن المعلومات الداخلية. A2A يمكن أن يكون "تصل بعامل خدمة العملاء" دون أن يتعلم المتصل كيف يقوم هذا العامل بتنفيذ الخدمة.

### العلاقة مع MCP

| الأبعاد | MCP | A2A |
|-----------|-----|-----|
| حالة الاستخدام | وكيل إلى أداة | عميل إلى عميل |
| التفتيش | دعوات أداة شفافة | التفكير الداخلي غير الواضح |
| المتصلين المعتادين | -معاينة وقت التشغيل | عميل آخر |
| الدولة | نتيجة دعوة الأداة | المهمة مع دورة الحياة |
| الإذن | OAuth 2.1 (المرحلة 13 · 16) | JWT-signed وكيل بطاقات (AP2) |
| النقل | ستديو / قابل للتسجيل HTTP | JSON-RPC على HTTP / gRPC |

الاستخدام MCP عندما تريد استدعاء أداة محددة. A2A عندما تريد تفويض مهمة كاملة إلى وكيل آخر. العديد من أنظمة الإنتاج تستخدم كلتا: وكيل يستخدم MCP لطبقة الأدوات الخاصة بها A2A لطبقة التعاون

## استخدمها

`code/main.py` تنفيذ الحد الأدنى A2A يُنشر وكيل البحث بطاقته، ويقبل وكيل الكتاب `tasks/send` مع قطع تشمل: PDF وتقوم بإعادة إصدار النص النصي، وتقوم بالانتقال من خلال العمل → input_required → working → completed، وتعطي النص النصي. كل stdlib؛ يستخدم نقل في الذاكرة لتركيز على أشكال الرسائل.

ما الذي يجب أن ننظر إليه:

- وكيل بطاقة JSON الشكل
- تحديد الهوية المهام والتحولات الحكومية
- رسائل ذات أجزاء مختلطة
- الإدخال المطلوب في منتصف المهمة
- العودة الفنية عند الانتهاء.

## أرسله

هذا الدرس يُنتج `outputs/skill-a2a-agent-spec.md`. بالنظر إلى عميل جديد يجب أن يكون قابلاً للدعوة من قبل عملاء آخرين ، فإن المهارة تنتج بطاقة العميل JSON، مخطط مهارات، وخطط النهاية.

## التمارين

1. أركض `code/main.py`. تتبع دورة حياة المهمة بأكملها، بما في ذلك الموقف المطلوب من المدخلات عندما يطلب الوكيل المشارك توضيحا.

2. إضافة بطاقة وكيل موقعة وقع مع HMAC على بطاقة القنوني JSON. اكتب مؤكداً و تأكد أنه يفشل على بطاقة متحولة

3. تنفيذ تحرك المهام: وكيل الكتاب يبعث ثلاثة قطع متزايدة من الفن SSE ويتراكمهم المدعو

4. تصميم A2A وكيل الذي يلف MCP خادم، خريطة كل MCP أداة إلى A2A لاحظ التنازلات ما هو الضموضة المفقودة؟

5. اقرأ A2A v1.0 الإعلان وتحديد الميزة الوحيدة التي لم يتم تنفيذها بعد من قبل أي إطار اعتبارا من أبريل 2026 (لمحة: يتعلق الأمر بتفويض مهام متعددة المكالمات).

## الشروط الرئيسية

| المدة | ما يقوله الناس | ما يعنيه هذا في الواقع |
|------|----------------|------------------------|
| A2A | "بروتوكول وكيل إلى وكيل" | بروتوكول مفتوح للتعاون مع الوكلاء غير الشفاف |
| وكيل بطاقة | "`.well-known/agent.json`" | البيانات المطبوعة التي تصف مهارات وكيل ومصادفه |
| المهارات | "وحدة قابلة للاتصال" | العملية المسمى التي يدعمها الوكيل (مماثلة MCP أداة) |
| المهمة | "وحدة التفويض" | قطعة عمل مع دورة حياة ومتحضرة نهائية |
| الرسالة | "مشاركة مهمة" | يحمل أجزاء (نص، ملف، بيانات) |
| الجزء | "مُنْسَخَةَ قطعة" | `text` / `file` / `data` عنصر رسالة |
| القطع الأثرية | "مخرج المهام" | المخرج المسمّى والمنشط المرجع عند الانتهاء |
| AP2 | "بروتوكول دفع وكلاء" | تمديد بطاقات العميل الموقعة للثقة والمدفوعات |
| التفتيش | "التعاون مع الصندوق الأسود" | معلومات العميل المُتصل مخفية من المُتصل |
| المطلوب في المدخل | "توقف مهمة" | حالة دورة الحياة عندما يحتاج الوكيل إلى مزيد من المعلومات |
