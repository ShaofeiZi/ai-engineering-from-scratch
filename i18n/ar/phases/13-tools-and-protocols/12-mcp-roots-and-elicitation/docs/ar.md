# نطاق واضح وتسجيل العزل

> الجذور قد تم إزالة MCP 2026-07-28 ولم تكن أبدا مربع الرمل الأمن. وضع نطاق في الحجج الأداة المرئية أو الموارد URIs، وافق عليه على الخادم ، واستخدم MRTR عندما تحتاج أداة إلى مدخلات المستخدم حقاً. يرى المستخدم القرار، ويرى النموذج المقبض، ويمكن لأي مثال من خادم معالجة المحاولة مرة أخرى.

**Type:** Build
**Languages:** Python
**Prerequisites:** Phase 13 · 07 (MCP server), Phase 13 · 11 (stateless MRTR)
**Time:** ~60 minutes

## أهداف التعلم

- استبدال الجذور القديمة مع معايير مساحة العمل الصريحة، الموارد URIsأو تكوين الخادم
- إشارات مختلفة من الإذن، وتحديد المسار، وتعبئة النظام التشغيلي.
- وضع النموذج `elicitation/create` من خلال MRTR `input_required` النتيجة
- إعلان دعم الإجراءات في إمكانات العميل حسب الطلب ورفض أنماط غير المدعومة.
- التحقق من الصلاحية `accept`, `decline`و `cancel` نتيجة واضحة
- ربط التأكيد المدمر بالرئيسي الموثق والحجج الأصلية ومجموعة المرشحين والانهيار.

## مشاكل متشابهة

أداة ملاحظات تتلقى هذا الطلب: "حذف القائمة القديمة TPS تقرير"

يجب على الخادم الإجابة على سؤالين مختلفين

1. أي مساحة عمل يمكن أن تلمس هذه العملية؟
2. أي من النصوص الثلاث المتناسبة قصدها المستخدم؟

الأول هو النطاق والإذن. الثاني هو التباين التفاعلي. يسبب خلطهم تصميمات خطيرة، مثل التعامل مع مجلد يقدمه العميل كدليل على أن المدعو قد يقوم بحذف كل شيء بداخله.

## الجذور هي سطح الهجرة

في وقت سابق MCP تمكن العميل من الإعلان عن الجذور وإعلام الخادم عندما تغير القائمة. كانت الجذور توجيهات معلومية. لم تقيد ما يمكن لعملية الخادم قراءته ، ولم تسمح للمدعو ، ولم تخلق صندوق رمل للنظام التشغيلي.

MCP 2026-07-28 تعليقات `roots/list` و `notifications/roots/list_changed` في تصاميم جديدة، تفضل إحدى هذه الاستبدالات الصريحة:

- A `workspaceUri` أو `directory` حجة الأداة عندما يتغير نطاق المكالمة لكل مكالمة.
- مصدر URI عندما تستهدف العملية بالفعل مصدر.
- تكوين الخادم عندما يمتلك تنفيذ واحد مساحة عمل ثابتة واحدة.
- صندوق رمل العملية أو نظام ملفات محبوس عندما يكون الكود لا يمكن الهرب منه تقنيا.

إذا كان هناك حاجة لا تزال إلى تكامل موجود في 2026-07-28 `roots/list` خلال نافذة التخلف ، يقوم الخادم بإدخاله في MRTR `inputRequests`. لا يجب أن ترسل طلبًا عكسياً مباشراً. هذا هو مُعدل الهجرة؛ يجب على المُعاملين الجدد أن يقبلوا نطاقًا صريحًا بدلاً من ذلك.

يمكن أن يرى النموذج ويعيد التدخل الصريح. يسهل فحص المجال الخفية للانتقال من أجل جلسة التنقل، وإعادة تشغيلها، والتحقق، والمسار.

### قاعدة ثلاث طبقات

-أحد المواصفات URI لا يزال لا يسمح لنفسه.

1. **الإذن:** هل يسمح لهذا المدير الموثق باستخدام هذا المجال؟
2. **الحبس:** هل الهدف المعادية URI البقاء داخل حدود المجال المسموح به للعمل؟
3. **صندوق الرمل:** هل يمكن أن يمنع النظام التشغيلي خادم مُعرض للخطر من الهروب على أي حال؟

الخادم القابل للتشغيل يحافظ على قائمة الإذن بمساحة العمل المسموح بها URIs، يُعادِل المسارات المُشفّرة بنسبة مئوية، يُحقق من حدود المكون الحقيقي للمسار، ويعيد التحقق من الحفاظ على السيطرة مباشرةً قبل الحذف.

التحقق من مخطوطات السطر البديلة خاطئة:

```text
allowed:   file:///work/notes
attacker:  file:///work/notes-evil/secret.md
traversal: file:///work/notes/%2e%2e/private.md
```

تبدأ كل من المسارات العدائية بخطط مضلل. عادي أولاً ، ثم مقارنة مكونات المسار. يجب على خادم نظام الملفات الإنتاج أيضًا الدفاع عن سباقات الرمزية والمسار المحدد للمنصة.

## لا يزال هناك طلب، لكن التسليم قد تغير

الإجراء هو ميزة العميل الحالية لجمع المدخلات المستخدمة خلال `tools/call`, `prompts/get`أو `resources/read`. اسم الطريقة يبقى `elicitation/create`ما تغير هو اتجاه تدفق الأسلاك

خادم 2026-07-28 لا يرسل العكس JSON-RPC طلب. يعيد `InputRequiredResult`:

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "resultType": "input_required",
    "inputRequests": {
      "delete_choice": {
        "method": "elicitation/create",
        "params": {
          "mode": "form",
          "message": "Choose one matching note and confirm deletion.",
          "requestedSchema": {
            "type": "object",
            "properties": {
              "note_id": {
                "type": "string",
                "enum": ["note-3", "note-7", "note-14"]
              },
              "confirm": {"type": "boolean"}
            },
            "required": ["note_id", "confirm"]
          }
        }
      }
    },
    "requestState": "integrity-protected-delete-state"
  }
}
```

المضيف يعيد إعادة تشغيله. يمكن للمستخدم قبوله أو رفضه صراحة أو رفضه. ثم يحاول العميل إعادة تشغيله الأصلي `tools/call` مع هوية جديدة:

```json
{
  "jsonrpc": "2.0",
  "id": 2,
  "method": "tools/call",
  "params": {
    "name": "notes_delete",
    "arguments": {
      "workspaceUri": "file:///Users/alice/Documents/Notes",
      "title": "TPS report"
    },
    "inputResponses": {
      "delete_choice": {
        "action": "accept",
        "content": {"note_id": "note-14", "confirm": true}
      }
    },
    "requestState": "integrity-protected-delete-state",
    "_meta": {
      "io.modelcontextprotocol/protocolVersion": "2026-07-28",
      "io.modelcontextprotocol/clientCapabilities": {
        "elicitation": {"form": {}}
      }
    }
  }
}
```

لا يوجد جلسة بروتوكول بين المكالمتين. يقوم الخادم بتحقق من حالة الصوت، وتؤكد من الاستجابة ضد النموذج المتوقع، وتحقق من أن الملاحظة المختارة كانت في مجموعة المرشحين الموقعة، وإعادة تفويض مساحة العمل، وإعادة التحقق من الحفاظ عليها، ثم حذف.

## التفاوض على القدرة هو حسب الطلب

العميل الذي يدعم استدعاء وضع النموذج يعلن:

```json
{
  "io.modelcontextprotocol/clientCapabilities": {
    "elicitation": {"form": {}}
  }
}
```

قدرة هباء فارغة `"elicitation": {}`لا يزال هذا يعادل دعم للاتفاقية فقط على شكل `"elicitation": {"form": {}}` يدعم أيضا وضع النموذج. URL-only الإعلان `"elicitation": {"url": {}}`لا يجب على الخادم إدراج وضع غائب من قدرات الطلب الحالي، حتى لو كان طلب سابق يعلن عنه.

كل طلب يحمل أيضا `io.modelcontextprotocol/protocolVersion`. إصدار مفقود أو غير سلسلة يعود `-32602`. تعود سلسلة غير مدعومة `-32022` مع دقة `supported` و `requested` البيانات المفقودة أو URL-only إرجاع دعم الطلب `-32021` مع `data.requiredCapabilities` المحددة إلى `{"elicitation":{"form":{}}}`.

غلاف بدون JSON-RPC `id` هو إشعار. JSON-RPC رد فعل النجاح أو الخطأ. على المباشر HTTP، تتلقى إشعار مقبول `202 Accepted` بدون جثة

`clientInfo` يجب أن يتم تضمينها للتشخيص، ولكنها ذاتية الإبلاغ ولا يمكن تحديد المستخدم للحصول على الموافقة.

الخادم ينفذ `server/discover` والعائدات `supportedVersions`، القدرات `ttlMs`و `cacheScope` مع `resultType: "complete"`. لا تشعل عن هذا التصميم الحديث الجذري. لأنه يعلن عن الأدوات، فإنه ينفذ أيضا إلزامية `tools/list`هذا النتيجة تعيد التحدد `notes_delete` وصف، كائن صالح `inputSchema`، بيانات الهوية الخادم، وتلميحات التخزين العام.

## وضع الشكل

وضع النموذج يستخدم مقيد JSON مخطط مصمم لمحادثات قابلة للاستخدام. الجذر هو كائن وخصائصه هي حقول بدائية مسطحة أو صفوف enum مدعومة. لا تنتمي الأشياء المتداخلة بعمق ومخططات الوثائق العامة إلى حوار التأكيد.

استخدام وضع النموذج ل:

- اختيار واحد من العديد من المرشحين
- تأكيد عملية مدمرة؛
- جمع التفضيلات غير الحساسة
- جمع عدد صغير من القيم يجب على المستخدم، وليس النموذج، أن يقرر.

لا تستخدم وضع النموذج للكلمات المرور، API المفاتيح، رموز الوصول، أو أوراق اعتماد الدفع. MCP العميل ويمكن أن تصل إلى السجلات أو النموذج السياق.

يقوم الخادم بتؤكيد المحتوى المرجع مرة أخرى. تحسن التؤكيد من النموذج من جانب العميل UX لكن لا يخلق الثقة

## URL الوضع

URL وضع يرسل شبكة آمنة URL للتفاعل خارج النطاق:

```json
{
  "method": "elicitation/create",
  "params": {
    "mode": "url",
    "message": "Connect the report service to continue.",
    "url": "https://mcp.example.com/connect/report-service"
  }
}
```

استخدمها عندما يجب أن تذهب المعلومات الحساسة مباشرة إلى تدفق الويب الذي يسيطر عليه الخادم، مثل إذن طرف ثالث. يظهر العميل الوجهة الكاملة ويستلم موافقته قبل فتحها. URL.

(إنجليزية) `accept` الإجابة تعني أن المستخدم وافق على فتح URL. لا يثبت أن التدفق الخارجي قد اكتمل. عند محاولة أخرى، يقوم الخادم بتحقق حالة خاصة به وإما أنه يكتمل أو يعيد آخر `input_required` النتيجة

URL لا يمكن أن يكون الإجراءات التي تمتد لاستبدال الإجراءات التي تمتد بين MCP العميل و MCP هو للتفاعل الخارجي MCP يجب أن يقوم الخادم بإجراءات نيابة عن المستخدم. يجب على الخادم ربط مستخدم المتصفح بنفس المبدأ المصادق الذي بدأ MCP العملية

## فروع الاستجابة

تعامل الإجراءات كقرارات منتجات وليس كـ"تلقيحات":

| الإجراءات | المعنى | سلوك الخادم الآمن |
|--------|---------|----------------------|
| `accept` | قدمت المستخدم التفاعل | تصحيح المحتوى واستمر |
| `decline` | رفض المستخدم صراحة | أعد نتيجة رفض كاملة لا يوجد فيها خطأ |
| `cancel` | مستخدم رفض أو لم يتمكن من الانتهاء | توقف بأمان وافق على محاولة أخرى لاحقا |

لا تفسير المحتوى المفقود كإذن، ولا تحويل الرفض إلى حلقة استمرارية.

## حماية المدمرة MRTR الدولة

قائمة المرشحين لا يمكن أن تكون موجودة فقط في المكالمة أو غير الموقعة Base64 العميل يسيطر على كل شيء يرسل

الدرس يُوقع على حمولة دولية تحتوي على:

- الرئيسي الموثوق به
- طريقة الأصل
- هضم `workspaceUri` و `title`;
- أرقام الملاحظات المسموح بها التي تظهر في النموذج
- مرحلة التشغيل
- انتهاء الصلاحية قصير

قبل الطفرة، يفتقد الخادم أيضًا سجل الملاحظة الحية. هذا يلتقط سباقات الحذف والهدف الذي انتقل خارج مساحة العمل بعد عرض النموذج.

في حالة إجراء مالي أو لا رجعة فيه مرة واحدة، HMAC لا تمنع الحالة الصحيحة من تمثيلها خلال انتهاء صلاحيتها. تخزين وتستهلك غير واحد بالضبط مرة واحدة في متجر التشغيل المشترك مع كل حالة المعاملة. TTL-pruned تخزين وتحتفظ بمطالبة الذرية أثناء إجراء حذف في الذاكرة. يجب أن تربط قاعدة بيانات الإنتاج المطالبة غير المطلوبة والطفرة في معاملة واحدة أو حدود كتابة مشروطة معادلة.

تأكيد التفاعل قبل المطالبة بالدفع. `cancel` لا يؤدي أي طفرة و يترك الحالة قابلة للتحرك حتى انتهاء صلاحيتها `decline` هو نهائي، لذلك الدروس تستهلك غير المفردة دون حذف أي شيء.

## بناءها

`code/main.py` يظهر أن `notes_delete` الوسيلة:

- `tools/list` يعيد وصف تحديدي، قابلا للتخفيض مع مساحة العمل المطلوبة ونظام العنوان.
- النطاق هو صريح `workspaceUri` -أحاديث
- تكوين الخادم يسمح بذلك المجال للعمل للمعلم.
- URI التطبيع يرفض الخلط من المواضيع المسبقة والتحول المشفر.
- كل حذف مدمر يتطلب إثارة وضع الشكل
- الجهاز السريع يسافر إلى الداخل `resultType: "input_required"`.
- توقيع `requestState` يربط قائمة المرشحين الدقيقة والحجج الأصلية.
- متجر إعادة التشغيل المحقق يرفض نفس الحالة المقبولة أو المقبولة عبر حالات الخادم.
- تستخدم المحاولة الجديدة هوية الطلبات وتعود `resultType: "complete"`.

مخزن البيانات في الذاكرة لذلك سلوك البروتوكول سهل للتفتيش. قواعد الأمن تظل نفسها مع قاعدة البيانات.

## استخدمها

من جذور المخبأ:

```bash
cd phases/13-tools-and-protocols/12-mcp-roots-and-elicitation/code
python3 main.py
python3 -m unittest discover tests -v
```

نقاط التفتيش المتوقعة:

- "ديسكفري" تعلن عن أدوات بدون "جذر".
- تعود أداة اكتشاف `notes_delete` مع `resultType`، هوية الخادم ، وتلميحات التخزين
- رقم طلب `1` يعيد النموذج في `inputRequests.delete_choice`.
- رقم طلب `2` يردد الحالة الموقعة ويؤدي إلى إزالة.
- مسار المُقبل ومسار التقاطع المشفرين فشلوا في الحفاظ عليه.
- لا يمكن لإعادة استخدام العنوان المتغير حالة التأكيد الأصلية.
- إن تراجع يترك النقش غير متغير
- لا يمكن لمتلكين كائنات الخادم المشتركة في حالة ملاحظة وإعادة تشغيل تنفيذ تأكيد واحد.
- الإعلانات الفارغة والصريحة تعمل، بينما URL-only إرجاع الدعم دقيق `-32021` متطلبات الشكل.
- أخطاء الإصدار غير المدعومة تستخدم `-32022` شكل البيانات
- إشعار بدون هوية يُنتج لا JSON-RPC رد فعل

## التمارين

1. استبدل متجر إعادة التلفزيون في الذاكرة SQLite. استخدم معاملة واحدة للمطالبة بالبيانات والحذف من الملاحظة، ثم إثبات أن عمليتين لا يمكن أن تتعهد.
2. إضافة `url` التفاوض على القدرة وتدفق إعداد خارج النطاق. `inputResponses`.
3. استبدل خريطة الملاحظات في الذاكرة بخريطة مؤقتة SQLite قاعدة البيانات، إعادة التحقق من الإذن والاحتواء داخل معاملة الطفرات
4. إضافة سياسة الرمزية لترابط تنفيذ نظام الملفات الحقيقي. شرح لماذا URI لا يمكن أن يمنع الحبس اللكسيكي وحده الهروب من الرابط التواصل.
5. تصميم مُكيف 2025-11-25 الذي يُخترط الحديث MRTR خروجه من المعامل إلى الإجراءات التي يبدأها الخادم القديم. أبقيه بعيدًا عن المعامل الحالي.
