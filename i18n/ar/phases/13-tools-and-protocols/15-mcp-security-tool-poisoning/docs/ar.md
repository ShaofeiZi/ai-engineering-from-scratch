# MCP الأمن: البيانات المتحفّرة، التوجيه، MRTR الدولة

> لا يعني أنّه لا يُمكنك الثقة، بل يعني أنّ كلّ طلب يُعرض الأدلة التي يحتاجها الخادم والبوابة للتحقق من المكالمة بشكل مستقل.

**Type:** Learn
**Languages:** Python
**Prerequisites:** Phase 13 · 07 (MCP server), Phase 13 · 08 (MCP client)
**Time:** ~60 minutes

## أهداف التعلم

- تعامل وصف الأدوات، وتعليقات، ومعلومات العميل، ومعلومات الخادم كبيانات غير موثوق بها.
- اكتشاف التسمم البيانات المعدنية وتغييرات المصطلحات والتصادم بين أسماء الخادم.
- تأكييد بيانات الميتاءات الطلب 2026-07-28 و Streamable HTTP الرؤوس التوجيه
- الحماية MRTR `requestState` ضد التلاعب والربط بالتحديد بالثباتات
- تطبيق الحدود السموحة والسعر على الرئيسي، وليس جلسة بروتوكول إزالتها.

## المشكلة

يقرأ نموذج وصف الأداة لتحديد ما يجب الاتصال به. يقرأ جهاز توجيه أسماء الأداة لتحديد أين يرسل طلبًا. يقرأ المستخدم علامات لتحديد ما يجب الموافقة عليه. يمكن أن يستهدف وصفًا ضارًا واحدًا الثلاثة.

المسؤول MCP توجيهات الأمن مباشرة: يجب التعامل مع التصفيات والإشارات كغير موثوق بها ما لم تأتي من خادم موثوق به. حتى في ذلك الحين، يمكن أن تتغير ثقة التنفيذ. تحديث الخادم، والحزمة المخططة، وأخطاء السجل، أو دمج البوابة يمكن أن يغير ما يراه النموذج.

البروتوكول الحالي يغير أيضا حدود الأمن. في 2026-07-28 لا توجد أي ضغط يد أساسي ولا جلسة نقل. تصميم أمن يضع مفاتيح الموافقة أو حدود السعر أو تاريخ المراجعة فقط من خلال `Mcp-Session-Id` ليس تصميماً حالياً

## المفهوم

### سبعة مناطق هجومية تستحق التحقق منها

استخدم قائمة ملموسة بدلاً من التعليمات الغامضة للحذر

1. **تسمم البيانات المعدنية** يحتوي وصف على تعليمات غير مرتبطة بالسلوك المعلن للأداة.
2. **سحب السجادة المصففة** تغييرات في الاسم أو الوصف أو النموذج أو التعليقات المعتمدة سابقاً.
3. **التظلّم عبر الخادم.** اثنين من الخلفيات تعرض نفس اسم الأداة غير المؤهلين والتوجه يختار واحد بصمت.
4. **إرتباط الرأس والجسم** `Mcp-Method` أو `Mcp-Name` لا يوافق مع JSON-RPC طلب
5. **تصاعد القدرات** يطالب أحد الأقران بميزة أو ميزة عميل والخادم يخطئ هذا الإعلان للحصول على إذن.
6. **MRTR التلاعب بالولاية** يتغير العميل `requestState`، يجيب على سؤال مختلف، أو يستخدم التأكيد مرة أخرى مع حجج مختلفة.
7. **خلط الهوية في سلسلة التوريد** يُعتبر اسم العرض المألوف دليل على هوية الناشر أو الخادم.

هذه السطحات تتداخل. تساعد التمزيق بالهاش في تغييرات المصفير ولكن لا يثبت أن المصفير الأول آمن. يلتقط المسح الحصري عبارات واضحة ولكن ليس تعليمات دقيقة. يمنع الفضاء الاسمي فئة واحدة من الصدام ولكن ليس خادمًا ضارًا يحتوي على مساحة أسماء. قم بتجميع التحكمات.

### الطلب الحالي هو دليل، وليس هوية

كل طلب في 2026-07-28 يحتوي على:

```json
{
  "_meta": {
    "io.modelcontextprotocol/protocolVersion": "2026-07-28",
    "io.modelcontextprotocol/clientCapabilities": {
      "elicitation": {"form": {}}
    },
    "io.modelcontextprotocol/clientInfo": {
      "name": "security-lab",
      "version": "1.0.0"
    }
  }
}
```

تأكيد النسخة وشكل القدرة على كل طلب. استخدم القدرات لتحديد شكل استجابة متوافق. لا تستخدم `clientInfo` كمدير مصادق. إنه مذكر بنفسه.

نفس التحذير ينطبق على `io.modelcontextprotocol/serverInfo` في بيانات النتيجة. انها مفيدة لسجلات وتحليل التحريفات. انها ليست شهادة، دليل السجل، أو قرار التأخيص.

### تأكيد التوجيه قبل التشريع

ل: `tools/call`, قابل للتدفق HTTP يتضمن:

```text
MCP-Protocol-Version: 2026-07-28
Mcp-Method: tools/call
Mcp-Name: notes.export
```

يجب أن تكون طريقة العنوان مساوية لطرق الجسم. يجب أن يكون اسم العنوان مساويا `params.name`- رفض الخلاف مع `-32020` قبل اختيار الخلفية، تطبيق RBACأو تستهلك رمزًا محددًا للأسعار

هذا التنظيم ينهي عدم وضوح شائع: أحد المكونات يسمح بالجسم بينما يتوجه آخر عن طريق الرأس.

التحقق من التحقق من الوصول عبر الأسلاك يتبع تسلسل واحد بالضبط. JSON-RPC وتقارن قيم العنوان مع الجسم ، ثم تحقق ما إذا كان الإصدار المماثل مدعومًا. يعود العنوان غير المماثل HTTP 400 with `-32020`إذا اتفق الرأس والجسم على نسخة غير مدعومة، أعيد HTTP 400 with `-32022` و `data` بالضبط `{"supported":["2026-07-28"],"requested":"<actual>"}`. طريقة مجهولة تعود HTTP 404 with `-32601`.

كل كائن خطأ يحتوي على اختياري `data` عندما يحتاج العقد إلى معلومات استرداد مهيكلة. `id`، لذلك لا تتلقى أبدا JSON-RPC رد النجاح أو الخطأ. HTTP الإخطار يعود 202 مع جسم فارغ.

### ضغط على كل وصف

تفتقر التوصيف الهاش وحده إلى تغييرات النظام والتعليقات. قم بتعريف وحش حقل وصف المستخدم المعتمدة:

```python
normalized = json.dumps(tool, sort_keys=True, separators=(",", ":"))
digest = hashlib.sha256(normalized.encode()).hexdigest()
```

تخزين المقال تحت مفتاح مؤهل مثل `notes.export`، مع دليل الناشر وقتا الموافقة خارج هذا مثال اللعبة.

في كل إطراء:

- مفتاح مجهول: الحجر الصحي حتى المراجعة.
- نفس المفتاح، مختلفة التهضم: الحجر الصحي كمساحة السجاد حتى يتم إعادة الموافقة عليها.
- اسم غير مؤهل مزدوج: يتطلب مساحة أسماء محددة.
- ضربة المسح: حظر ومراجعة المصف الكامل.

إنّ المساواة تثبت الاستقرار، وليس السلامة.

### المسح الدوري هو سلك ثلاثي

يمكن أن تكون النماذج البسيطة علامات على الأدوار، وتعديل التعليمات، والخفاء، والوصول السري، وجهات الشبكة المظلمة. CI.

لا يعدون دليلًا تعنييًا. يمكن أن يحتوي وصف آمن على عبارة معينة في تحذير مشروع. يمكن أن يتجنب وصفًا ضارًا كل عبارة. تعامل نتائج المسحون كدليل مراجعة ، وليس نتيجة براءة تلقائية.

### مساحة الأسماء قبل الاندماج

لنفترض أن خادمين يكتشفون كل منهما `search`لا تدع أمر الاكتشاف يقرر من يفوز

```text
notes.search
issues.search
```

الاسم المؤهل هو اسم البوابة العامة. سجل خرائط الخلفية بشكل منفصل. الأسماء الثابتة تصنع الموافقة، المراجعة، أدوات الاختبار، `Mcp-Name` التوجيه يشير إلى نفس الكائن.

### الإمكانيات هي إعلانات التوافق

حسب الطلب `clientCapabilities` يخبر الخادم عن البروتوكول الذي يمكن للعميل معالجته. لا يمنح العميل الوصول إلى الأدوات أو البيانات أو الإجراءات.

لا يزال التأذن يأتي من سياسة الأساسية والموارد الموثقة.

1. تحديد مصداقية النقل
2. تأكيد الإصدار والعناوين والشكل الطلب.
3. تحقق من توافق القدرة
4. أصدّق المبدأ، الأداة، الموارد، والحجج.
5. تنفيذ أو طلب إدخال المستخدم.

### حماية الفرد MRTR تأكيد

أداة متواصلة قد تحتاج إلى تأكيد المستخدم. MCP يستخدم طلبات رحلة متعددة بدلاً من استدعاءات الخادم إلى العميل.

ردّة أولى:

```json
{
  "resultType": "input_required",
  "inputRequests": {
    "confirm": {
      "method": "elicitation/create",
      "params": {
        "mode": "form",
        "message": "Export notes to archive?",
        "requestedSchema": {
          "type": "object",
          "properties": {
            "confirm": {"type": "boolean"}
          },
          "required": ["confirm"]
        }
      }
    }
  },
  "requestState": "opaque-integrity-protected-value"
}
```

العميل يحصل على المدخل ويعيد تجربة الطريقة الأصلية مع طريقة جديدة JSON-RPC المعلومات:

```json
{
  "jsonrpc": "2.0",
  "id": 2,
  "method": "tools/call",
  "params": {
    "name": "notes.export",
    "arguments": {"query": "private", "destination": "archive"},
    "requestState": "opaque-integrity-protected-value",
    "inputResponses": {
      "confirm": {
        "action": "accept",
        "content": {"confirm": true}
      }
    },
    "_meta": {
      "io.modelcontextprotocol/protocolVersion": "2026-07-28",
      "io.modelcontextprotocol/clientCapabilities": {
        "elicitation": {"form": {}}
      }
    }
  }
}
```

كل واحد `inputRequests` القيمة هي طلب شامل كامل مع `method` و `params`. يجب أن يطابق مفتاحها الإدخال المقابل في `inputResponses`. إثارة النموذج تستخدم جذور كائن `requestedSchema`و يجب أن يكون العميل قد أعلن قدرة إطلاق النموذج قبل أن يطلبها الخادم.

القدرة الحالية لديها إعلانات نموذج صالحة. `{"elicitation":{}}` يدعم بشكل ضمني الحصول على النوع، بينما `{"elicitation":{"form":{}}}` يذكر ذلك صراحة. URL-only الإعلان مثل `{"elicitation":{"url":{}}}` لا يدعم طلب النموذج. الخادم يعود HTTP 400 with `-32021` و `data.requiredCapabilities` مساوية `{"elicitation":{"form":{}}}`.

العلاج `requestState` إدخال عدائي. وقع أو تشفيرها، وتؤكيدها، وتربطها على طريقة، الأداة، الحجج الدقيقة، الغرض، انتهاء الصلاحية، الرئيسية، ونونس مرة واحدة عند إعادة تشغيل الأمور. HMAC و الحجة المتماثلة بالضبط لجعل الحدود مرئية

لا يجب أن يعيش دفتر غير موجود داخل كائن بوابة واحد. النموذج القابل للتشغيل يضخ TTL-pruned مخزن استرداد يمكن مشاركتها من قبل حالات بوابة متعددة. دعوة الذرية هي حدود التنفيذ: فقط قبول معتمد أو تراجع محطام صريح يتناول الحالة. استجابة غير مصممة أو `cancel` لا تنفذ أي شيء وتبقى قابلة للتعديل حتى انتهاء صلاحيتها.

لا تخزين سياق التأكيد الخفي في جلسة بروتوكول. يجب أن تكون أي حالة خادم قادرة على التحقق من التجربة المجددة.

### قاعدة رقم اثنان للاتصالات ذات المخاطر العالية

تصنيف مكالمة على طول ثلاثة محور:

- إنه يستهلك المدخلات غير الموثوق بها
- يمكنه الوصول إلى البيانات الحساسة
- ويتسبب في عمل خارجي متواصل.

خطوة واحدة تلقائية لا ينبغي أن تجمع بين الثلاثة. تقسيمها، تقليل الامتيازات، أو طلب إدخال المستخدم صريح من خلال MRTR. هذه هي هيرستيك التصميم، وليس قدرة بروتوكول.

### تقليل السلطة قبل الإعدام

عدم الحالة الجنسية وحدها ليس أمنا. فإنه يزيل تاريخ البروتوكول المخفي، ولكن طلب مستقل لا يزال يمكن أن يطلب من المعاملة المكثفة السلطة تسريب البيانات أو إجراء تغيير لا رجعة فيه. يأتي الأمان من تقليل السلطة في كل حدود:

1. **صيغة صيغة** تعرض عملية محددة واحدة مثل `archive_note`، ليس عادي `run` أو `request` أداة يمكنها أن تعبر عن سلطات غير مرتبطة
2. **حجج مُصحّح** استخدم مخططًا مغلقًا حيث يكون عمليًا ، ورفض الحقول غير المعروفة ، وتطبيع المعرفات مرة واحدة ، وحجم الحد الأقصى ، وتؤكد المقصود ، والمساكن ، وملكية الموارد قبل تقييم السياسة.
3. **الإذن الحالي** ربط الرئيسي الموثق بالفعل الدقيق والموارد والبيئة والحجج المعايدة. لا تمنح ملاحظات الأدوات وقدرات العميل هذه السلطة.
4. **الموافقة المرتبطة بالعمل** للحصول على دعوة متسقة، ربط الموافقة بتحويل الفعل المكتوب والحجج المعايدة، بالإضافة إلى السياسة الرئيسية والمتأخرة والمرة الواحدة. أي حقل تغير يتطلب قرارًا جديدًا.
5. **رفض من الدرجة الأولى** النموذج يرفض، انتهت صلاحية الموافقة، انخفاض مستخدمين، والوصول غير آمن كنتائج عادية التي لا تنفذ أي تأثير جانبي. لا تحويل رفض إلى أداة ضعف الرد.
6. **إعادة إصدار أدلة مراجعة** سجل من سأل، والذي اعترف وصف ونسخة السياسة التي استخدمت، والهدف المعتاد الذي تم ترخيصه، لماذا السماح أو رفض القرار، وما إذا كان التنفيذ بدأ. تخزين الاهتزازات أو القيم المحذوفة بدلا من السر.

كل خطوة تقضي ما يمكن أن يفعله المكون التالي. يجب على المعاملة النهائية تلقي أمر النطاق المعتمد بالفعل ، وليس نص النموذج الخام بالإضافة إلى إثباتات واسعة. كرر السلسلة بأكملها على MRTR محاولة إعادة، تحديث المهمة، أو المكالمة التي يتم إرسالها من خلال البوابة. لا يحول الموافقة السابقة الطلبات اللاحقة إلى حركة مرور جلسة موثوق بها.

### مسارات التفاعل الحالية والمتبقية

تم إزالة الجذر والعينة والسجل في التنفيذات الجديدة 2026-07-28. يمكن للبوابة الاحتفاظ بالرقم القديم لقناة الطلب فقط كمسار توافقية محدد الإصدار.

لا تبني دفاعا جديدا حول مقيّد العينات في الجلسة. تطبق حصص على الرئيسي الموثق، والمصدر، والموارد، والأداة، والفترة. MRTR طلبات الدخول والردود.

### التحققات النقلية

- اقبلوا الحديث MCP الرسائل في الفردي POST نقطة النهاية
- العودة 405 للحديث GET و DELETE.
- لا تعتمد على `Mcp-Session-Id`.
- تجاهل جلسة إرث وتعيد تشغيل العناوين كمدخلات السلطة.
- العودة JSON أو طموح الطلب SSE لهذا السبب POST.
- الاستخدام `subscriptions/listen` فقط لإخطارات التغييرات التي تستمر لفترة طويلة.

## بناءها

`code/main.py` يطبق نموذج بوابة أمن صغيرة داخل العملية. فإنه يطرح ويدخل وصف أداة كاملة، ويرجع تقارير التسمم البيانات المعدنية والظل، ويمتحق القيم الحديثة لطلب الملفات والتوجه، ويقوم بتصدير مؤكد في جولتين مع توقيع `requestState` ومتجر إعادة تشغيل مشترك

النموذج يبدأ بعد HTTP لقد قام المعدل بتحليل JSON الرؤوس الجسمية والمسار. لا تؤكد `Content-Type` أو `Accept`. ربط نفس المُرسل إلى الدروس 09 كاملة التسريبية HTTP المعدل، الذي يتطلب `Content-Type: application/json` و `Accept` القيمة التي تحتوي على كلتا `application/json` و `text/event-stream`.

إشغله

```bash
cd phases/13-tools-and-protocols/15-mcp-security-tool-poisoning
python3 code/main.py
python3 -m unittest discover code/tests -v
```

يُعدّل العينة بشكل متعمد مصطلح وصف. يُنتج المسح والمقارنة الهضمية نتائج مستقلة. `input_required` ردّة فعل و محاولة أخرى بدون ولاية

في بوابة، قم بتجربة نفس التحققات أثناء الكشف ومن ثم قبل إرسالها. يمكن أن تقلل الاحتفاظ بالتخزين من عمل الكشف، ولكن يجب أن تنتهي الموافقة المحفظة في الاحتفاظ بالتخزين أو يتم إلغاء صلاحيتها عند تغيير المصطلح.

6. وضع كل ضغط اليد والسلوك الجلسة وراء `2025-11-25` فرع التوافق

## الشروط الرئيسية

| المدة | المعنى |
|------|---------|
| تسمم البيانات المعدنية | التعليمات أو الادعاءات الخادعة المضمنة في وصف الأداة |
| سحب السجاد | تغيير إلى وصف تمت الموافقة عليه سابقاً |
| إظلال الأدوات | التوجيه الغامض الناجم عن أسماء غير مؤهلة مزدوجة |
| عدم مطابقة العنوان | عنوان التوجيه و JSON-RPC خلاف الجسم، خطأ `-32020` |
| حاشة | إصدار الموصف المعتمد الكامل |
| MRTR | نمط الاستجابة غير الحكومية والإعادة المحاولة للمدخول الذي يطلبه الخادم |
| `requestState` | قيمة ذهاب و ذهاب غير واضحة يجب أن تعتبر مدخل غير موثوق به |
| إعلان القدرة | بيان على توافق البروتوكول، وليس تصريح |
| دعم النموذج الضمني | فجأة `elicitation` كائن القدرة، يعادل دعم النموذج |
| اسم الأداة المؤهل | اسم البوابة المستقرة مثل `notes.search` |
