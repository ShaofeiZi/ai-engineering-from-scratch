# 多智能体强化学习（MARL）——MADDPG、QMIX 与 MAPPO

> 多智能体协调继承了强化学习的深厚传统，而这些方法在 2026 年仍影响着 LLM 智能体系统。**MADDPG**（Lowe 等，NeurIPS 2017，arXiv:1706.02275）引入了集中式训练、分散式执行（CTDE）：训练期间，每个 critic 都能看到所有智能体的状态与动作；测试时只运行局部 actor。它适用于合作、竞争和混合环境。**QMIX**（Rashid 等，ICML 2018，arXiv:1803.11485）是一种使用单调混合网络的价值分解方法；各智能体的 Q 值组合成联合 Q，使 `argmax` 可以自然地分散计算——它在星际争霸多智能体挑战（SMAC）中占据主导。**MAPPO**（Yu 等，NeurIPS 2022，arXiv:2103.01955）是在 PPO 中加入集中式价值函数；只需少量调参，就在粒子世界、SMAC、Google Research Football 和 Hanabi 上表现得“出人意料地有效”。这些方法为必须分散行动的智能体团队提供训练策略。MAPPO 是 **2026 年合作式 MARL 的默认基线**。本课会在一个小型网格世界玩具示例中分别构建三种模式，让你在开始训练 LLM 智能体之前形成直觉。

## 问题

LLM 智能体系统越来越多地训练智能体间协调策略：何时让步、何时行动、调用哪个同伴。告诉你如何训练这类策略的研究领域是多智能体强化学习（Multi-Agent Reinforcement Learning，MARL）。它早于 LLM 浪潮出现，并形成了少数占主导地位的算法。

如果不了解模式词汇，阅读 MARL 论文会非常痛苦。集中式训练、分散式执行（CTDE）、价值分解和集中式 critic 并非流行术语，而是针对具体问题给出的具体答案：

- 独立强化学习（每个智能体单独学习）从每个智能体的视角看都是非平稳的，效果很差。
- 集中式强化学习（一个智能体控制所有主体）无法扩展，也违反执行约束。
- CTDE 兼得二者优点：使用全局信息训练，再部署局部策略。

## 概念

### 论文使用的三类环境

- **粒子世界（多智能体粒子环境）。** 具有合作与竞争任务的简单二维物理环境，是 MADDPG 最初的试验场。
- **星际争霸多智能体挑战（SMAC）。** 合作式微操、部分可观测；是 QMIX 的试验场。动作离散，状态连续。
- **Google Research Football、Hanabi、MPE。** 用于 MAPPO 基线。

不同环境具有不同的动作与观察类型，各算法会据此选择方法。

### MADDPG（2017）——CTDE 模式

每个智能体 `i` 都有一个 actor `mu_i(o_i)`，把自己的观察映射为动作。每个智能体也有一个 critic `Q_i(x, a_1, ..., a_n)`，在训练期间查看全部观察与全部动作。actor 根据 critic 的评估通过策略梯度更新。

```
actor update:    grad_theta_i J = E[grad_theta mu_i(o_i) * grad_a_i Q_i(x, a_1..n) at a_i=mu_i(o_i)]
critic update:   TD on Q_i(x, a_1..n) given next-state joint estimate
```

为什么采用 CTDE：训练时，我们知道所有智能体的动作，并用这些信息降低每个 critic 的方差；部署时，每个智能体只能看到 `o_i`，并调用 `mu_i(o_i)`。

失败模式：critic 的规模会随智能体数量 N 增长，因为输入包含所有动作。不使用近似时，它很难扩展到约 10 个以上的智能体。

### QMIX（2018）——价值分解

它只适用于合作场景。全局奖励是各智能体 Q 值的某个单调函数：

```
Q_tot(tau, a) = f(Q_1(tau_1, a_1), ..., Q_n(tau_n, a_n)),   df/dQ_i >= 0
```

单调性保证，`argmax_a Q_tot` 可以由每个智能体独立选择 `argmax_{a_i} Q_i` 来计算。这**恰好就是所需的分散式执行属性**。训练期间，混合网络根据各智能体的 Q 值生成 `Q_tot`。

QMIX 为何在 SMAC 上胜出：合作式星际争霸微操具有同构智能体、局部观察和全局奖励，与价值分解非常契合。

失败模式：单调性约束较为严格；有些任务的奖励结构无法单调分解，例如某个智能体为团队作出牺牲。QTRAN、QPLEX 等扩展放宽了这一限制。

### MAPPO（2022）——被忽视的默认方案

多智能体 PPO：带有集中式价值函数的 PPO。每个智能体都有自己的策略；所有智能体共享一个能够看到完整状态的价值函数，或各自拥有这样的价值函数。Yu 等在 2022 年使用五项基准，将 MAPPO 与 MADDPG、QMIX 及其扩展进行比较，发现：

- 在粒子世界、SMAC、Google Research Football、Hanabi 和 MPE 上，MAPPO 的表现达到或超过离策略 MARL 方法。
- 所需超参数调优很少。
- 训练稳定，而且可以跨随机种子复现。

在这篇论文之前，社区低估了同策略 MARL。到了 2026 年，MAPPO 已成为合作式 MARL 的默认基线，任何新方法都必须胜过它。

### LLM 智能体工程师为何应该关注

有三种直接用途：

1. **路由器训练。** 元智能体选择由哪个子智能体处理任务。这是一个 MARL 问题：有 N 个分散式子智能体和一个集中式路由器，适合使用 MAPPO。
2. **角色涌现。** 在生成式智能体模拟中，训练智能体随时间采用互补角色，本质上也是 MARL 问题。QMIX 风格的价值分解通过结构强制产生互补性。
3. **多智能体工具使用。** 当智能体共享工具并竞争预算时，通过 CTDE 训练可以得到遵守资源约束、可部署的局部策略。

实际注意事项是：2026 年的大多数生产 LLM 智能体系统仍通过提示来设定策略，而不是训练策略。只有在你拥有（a）大量交互数据、（b）明确奖励信号和（c）投入训练基础设施的意愿时，MARL 才会进入方案。

### CTDE 也是超越 RL 的设计模式

即使不训练，CTDE 仍是一种有用的架构模式：

- 在*设计*期间，假设可以看到完整团队信息。
- 在*运行时*，强制执行分散式执行：每个智能体只能看到 `o_i`。

这种模式迫使你显式维护每个智能体的状态，并从一开始就思考部分可观测性。很多生产多智能体系统暗中假定状态完全共享；CTDE 的纪律能够避免这种问题。

### 非平稳性问题

多个智能体同时学习时，从每个智能体看来，它的环境——包括其他智能体的策略——都是非平稳的。经典单智能体强化学习的证明会失效。本课中的 MARL 算法都在处理这一问题：

- MADDPG：全局 critic 看到所有动作，因此价值估计保持平稳。
- QMIX：价值分解把学习移到最优性有明确定义的联合 Q 空间。
- MAPPO：集中式价值函数减弱其他智能体策略变化造成的方差。

在 LLM 智能体系统中，非平稳性表现为：“我的智能体上个月还能正常工作，现在上游另一个智能体发生变化，它就开始失常。”使用 CTDE 训练 MARL 是原则性的修复方案；提示级修复更快，却不够持久。

## 动手构建

`code/main.py` 会在同一个微型双智能体合作网格世界中演示三种模式：

- 环境：两个智能体位于 4×4 网格中，其中有一个奖励颗粒。任何智能体到达颗粒时，奖励为 1，任务结束。
- `IndependentAgents`——每个智能体都把其他智能体视为环境。基线。
- `MADDPGStyle`——集中式 critic 计算联合价值，actor 策略据此更新。使用脚本模拟策略改进。
- `QMIXStyle`——使用单调混合器进行价值分解。
- `MAPPOStyle`——使用集中式价值函数，策略根据共享基线更新。

四种实现会运行相同 episode，并报告到达目标所需的平均步数。CTDE 变体会比独立基线收敛到更短路径。

运行：

```
python3 code/main.py
```

预期输出：独立智能体平均需要约 6 步；CTDE 变体收敛到约 3.5 步（4×4 网格的最优值为 3）。即使使用脚本化策略，模式差异仍会显现。

## 交付成果

MARL 在生产环境中并不常见。当你确实要使用它时：

- **从 MAPPO 开始。** 2022 年论文确立了它的基线地位；先复现 MAPPO，可以避免花费数周追逐更复杂的方法。
- **记录每个智能体的观察与动作流。** 没有逐智能体追踪，几乎无法调试 MARL。
- **分离训练代码与执行代码。** CTDE 是一项纪律；确保执行路径真的只能看到 `o_i`。
- **奖励塑形警告。** MARL 对奖励设计极为敏感。塑形中只要有一个协调缺陷，智能体就会学会利用它。应运行对抗测试。
- **对于 LLM 智能体，** 先考虑提示级策略。只有交互数据、奖励信号和基础设施全部具备时，才投资 MARL 训练。

## 练习

1. 运行 `code/main.py`，测量独立智能体与 MAPPO 风格智能体之间的目标步数差距。在 6×6 网格上，差距会扩大还是缩小？
2. 实现竞争变体：两个智能体、一个颗粒，只有先到达者获得奖励。哪种模式能自然处理竞争？历史上是 MADDPG。
3. 阅读 MADDPG（arXiv:1706.02275）第 3 节。用自己的语言，以伪代码形式实现准确的 critic 更新规则。
4. 阅读 MAPPO（arXiv:2103.01955）。为什么作者认为集中式价值 + PPO 在他们的基准上胜过离策略 MARL？列出最有力的三项论据。
5. 把 CTDE 作为设计模式应用到一个假想的 LLM 智能体系统（例如研究智能体 + 摘要智能体 + 编码智能体）。设计时可以获得、但运行时不可用的联合信息有哪些？

## 关键术语

| 术语 | 人们通常怎么说 | 实际含义 |
|------|----------------|------------------------|
| MARL | “多智能体强化学习” | 面向多智能体系统的强化学习。 |
| CTDE | “集中式训练、分散式执行” | 使用全局信息训练，使用局部策略部署。 |
| MADDPG | “多智能体 DDPG” | CTDE 方法，每个智能体的 critic 都能看到全部观察与动作。 |
| QMIX | “价值分解” | 单调混合每个智能体的 Q 值，仅适用于合作场景。 |
| MAPPO | “多智能体 PPO” | 带集中式价值函数的 PPO，是 2026 年默认基线。 |
| 价值分解 | “各个 Q 值之和” | 把联合 Q 表示为各智能体 Q 值的单调函数。 |
| 非平稳性 | “不断移动的目标” | 其他智能体学习时，每个智能体的环境都会改变；这是 MARL 的核心问题。 |
| 在策略 / 离策略 | “从当前策略 / 重放中学习” | PPO 属于在策略（MAPPO）；DDPG 与 Q-learning 属于离策略。 |
| SMAC | “星际争霸多智能体挑战” | 合作式微操基准，是 QMIX 的主场。 |
