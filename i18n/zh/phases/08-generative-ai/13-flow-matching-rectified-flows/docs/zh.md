# 流匹配与整流流

> 扩散模型需要 20～50 个采样步骤，是因为它从噪声到数据走的是一条弯曲路径。流匹配（Lipman 等，2023）与整流流（Liu 等，2022）则训练出笔直路径。路径越直，所需步骤越少，推理也越快。Stable Diffusion 3、Flux.1 与 AudioCraft 2 都在 2024 年转向了流匹配。

**Type:** 构建
**Languages:** Python
**Prerequisites:** 阶段 8 · 06（DDPM）、阶段 1（微积分）
**Time:** 约 45 分钟

## 问题

DDPM 的反向过程是从 `N(0, I)` 返回数据分布的 1000 步随机游走。DDIM 将其压缩为 20～50 个确定性步骤。你希望进一步减少步骤，最好只用一步。障碍在于，求解反向过程的常微分方程是刚性的，路径也很弯曲。

如果能训练模型，让噪声到数据之间的路径成为*直线*，那么从 `t=1` 到 `t=0` 只需一个欧拉步骤。流匹配直接构造这种路径：定义从 `x_1 ∼ N(0, I)` 到 `x_0 ∼ data` 的直线插值，训练向量场 `v_θ(x, t)` 去匹配它的时间导数，再在推理时执行积分。

整流流（Liu，2022）更进一步：通过再流动过程迭代拉直路径，使常微分方程逐渐趋近线性。经过两轮再流动后，两步采样器即可达到 50 步 DDPM 的质量。

## 概念

![流匹配：噪声与数据之间的直线插值](../../../../../../phases/08-generative-ai/13-flow-matching-rectified-flows/assets/flow-matching.svg)

### 直线流

定义：

```
x_t = t · x_1 + (1 - t) · x_0,   t ∈ [0, 1]
```

其中 `x_0 ~ data`，`x_1 ~ N(0, I)`。沿这条直线的时间导数是常数：

```
dx_t / dt = x_1 - x_0
```

定义一个神经向量场 `v_θ(x_t, t)`，训练它匹配这个导数：

```
L = E_{x_0, x_1, t} || v_θ(x_t, t) - (x_1 - x_0) ||²
```

这就是**条件流匹配**损失（Lipman，2023）。训练不需要模拟：从不展开常微分方程，只需采样 `(x_0, x_1, t)` 并进行回归。

### 采样

推理时，沿时间*反向*积分学习到的向量场：

```
x_{t-Δt} = x_t - Δt · v_θ(x_t, t)
```

从 `x_1 ~ N(0, I)` 开始，通过欧拉步骤一路走到 `t=0`。

### 整流流（Liu，2022）

直线流可以工作，但学习到的路径*实际上并不笔直*——因为多个 `x_0` 都可能映射到同一个 `x_1`。整流流的再流动步骤如下：

1. 用随机配对训练流模型 v_1。
2. 采样 N 对 `(x_1, x_0)`：从 `x_1` 出发，用 v_1 积分到其落点 `x_0`。
3. 在这些配对样本上训练 v_2。由于这些样本现已“按常微分方程匹配”，它们之间的直线插值确实更加平坦。
4. 重复上述过程。

实践中，两轮再流动就能得到近乎线性的路径，从而支持 2～4 步推理。SDXL-Turbo、SD3-Turbo 与 LCM 都是从流匹配模型蒸馏得到的。

### 为什么它在 2024 年赢得图像领域

原因有三：

1. **训练无须模拟**——训练时不必展开常微分方程，实现非常简单。
2. **更好的损失几何性质**——直线路径拥有一致的信噪比，而 DDPM 的 ε 损失在调度两端的信噪比很差。
3. **推理更快**——4～8 步即可达到 SDXL-Turbo 的质量；借助一致性蒸馏则只需一步。

## 流匹配与 DDPM——确切联系

采用高斯条件路径时，流匹配就是使用*特定噪声调度*的扩散。选择 `x_t = α(t) x_0 + σ(t) x_1` 调度后，流匹配会恢复经过 Stratonovich 重写的扩散，其中 `v = α'·x_0 - σ'·x_1`。对于高斯路径，两者在代数上等价。

流匹配增加的是：更清晰的目标（普通速度）、更简洁的损失，以及尝试非高斯插值的自由。

## 动手构建

`code/main.py` 在双峰高斯混合分布上实现一维流匹配。向量场 `v_θ(x, t)` 是一个微型 MLP，用直线目标训练。推理时分别积分 1、2、4、20 个欧拉步骤，并比较样本质量。

### 第 1 步：训练损失

```python
def train_step(x0, net, rng, lr):
    x1 = rng.gauss(0, 1)
    t = rng.random()
    x_t = t * x1 + (1 - t) * x0
    target = x1 - x0
    pred = net_forward(x_t, t)
    loss = (pred - target) ** 2
    # backprop + update
```

### 第 2 步：多步推理

```python
def sample(net, num_steps):
    x = rng.gauss(0, 1)
    for i in range(num_steps):
        t = 1.0 - i / num_steps
        dt = 1.0 / num_steps
        x -= dt * net_forward(x, t)
    return x
```

预期四步采样器已经能够达到二十步的质量——这对延迟影响巨大。

## 陷阱

- **时间参数化。** 流匹配使用 `t ∈ [0, 1]`，其中 `t=0` 对应数据、`t=1` 对应噪声。DDPM 使用 `t ∈ [0, T]`，其中 `t=0` 对应数据、`t=T` 对应噪声。方向相同，尺度不同。论文经常弄错这一点。
- **调度选择。** 整流流的直线是“标准”流匹配调度，但也可以采用余弦调度或逻辑正态 t 采样（SD3 就这样做），以更好地覆盖不同尺度。
- **再流动成本。** 为再流动生成配对数据集，相当于对每个样本执行一次完整推理。只有确实需要 1～2 步推理时才应使用再流动。
- **无分类器引导仍然适用。** 只需在线性组合中用 v 替换 ε：`v_cfg = (1+w) v_cond - w v_uncond`。

## 练习

1. **简单。** 运行 `code/main.py`，对照真实数据分布，比较一步与二十步采样的 MSE。
2. **中等。** 将均匀 `t` 采样改为逻辑正态采样（让采样集中在 t 的中间区域）。模型质量是否有所提高？
3. **困难。** 实现一轮再流动：通过对第一个模型进行积分生成配对的 (x_0, x_1)，在这些配对上训练第二个模型，并比较一步采样的质量。

## 关键术语

| 术语 | 人们通常怎么说 | 实际含义 |
|------|-----------------|-----------------------|
| 流匹配 | “直线扩散” | 训练 `v_θ(x, t)`，使其沿插值路径匹配 `x_1 - x_0`。 |
| 整流流 | “再流动” | 迭代拉直学习所得流的过程。 |
| 速度场 | “v_θ” | 模型的输出——`x_t` 应当移动的方向。 |
| 直线插值 | “路径” | `x_t = (1-t)·x_0 + t·x_1`；目标导数非常简单。 |
| 欧拉采样器 | “一阶常微分方程求解器” | 最简单的积分器；路径笔直时效果很好。 |
| 逻辑正态 t | “SD3 采样” | 让 `t` 采样集中到梯度最强的中间取值。 |
| 一致性蒸馏 | “一步采样器” | 训练学生模型，把任意 `x_t` 直接映射到 `x_0`。 |
| 使用速度的 CFG | “v-CFG” | `v_cfg = (1+w) v_cond - w v_uncond`；同样的技巧，换了变量。 |

## 生产说明：Flux.1-schnell 将流匹配速度发挥到极致

流匹配在生产中的代表成果是 Flux.1-schnell——一个经过流匹配训练、蒸馏到 1～4 个推理步骤的 DiT，同时保持接近 Flux-dev 的质量。Niels 的“在 8GB 机器上运行 Flux”笔记本是参考部署方案：T5 + CLIP 编码、量化 MMDiT 去噪（schnell 用 4 步，而 dev 用 50 步）、VAE 解码。成本如下：

| 变体 | 步数 | L4 上 1024² 的延迟 | 总 FLOP（相对值） |
|---------|-------|------------------------|------------------------|
| Flux.1-dev（原始） | 50 | 约 15 秒 | 1.0× |
| Flux.1-schnell | 4 | 约 1.2 秒 | 0.08×（快 12 倍） |
| SDXL-base | 30 | 约 4 秒 | 0.25× |
| SDXL-Lightning 两步版 | 2 | 约 0.3 秒 | 0.03× |

生产法则是：**流匹配基础模型 + 蒸馏 = 2026 年快速文生图的默认方案。** 各大供应商都提供这种组合：SD3-Turbo（SD3 + 流 + 蒸馏）、Flux-schnell（Flux-dev + 整流流拉直）、CogView-4-Flash。纯扩散基础模型只存在于旧检查点中。
