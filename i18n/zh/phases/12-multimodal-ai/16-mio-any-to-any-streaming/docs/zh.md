# MIO 与任意模态到任意模态的流式多模态模型

> GPT-4o 交付了一种多数开放模型无法复现的产品：一个能够实时听取语音、观看视频并开口回应的智能体。到 2024 年末，开放生态给出的答案是 MIO（Wang 等，2024 年 9 月）。MIO 对文本、图像、语音与音乐进行分词，在交错序列上训练单个因果 Transformer，并实现任意模态到任意模态的生成。AnyGPT（Zhan 等，2024 年 2 月）是概念验证，MIO 是规模化版本，Unified-IO 2（Allen AI，2023 年 12 月）则是结合视觉与动作定位的近亲。本课会解读任意到任意模式——四个分词器、一个 Transformer，以及适合流式传输的解码。

**Type:** 学习
**Languages:** Python (stdlib, four-modality token allocator + streaming decode loop)
**Prerequisites:** 第 12 阶段 · 第 11 课（Chameleon）、第 6 阶段（语音与音频）
**Time:** 约 120 分钟

## 学习目标

- 设计一个能够容纳文本、图像、语音与音乐词元且不会发生冲突的共享词表。
- 从压缩与重建取舍的角度，比较 SEED-Tokenizer（图像）和 SpeechTokenizer 残差 VQ（语音）。
- 解释逐步构建任意模态到任意模态生成能力的四阶段课程。
- 说出三种开放的任意到任意配方及其主要取舍：MIO、AnyGPT、Unified-IO 2。

## 问题

统一多模态模型说起来容易，大规模构建却很困难。2024 年以前，大多数“任意到任意”系统实际上都是流水线：视觉模型 → 文本表示 → 语音模型 → 音频。每次跳转都会损失信息、增加延迟，也让训练更复杂。GPT-4o 的演示视频展示了单模型、亚秒级响应的替代方案，而开放系统落后了数月。

工程难题包括：

- 每种模态都必须有分词器；它要以足以重建的低损方式压缩数据，并以 Transformer 能够处理的速率生成词元。
- 单一词表必须为文本（32k 以上）、图像（16k 以上）、语音（4k 以上）和音乐（8k 以上）分配空间，最少要有四万多个条目。
- 训练数据必须覆盖每一种输入—输出组合（文本→图像、图像→语音、语音→图像等），否则模型必须学会组合。
- 推理时必须足够快地流式输出词元，使对话的首音频字节延迟低于 500 毫秒。

## 概念

### 四种模态的四个分词器

MIO 的分词器技术栈包括：

- 文本：标准 BPE，词表约 32000。
- 图像：SEED-Tokenizer（2023）——使用离散码本的量化 VAE，码本含 4096 个条目，每幅图像使用 32x32 个词元。
- 语音：SpeechTokenizer 残差 VQ（2023）——把 16kHz 波形编码到 8 个分层码本中；第一层表示粗粒度内容，后续层补充韵律和说话者身份。
- 音乐：类似的残差 VQ（Meta 的 MusicGen / Encodec 家族），使用 4～8 个码本。

每种模态都会产生整数词元。这些词元在共享词表中使用互不重叠的 ID 区间：

```
text:   0..31999
image:  32000..36095  (4096 image tokens)
speech: 36096..40191  (4096 speech base tokens, plus residual layers)
music:  40192..48383  (8192 music tokens)
sep:    48384..48390  (<image>, <speech>, <music>, </...>, etc.)
```

总词表约为 48k，输入嵌入与输出投影都覆盖全部条目。

### 流式解码

语音生成使用残差 VQ。Transformer 预测基础层（第 0 层）语音词元，再由并行解码的残差量化器预测后续层。以 16kHz 音频计算，每个第 0 层词元大约对应 50 毫秒声音。

流式处理模式如下：

1. 用户对着麦克风说话；实时音频分词器每 50 毫秒输出一次语音词元。
2. MIO 在词元抵达时进行消费（提示词预填充 + 增量前向传播）。
3. 输出词元在生成时立即流出；并行语音解码器在约 50～150 毫秒内将其转换为音频样本。
4. 首音频字节时间：MIO 论文约为 300～500 毫秒，接近 GPT-4o 的约 250 毫秒。

Mini-Omni（arXiv:2408.16725）、GLM-4-Voice（arXiv:2412.02612）和 Moshi（arXiv:2410.00037）是互为补充的流式语音大语言模型设计。Moshi 尤其突出，能在单张 GPU 上实现 160 毫秒往返延迟。

### 四阶段课程

MIO 的训练课程如下：

1. 阶段 1——对齐。使用大规模模态配对语料：文本—图像、文本—语音、文本—音乐。每种配对都使用自己的词表区段，从而训练共享词表。
2. 阶段 2——交错。使用多模态交错文档（包含图像 + 视频的博客、附带转写文本的播客等），训练跨模态上下文能力。
3. 阶段 3——语音增强。加入更多音频数据，在不损失文本能力的情况下提高语音质量。
4. 阶段 4——SFT。跨模态执行指令微调：VQA、图像描述、旁白、语音到语音对话。

缺少任何阶段都会损害相应能力：跳过阶段 2，模型会失去跨模态上下文；跳过阶段 3，语音质量会很差。

### 视觉思维链

MIO 引入视觉思维链：模型会输出中间图像词元，作为推理步骤。对于“猫是否正在爬树？”这个问题，模型会：

1. 输出渲染场景的 `<image>` 词元（来自输入图像或一幅草图）。
2. 输出分析该草图的文本。
3. 输出最终答案。

渲染出的中间图像充当草稿纸。空间推理任务的基准表现会因此提升，其思想与文本推理中的思维链相呼应。

### 任意到任意模型的竞争者

- AnyGPT（arXiv:2402.12226）：支持四种模态（文本、图像、语音、音乐），设计类似。
- Unified-IO 2（arXiv:2312.17172）：增加视觉动作输出、深度与法线。任务更多样，规模较小。
- NExT-GPT（arXiv:2309.05519）：大语言模型 + 模态专用扩散解码器，并非单模型方案。
- CoDi（arXiv:2305.11846）：可组合扩散；通过共享潜空间实现任意到任意生成。

MIO 是最接近纯词元任意到任意的方案，AnyGPT 则是它的概念先驱。

### 延迟预算

对话式产品中，每个组件的延迟都很重要：

- 麦克风到音频词元：约 50 毫秒。
- 预填充（音频词元 + 历史）：在 8B 模型上约 100 毫秒。
- 第一个输出词元：约 50 毫秒。
- 并行残差 VQ + 语音解码器：约 100～150 毫秒。

最低首音频字节时间总计约 300 毫秒。GPT-4o 宣称约 250 毫秒，Moshi 宣称 160 毫秒；根据公开基准，MIO/AnyGPT 大约在 400～600 毫秒范围内。

### 任意到任意为何仍然困难

即使到了 2026 年，开放任意到任意模型仍在两个方面落后于闭源模型：

- 语音质量。残差 VQ 分词器有损，生成的对话语音比 ElevenLabs 级别的声音更显机械。
- 跨模态推理。要求模型“把看到的内容唱出来”，失败率仍然高于纯视觉任务。

这些仍是开放研究问题。Qwen3-Omni（第 12.20 课）是 2025 年最先进的开放尝试。

## 投入使用

`code/main.py` 会：

- 定义四模态词表分配并打印结果。
- 通过分词器路由器处理一组多模态输入（文本、图像、音频片段、音乐）。
- 模拟文本到语音响应的流式解码，并统计延迟。
- 根据编码器、预填充与解码器延迟，计算预期首音频字节时间。

## 练习

1. 你的产品接收语音输入并返回语音输出。端到端延迟预算目标应当是多少？列出所有会消耗时间的组件。

2. SpeechTokenizer 残差 VQ 使用 8 个码本。解释为什么必须并行解码残差层（而不是顺序解码），以及这样能节省多少延迟。

3. 你的词表包含 32k 文本 + 4k 图像 + 4k 语音。再加入 8k 音乐和约 10 个分隔符。在隐藏维度为 4096 时，嵌入矩阵需要多少参数？

4. 视觉思维链会生成一幅中间图像。哪些类型的问题会从中受益？哪些问题会因额外词元而受损？

5. 阅读 Moshi（arXiv:2410.00037）。描述它的“内心独白”技术，并与 MIO 的视觉思维链比较。

## 关键术语

| 术语 | 人们常说 | 实际含义 |
|------|-----------------|------------------------|
| 任意到任意 | “多模态输入/输出” | 一个可以沿任意方向接收和输出文本、图像、语音与音乐的模型 |
| 残差 VQ | “语音分词器栈” | 每层补充信息的多码本分词方法；基础层表示内容，后续层表示韵律 |
| SEED-Tokenizer | “图像编码” | MIO 使用的离散图像分词器，码本包含 4096 个条目 |
| 视觉思维链 | “视觉草稿纸” | 模型在最终答案之前生成一幅中间图像，作为推理步骤 |
| 首音频字节时间 | “TTFAB” | 从用户发出语音到收到第一个音频输出的延迟；低于 500 毫秒才有对话感 |
| 四阶段课程 | “训练配方” | 按“对齐 -> 交错 -> 语音增强 -> SFT”的顺序训练 |
