# 多模态智能体与计算机使用（综合项目）

> 2026 年的前沿产品，是能够读取屏幕截图、点击按钮、浏览 Web 界面、填写表单并端到端完成工作流的多模态智能体。SeeClick 与 CogAgent（2024）证明了 GUI 定位原语的可行性，Ferret-UI 将其扩展到移动端，ChartAgent 则为图表引入视觉工具使用。VisualWebArena 与 AgentVista（2026）是前沿模型追赶的基准——即使 Gemini 3 Pro 与 Claude Opus 4.7，在 AgentVista 困难任务上的得分也只有约 30%。这个综合项目会汇集阶段 12 的所有脉络：感知（高分辨率 VLM）、推理（带工具使用的大语言模型）、定位（坐标输出）、长程记忆和评估。

**Type:** 综合项目
**Languages:** Python (stdlib, action schema + agent loop skeleton)
**Prerequisites:** 第 12 阶段 · 第 05 课（LLaVA）、第 12 阶段 · 第 09 课（Qwen-VL JSON）、第 14 阶段（智能体工程）
**Time:** 约 240 分钟

## 学习目标

- 设计多模态智能体循环：感知 → 推理 → 行动 → 观察 → 重复。
- 构建 GUI 定位输出 Schema，让 VLM 能以 JSON 输出点击坐标、输入文本、滚动与拖拽。
- 比较仅屏幕截图智能体、无障碍树智能体与混合智能体。
- 在小型 VisualWebArena 子集上建立多模态智能体基准评估。

## 问题

一个订票网站工作流：“帮我找一张 4 月 15 日飞往东京、价格低于 800 美元的靠过道座位机票，并完成预订。”

多模态智能体需要：

1. 截取浏览器屏幕。
2. 根据屏幕截图 + URL + 目标生成计划。
3. 输出结构化动作：在（x,y）处点击，在元素 E 中输入“Tokyo”，向下滚动，选择单选按钮。
4. 将动作应用到浏览器。
5. 观察新状态（下一张屏幕截图）。
6. 重复，直到任务完成。

每一步都是一次多模态 VLM 调用。VLM 输出必须是可解析 JSON。错误会跨步骤累积，因此恢复能力至关重要。

## 概念

### GUI 定位——基础原语

GUI 定位是指：给定一张屏幕截图与自然语言指令，输出应点击位置的（x, y）坐标（或其他动作）。

SeeClick（arXiv:2401.10935）是首个大规模开放成果：在合成 + 真实 GUI 数据上微调 VLM，以纯文本词元输出坐标。它确实有效。

CogAgent（arXiv:2312.08914）为密集用户界面加入 1120x1120 高分辨率编码，在 Web 导航上的得分约为 84%。

Ferret-UI（arXiv:2404.05719）专注移动端用户界面，并与 iOS 无障碍数据集成。

输出格式通常为 JSON：

```json
{"action": "click", "x": 384, "y": 220, "element_desc": "Search button"}
```

`element_desc` 有助于错误恢复：如果两张截图之间坐标发生漂移，语义提示可以让系统重新定位。

### 动作 Schema

典型动作 Schema 包含 6～10 种动作类型：

- `click`：(x, y)
- `type`：(text, x?, y?)
- `scroll`：(direction, amount)
- `drag`：(x0, y0, x1, y1)
- `select`：(option_index)
- `hover`：(x, y)
- `navigate`：(url)
- `wait`：(ms)
- `done`：(success, explanation)

智能体每一步输出一个动作。浏览器包装器执行动作，并返回新状态。

### 仅屏幕截图与无障碍树

有两种输入模式：

- 仅屏幕截图：输入完整图像，不包含结构信息。通用性最强，适用于任何应用。
- 无障碍树：结构化 DOM / iOS 无障碍信息。定位可靠得多，但只能在可获取无障碍树的环境中使用。
- 混合模式：同时使用二者；无障碍树为原子动作提供可靠定位，屏幕截图提供语义上下文。

生产级智能体会尽可能使用混合模式。浏览器自动化（Selenium + 无障碍接口）始终可以获取树，桌面应用则不一定。

### 长程记忆

一个 20 步工作流会生成 20 张屏幕截图，VLM 上下文很快就会填满。有三种压缩策略：

- 摘要链：每执行 5 步，总结一次已发生的内容，再丢弃旧截图。
- 跳帧：保留第一张、最后一张和每隔 3 张的截图。
- 工具记录日志：执行动作后，只保留已完成操作的文本日志；不再重新查看旧截图。

Claude 的计算机使用 API 采用日志模式。它更简单，也更可靠。

### 视觉工具使用

ChartAgent（arXiv:2510.04514）为图表理解引入视觉工具使用：裁剪、缩放、OCR、调用外部检测。智能体可以输出工具调用：“裁剪到区域（100, 200, 300, 400），然后调用 OCR。”工具返回文本，VLM 继续推理。

这种模式可以推广：标记集提示、区域标注和外部检测工具，都符合相同的“输出工具调用，接收结构化响应”Schema。

### 2026 年基准

- ScreenSpot-Pro：在约 1000 张 Web 截图上进行 GUI 定位。开放模型最佳 Qwen2.5-VL-72B 约 85%，前沿模型约 90%。
- VisualWebArena：端到端 Web 任务（商店、论坛、分类广告）。开放模型最佳约 20%，Gemini 3 Pro 约 27%。
- AgentVista（arXiv:2602.23166）：2026 年最困难的基准，覆盖 12 个领域的真实工作流。前沿模型得分 27%～40%，开放模型为 10%～20%。
- WebArena / WebShop：更早的基准，已被前沿模型刷到饱和。

### 为什么仍然困难

智能体性能瓶颈包括：

1. 细粒度视觉定位。“点击那个小 X”在移动端分辨率下经常失败。
2. 长程规划。执行 10 个动作后，智能体会偏离目标。
3. 错误恢复。点击失败（按钮点错）后，检测并恢复的训练数据极少。
4. 跨页面上下文。在标签页之间切换或填写长表单时，状态会丢失。

研究方向包括：记忆架构、显式重新规划、多模态验证（使用截图匹配确认动作是否成功）。

### 综合项目的构建任务

综合项目要求构建一个计算机使用智能体，它会：

1. 读取模拟订票网站页面的 HTML + 屏幕截图。
2. 规划多步骤序列：搜索 → 选择 → 填写表单 → 提交。
3. 输出符合动作 Schema 的 JSON 动作。
4. 在固定的 10 项任务子集上评估。

## 练习

1. 为动作 Schema 添加 `screenshot_region` 工具（裁剪 + 缩放）。哪些任务会从中受益？

2. 阅读 AgentVista（arXiv:2602.23166）。描述最困难的任务类别，以及前沿模型为何仍会失败。

3. 长程记忆压缩：设计一条摘要链，实时保留的屏幕截图不超过 4 张，但可以记录任意数量的文本日志。

4. 构建错误恢复挂钩：动作失败（找不到按钮）时，智能体下一步做什么？

## 关键术语

| 术语 | 人们常说 | 实际含义 |
|------|-----------------|------------------------|
| GUI 定位 | “点击坐标” | 模型针对屏幕截图中的指令目标输出（x,y）坐标 |
| 动作 Schema | “工具定义” | 有效动作（点击、输入、滚动、拖拽）的 JSON 描述 |
| 无障碍树 | “结构化 DOM” | 来自浏览器/iOS API 的机器可读用户界面层次结构 |
| 混合智能体 | “截图 + 树” | 同时使用图像与结构化信息；比单独使用其中任一种更可靠 |
| 视觉工具使用 | “缩放/裁剪/检测” | 智能体在规划过程中调用外部视觉工具（OCR、检测） |
| 摘要链 | “记忆压缩” | 用周期性文本摘要替换很长的截图历史 |
| VisualWebArena | “端到端 Web 基准” | 2024 年用于端到端 Web 任务的基准 |
| AgentVista | “2026 困难基准” | 覆盖 12 个领域的真实工作流；即使 Gemini 3 Pro 也只得约 30% |
