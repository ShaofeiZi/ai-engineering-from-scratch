# Show-o 与离散扩散统一模型

> Transfusion 混合连续表示与离散表示。Show-o（Xie 等，2024 年 8 月）则反其道而行：文本词元使用因果下一词元预测，图像词元使用 MaskGIT 风格的掩码离散扩散。二者位于同一个 Transformer 中，并使用混合注意力掩码。结果是，一个骨干、每种模态一个分词器、一种损失形式（从下一词元预测扩展到掩码预测），即可统一 VQA、文本生成图像、图像修复与混合模态生成。本课会讲解 Show-o 的设计——掩码离散扩散为何能成为一种并行、少步骤的图像生成器——并将其与 Transfusion 和 Emu3 对比。

**Type:** 学习
**Languages:** Python (stdlib, masked-discrete-diffusion sampler)
**Prerequisites:** 第 12 阶段 · 第 13 课（Transfusion）
**Time:** 约 120 分钟

## 学习目标

- 解释掩码离散扩散：先按均匀分布采样的比例遮盖词元，再让 Transformer 恢复它们的调度方法。
- 从速度与质量两方面比较并行图像解码（Show-o、MaskGIT）和自回归图像解码（Chameleon、Emu3）。
- 说出 Show-o 用一个检查点处理的三项任务：T2I、VQA、图像修复。
- 选择一种掩码调度（余弦、线性、截断），并分析它对样本质量的影响。

## 问题

Transfusion 的双损失训练能够工作，但其动态更难控制——连续扩散损失与离散 NTP 损失处于不同数值尺度。平衡损失权重需要进行超参数搜索。这个架构有效，却很复杂。

Show-o 的答案是：像 Chameleon 一样让两种模态都保持离散，但通过掩码离散扩散并行生成图像，而不是逐个词元生成。训练目标变成单一的掩码词元预测，它可以自然地泛化下一词元预测。

## 概念

### 掩码离散扩散（MaskGIT）

Chang 等人（2022）最初提出的 MaskGIT 技巧非常优雅。从一幅完全被遮盖的图像开始（每个词元都是特殊的 `<MASK>` ID）。每一步并行预测所有被遮盖词元，然后保留置信度最高的 top-K 个预测，重新遮盖其余词元。经过约 8～16 次迭代后，所有词元都被填入。每一步解除多少词元遮盖由调度策略决定——余弦调度效果很好。

训练很简单：从 [0, 1] 均匀采样一个掩码比例，将其应用到图像的 VQ 词元，再训练 Transformer 恢复被遮盖的词元。这与 BERT 对文本所做的事情完全相同，只是扩展到了图像生成。

### Show-o：一个 Transformer，一种混合掩码

Show-o 把 MaskGIT 放进因果语言模型 Transformer。注意力掩码如下：

- 文本词元：因果注意力（标准大语言模型）。
- 图像词元：在图像块内部完全双向（因此预测时，被遮盖词元可以看到其他所有图像词元）。
- 文本到图像：文本关注先前图像，图像关注先前文本。

训练会在以下三类数据间交替进行：
1. 文本序列上的标准 NTP。
2. T2I 样本：文本 → 带掩码的图像词元，使用掩码词元预测损失。
3. VQA 样本：图像 → 带掩码的文本词元（实质上仍是 NTP）。

统一损失是 `<MASK>` 词元上的交叉熵，它既涵盖文本 NTP（只有最后一个词元被“遮盖”），也涵盖图像掩码扩散（随机子集被遮盖）。

### 并行采样

Show-o 大约用 16 步生成一幅图像，而不是自回归方式的约 1000 步，也不是扩散方式的约 20 步。每一步都并行预测全部被遮盖词元，提交置信度最高的 top-K，再重复这一过程。

比较如下：
- Chameleon / Emu3（对词元进行自回归）：N_tokens 次前向传播，通常每幅图像需要 1024～4096 次。
- Transfusion（连续扩散）：约 20 步，每一步都执行完整 Transformer 前向传播。
- Show-o（掩码离散扩散）：约 16 步，每一步都执行完整 Transformer 前向传播。

在规模相近的模型上，Show-o 比 Chameleon 更快；它的步骤数大致与 Transfusion 相同，但每一步成本更低（离散词表 Logit，而不是连续 MSE 损失）。

### 一个检查点处理多种任务

Show-o 在推理时支持四项任务，由提示词格式选择：

- 文本生成：标准自回归文本输出。
- VQA：输入图像，输出文本。
- T2I：输入文本，通过掩码离散扩散输出图像。
- 图像修复：输入部分词元被遮盖的图像，再填充缺失内容。

图像修复能力直接来自掩码预测训练，无须额外成本。只需遮盖 VQ 词元网格的一块区域，输入其余部分与一条文本提示词，再预测被遮盖词元。

### 掩码调度

每一步解除多少词元的遮盖，会决定生成质量。Show-o 推荐余弦调度：

```
mask_ratio(t) = cos(pi * t / (2 * T))   # t = 0..T
```

第 0 步全部词元被遮盖（比例为 1.0），第 T 步没有词元被遮盖。余弦调度把更多变化集中在预测信息量最大的中间比例。线性调度也能工作，但会更早进入平台期。

### Show-o2

Show-o2（2025 年后续工作，arXiv 2506.15564）扩展了 Show-o：使用更大的语言模型基座、更好的分词器和改进的掩码调度，架构模式保持不变。

### Show-o 所处的位置

在 2026 年的分类体系中：

- 离散词元 + NTP：Chameleon、Emu3。简单，但推理速度慢。
- 离散词元 + 掩码扩散：Show-o、MaskGIT、LlamaGen、Muse。并行采样，但仍受分词器有损性的限制。
- 连续表示 + 扩散：Transfusion、MMDiT、DiT。质量最高，但训练更复杂。
- VLM 中的连续表示 + 流匹配：JanusFlow、InternVL-U。最新路线。

根据任务选择：如果需要一个具备合理速度、能够同时执行 T2I + 图像修复 + VQA 的开放模型，选择 Show-o；如果质量最重要，而且能承担双损失管道，选择 Transfusion。

## 练习

1. 掩码离散扩散大约用 16 步采样。为什么不是 1 步？如果在第 0 步解除所有词元的遮盖，会破坏什么？

2. 掩码扩散天然支持图像修复。提出一个真实或假想的产品场景，说明 Show-o 的图像修复为什么优于专用模型。

3. 比较余弦调度与线性调度：当 T=8 时，追踪每一步解除遮盖的词元数。哪一种更加均衡？

4. 一幅 512x512 的 Show-o 图像包含 1024 个词元。词表大小 K=16384 时，模型输出 1024 * log2(16384) = 14,336 比特（约 1.75 KiB）数据。Stable Diffusion 输出 512*512*24 = 6,291,456 比特（约 768 KiB）原始像素。压缩率是多少？它换来了什么质量？

5. 阅读 LlamaGen（arXiv:2406.06525）。LlamaGen 的类别条件自回归图像模型，与 Show-o 的掩码方法有何不同？

## 关键术语

| 术语 | 人们常说 | 实际含义 |
|------|-----------------|------------------------|
| 掩码离散扩散 | “MaskGIT 风格” | 训练模型预测被遮盖词元；推理时迭代解除置信度最高预测的遮盖 |
| 余弦调度 | “解除遮盖调度” | 推理步骤中掩码比例的衰减方式；使置信度增长集中在中间阶段 |
| 并行解码 | “一次预测全部词元” | 每一步通过一次前向传播预测完整的被遮盖词元序列，再提交 top-K |
| 混合注意力 | “因果 + 双向” | 文本词元之间使用因果注意力、图像块内部使用双向注意力的掩码 |
| 图像修复 | “填充式生成” | 以部分词元被遮盖的图像为条件，预测缺失词元；该能力直接来自训练目标 |
| 提交率 | “每步 top-K” | 每轮被声明为“完成”的词元数量；控制推理成本与质量之间的取舍 |
