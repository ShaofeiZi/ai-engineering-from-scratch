# Qwen-VL 系列与动态帧率视频

> Qwen-VL 系列——Qwen-VL（2023）、Qwen2-VL（2024）、Qwen2.5-VL（2025）、Qwen3-VL（2025）——是 2026 年最具影响力的开放视觉—语言模型谱系。每一代都在架构上做出一个决定性的选择，随后十二个月内便被开放生态广泛借鉴：通过 M-RoPE 实现原生动态分辨率、结合绝对时间对齐的动态帧率采样、ViT 中的窗口注意力，以及结构化智能体输出格式。到 Qwen3-VL 时，配方已经稳定下来：使用支持原生宽高比输入的 2D-RoPE ViT 编码器，通过 MLP 投影器连接大型 Qwen3 语言基座，并在训练阶段把 OCR、定位和智能体行为作为一等目标。本课按时间顺序梳理这一系列，让你理解每个调节项为何如此设置。

**Type:** 学习
**Languages:** Python (stdlib, M-RoPE encoder + dynamic-FPS sampler)
**Prerequisites:** 第 12 阶段 · 第 06 课（patch-n'-pack）
**Time:** 约 120 分钟

## 学习目标

- 计算 M-RoPE 的三个轴向旋转（时间、高度、宽度），并解释为何三者缺一不可。
- 为视频选择动态帧率采样策略，并分析每秒词元数与事件检测准确率之间的取舍。
- 按顺序说出 Qwen-VL 四代模型的升级，以及每项升级带来的能力。
- 接入 Qwen2.5-VL 风格的 JSON 智能体输出格式，并从 VLM 响应中解析结构化工具调用。

## 问题

Qwen-VL 于 2023 年 8 月发布，直接回应 LLaVA-1.5 与 BLIP-2。Qwen 团队瞄准了三个方面的差距：分辨率、视频与结构化输出。

分辨率：LLaVA-1.5 以 336x336 运行。用于照片还可以，面对中文发票或密集的电子表格截图就毫无用处。Qwen-VL 的首项创新是使用 448x448 分辨率和带定位的边界框输出，让模型能够指向对象。

视频：Video-LLaMA 堆叠逐帧编码器，再把输出送入大语言模型。它适合短视频，却不适合以时间轴为主要信号的数分钟视频。Qwen 团队希望用单个编码器理解时间。

结构化输出：LLaVA 输出自由文本，而智能体需要 JSON。Qwen-VL 使用显式 JSON 输出格式进行训练，其中包括以文本表示的边界框坐标。

Qwen-VL 的每一代都沿这三个轴中的一个继续扩展。

## 概念

### Qwen-VL（2023 年 8 月）

第一代采用 OpenCLIP ViT-bigG/14 作为编码器（25 亿参数）、兼容 LLaMA 的 Q-Former（一步处理 256 个查询）以及 Qwen-7B 基座。主要贡献包括：

- 448x448 分辨率（当时开放 VLM 的业界最佳水平）。
- 定位能力：使用显式坐标词元输出的图文对训练。例如：“The cat is at <box>(112, 204), (280, 344)</box>”。
- 从一开始就使用中英双语训练。

当时的基准表现是：英语能力可与 GPT-4V 竞争，中文能力占据领先地位。定位监督才是真正的亮点。

### Qwen2-VL（2024 年 9 月）——M-RoPE 与原生分辨率

Qwen2-VL 用原生动态分辨率的 ViT 编码器，替换固定分辨率 + Q-Former 技术栈。主要变化包括：

- 原生动态分辨率。ViT 可以接收任意 HxW 且可被 28 整除的图像（Patch 14 并执行 2 倍空间合并）。一幅 1120x672 图像会产生 40x24 个合并图像块，即 960 个视觉词元。不缩放、不平铺、无缩略图。
- M-RoPE（多模态 RoPE）。每个词元携带三维位置（t、h、w），而不是一维位置。图像的 t=0，视频的 t=frame_index。RoPE 按每个轴的频率旋转查询/键向量，不需要位置嵌入表。
- MLP 投影器。移除 Q-Former，在合并后的图像块词元上使用两层 MLP。
- 使用动态 FPS 的视频。视频默认按 1～2 FPS 采样，但模型可以接受任意帧数。

结果是：Qwen2-VL-7B 在多个多模态基准上追平 GPT-4o，并在 DocVQA 上击败它（94.5 对 88.4）。架构变更是决定性的一步。

### Qwen2.5-VL（2025 年 2 月）——动态 FPS + 绝对时间

Qwen2.5-VL 的重大变化发生在视频侧。动态 FPS 不只是“需要时多采几帧”；论文进行了明确设计：

- 绝对时间词元。不使用位置索引（帧 0、1、2……），而使用实际时间戳。“在 0:04 时，猫跳了起来。”模型会看到与帧词元交错的 `<time>0.04</time>` 词元。
- 动态 FPS。慢速视频按 1 FPS 采样，动作场景按 4 FPS 以上采样。由用户或训练器选择，M-RoPE 自行适配。
- ViT 中的窗口注意力。空间注意力局限在局部窗口中，以提高吞吐量；每隔若干层执行一次全局注意力。
- 显式 JSON 输出格式。使用工具调用数据训练，例如：“{"tool": "click", "coords": [380, 220]}”。模型开箱即可充当智能体。
- MRoPE-v2 缩放。位置会按最大输入大小缩放，因此 10 分钟视频也不会耗尽频率范围。

基准结果：Qwen2.5-VL-72B 在多数视频基准上击败 GPT-4o，在文档任务上追平 Gemini 2.0，并在 GUI 定位上创下开放模型的最佳成绩（ScreenSpot：84% 准确率，而 GPT-4o 为 38%）。

### Qwen3-VL（2025 年 11 月）

Qwen3-VL 是一次整合式渐进升级，而不是重新发明架构：采用更大的语言模型基座（Qwen3-72B）、扩充训练数据、改善 OCR，并通过 Qwen3 的“思考模式”增强推理。ViT 与 M-RoPE 保持不变。论文重点是数据与训练改进，而不是架构。

这一谱系带来的结论是：到 2025 年，Qwen-VL 架构已经稳定。后续各代扩展的是计算与数据，而不是基本原语。

### M-RoPE 的数学原理

经典 RoPE 会旋转查询 `q`；它使用成对坐标，根据查询维度 `d` 和位置 `m` 完成旋转：

```
q_rot[2i]   = q[2i]   * cos(m * theta_i) - q[2i+1] * sin(m * theta_i)
q_rot[2i+1] = q[2i]   * sin(m * theta_i) + q[2i+1] * cos(m * theta_i)
theta_i     = 10000^(-2i/d)
```

M-RoPE 把隐藏维度拆成三个频带。假设 `d = 96`，分别为时间、高度和宽度分配 32 个维度。每个频带按对应轴的位置旋转。位于（t=5、h=10、w=20）的图像块，会在三个频带上分别应用旋转 `R_t(5)`、`R_h(10)`、`R_w(20)`。

文本词元使用 `t = text_index, h = 0, w = 0`（或某种归一化选择），以保持兼容。视频帧使用 `t = frame_time, h = row, w = col`，单幅图像则使用 `t = 0`。

好处是：一种位置编码就能处理文本、图像与视频，无须分支代码，也不需要不同的位置表。

### 动态 FPS 采样逻辑

给定时长为 `T` 秒的视频和目标词元预算 `B`：

1. 计算可负担的最大 FPS：`fps_max = B / (T * tokens_per_frame)`。
2. 从 `{1, 2, 4, 8}` 中选择满足 `fps <= fps_max` 的目标 FPS。
3. 如果运动幅度高（根据光流启发式或用户显式要求），选择更高 FPS；如果运动幅度低，则选择更低 FPS。
4. 以选定 FPS 均匀采样，并在帧之间插入 `<time>t</time>` 词元。

Qwen2.5-VL 会在训练中隐式学习这套逻辑；推理时用户通过 `fps` 参数控制。一段 60 秒的动作视频若按 4 FPS 采样、每帧 81 个词元，总计为 19440 个词元，可以放入 32k 上下文。

### 结构化智能体输出

Qwen2.5-VL 的智能体训练显式以结构化工具调用为目标：

```
{
  "tool": "mouse_click",
  "coords": [1024, 512],
  "button": "left",
  "modifier": null
}
```

解析是确定性的：对模型输出执行 JSON.parse。相比之下，自由文本“click at (1024, 512)”需要使用正则表达式，并处理歧义。这项转变使 Qwen2.5-VL 的 ScreenSpot 分数从 Qwen2-VL 的 55% 跃升到 84%。

## 关键术语

| 术语 | 人们常说 | 实际含义 |
|------|-----------------|------------------------|
| M-RoPE | “多模态 RoPE” | 在隐藏维度中划分时间、高度与宽度频带的三维旋转位置嵌入 |
| 动态 FPS | “智能采样” | 根据运动幅度、视频时长与词元预算为每段视频选择帧采样率 |
| 绝对时间词元 | “时间戳词元” | 序列中交错的 `<time>t</time>`，让模型看到实际秒数而不是帧索引 |
| 窗口注意力 | “局部注意力” | 空间自注意力只在小窗口内运行以提高速度；每隔若干层加入全局注意力 |
| 结构化智能体输出 | “JSON 模式” | 通过训练数据监督，教 VLM 输出包含坐标与工具名称的可解析 JSON |
| min_pixels / max_pixels | “分辨率边界” | Qwen2.5-VL 的逐请求控制参数，用于限制总像素数，从而限制词元数 |
| 定位 | “指向它” | 以文本词元输出边界框坐标；从 Qwen-VL 第一代起就已使用 |
