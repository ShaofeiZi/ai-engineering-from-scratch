# LLaVA-OneVision：一个模型统一单图、多图与视频

> LLaVA-OneVision（Li 等，2024 年 8 月）出现之前，开放 VLM 世界存在彼此分离的谱系：LLaVA-1.5 处理单幅图像，Mantis 与 VILA 等模型处理多幅图像，Video-LLaVA 和 Video-LLaMA 等模型处理视频。每个模型都能赢得自己的基准，却会在其他基准上失败。LLaVA-OneVision 主张，一套统一课程可以训练出一个同时主导三种场景的模型，而且涌现出的任务迁移效应（单图技能迁移到视频，多图推理迁移到单图）会超过多个专用模型之和。其配方看似简单：在各种场景间保持恒定的视觉词元预算，再采用从单图到 OneVision（多图）、最后到视频的显式课程。本课会解读这套预算、课程与涌现行为。

**Type:** 构建
**Languages:** Python (stdlib, token budget solver + curriculum planner)
**Prerequisites:** 第 12 阶段 · 第 05 课（LLaVA）、第 12 阶段 · 第 06 课（任意分辨率）
**Time:** 约 180 分钟

## 学习目标

- 设计一套在单图、多图与视频输入之间保持恒定的视觉词元预算。
- 安排训练课程顺序，使技能能够从单图迁移到视频，同时避免灾难性遗忘。
- 解释课程设计正确时，为何参数量相同的单一模型能够胜过多个专用模型。
- 说出 LLaVA-OneVision 报告的三种涌现能力：多摄像头推理、标记集提示、iPhone 截图智能体。

## 问题

单图、多图与视频会从不同方面考验模型。

单图需要高分辨率词元（AnyRes，约 2880 个视觉词元），以捕捉 OCR 内容和细微细节。每个样本的预算：一幅图像，2880 个词元。

多图需要多幅中等分辨率图像（每幅约 576 个词元），让跨图推理可以放入上下文。每个样本的预算：4～8 幅图像，每幅 576 个，共 2300～4600 个词元。

视频需要大量低分辨率帧（空间池化后每帧约 196 个词元），以捕捉时间动态。每个样本的预算：8～32 帧，每帧 196 个，共 1600～6200 个词元。

如果分别训练模型，你可以为每个模型选择一种预算；如果训练一个模型，则需要让预算在各种场景间合理伸缩，而不撑爆上下文。

OneVision 之前的默认答案是“训练一种场景，忽略其他场景”。Video-LLaVA 通过额外训练阶段，把视频能力改装到图像模型上。LLaVA-NeXT 使用平铺方式添加多图支持。它们都无法干净地统一三种场景。

## 概念

### OneVision 词元预算

LLaVA-OneVision 为每个样本设定约 3000～4000 个词元的统一视觉预算，并针对不同场景采用不同分配方式：

- 单图：AnyRes-9（3x3 图块 + 缩略图），每个图块使用 384 分辨率并产生 729 个图像块，经激进的 2x2 双线性池化 → 每图块 182 个词元。总计：9 * 182 + 182 = 1820 个词元。或者使用 AnyRes-4，每图块 729 个词元 = 2916 + 729。
- 多图：每幅图像采用中等分辨率（384，不平铺），不池化时为 729 个词元。6 幅图像的预算 → 4374 个词元。
- 视频：32 帧、384 分辨率，经激进的 3x3 双线性池化 → 每帧 81 个词元。总计：32 * 81 = 2592 个词元。

这种分配让总词元数大致保持恒定。大语言模型不会遇到撑爆上下文的批次。编码器会针对不同场景输出不同几何形态，但大语言模型消耗的预算相同。

### 三阶段课程

LLaVA-OneVision 分三个阶段训练：

1. 单图 SFT（SI 阶段）。全部数据都是单图 + 文本。使用高分辨率 AnyRes 输入进行训练，学习感知、OCR 与细粒度理解。数据包括 LLaVA-NeXT 数据和 OneVision 专用单图数据。
2. OneVision SFT（OV 阶段）。混合单图 + 多图 + 视频（均匀采样帧），并在统一词元预算下训练。这会教会模型处理异构批次形状。不重置权重——直接从 SI 阶段继续。
3. 任务迁移（TT 阶段）。继续使用目标任务混合训练，通常根据产品需求增加多图或视频的比重。部署前可选择进一步微调。

关键在于课程顺序。即便使用相同数据，先训练视频或多图，也会比先训练单图导致更差的图像性能。论文对此进行了明确消融。

### 课程为何有效

单图训练建立感知基础。图像块词元承载细粒度视觉特征，大语言模型则学会将其与文本融合。多图与视频引入结构性难题（哪幅图是哪幅、什么先发生），如果没有坚实的感知基础，就很难学会。

如果从头开始混合训练所有场景，模型会对感知欠拟合（每个批次中的单图数据有限），却对结构过拟合（多图/视频数据很多）。最终模型学会了遵循跨图推理模式，但视觉理解很浅。

课程排序先通过 SI 阶段获得强大的感知能力，再通过 OV 阶段学习组合与时间推理，同时保留二者。

### 跨场景涌现技能

LLaVA-OneVision 论文报告了三种涌现能力：

1. 多摄像头推理。模型分别在多图与视频上训练；推理时让它分析一个多摄像头驾驶场景。尽管训练中从未见过这种确切格式，模型仍能正确整合各视角。
2. 标记集提示。用户在图像中的物体上添加编号标记，模型推理“标记 3 相对于标记 7 正在做什么”。模型既没有在标记数据上训练，也没有在标注任务上训练，却从空间定位 + 多图引用的组合中学会了这种能力。
3. iPhone 截图智能体。用户提供 iPhone 屏幕截图，并要求规划下一次点击。模型接受过 UI 截图、用户工作流视频和多图前后对比样本的训练，因此能够泛化到智能体使用场景。

这些并不是训练任务，而是从课程的组合结构中涌现出来的能力。

### 视觉词元池化

词元预算要求进行池化。OneVision 在二维图像块网格上使用双线性插值：24x24 = 576 个图像块，会变成 12x12 = 144（缩小 2 倍）或 8x8 = 64（缩小 3 倍）。池化发生在图像块网格空间，而不是词元空间，以保留局部性。

每种场景所用的池化因子本身也是一个超参数。池化越少 → 词元越多 → 表示越丰富；池化越多 → 词元越少 → 能装入更多帧/图像。

### LLaVA-OneVision-1.5

2025 年的后续工作 LLaVA-OneVision-1.5（arXiv 2509.23661）在训练数据、模型权重和代码方面“完全开放”。它在部分基准上缩小了与专有模型的差距，并让这套方案更加普及。课程相同，数据更多，基础大语言模型更好，架构没有变化。

### 与 Qwen2.5-VL 对比

Qwen2.5-VL（第 12.09 课）采用了不同选择：它使用 M-RoPE 和动态 FPS，而不是固定池化。它的预算会随输入增长——一分钟视频使用的词元多于五秒视频。LLaVA-OneVision 则固定预算并调整池化比例。两种方案都有效；它们是在可配置性与可预测性之间做取舍。

## 投入使用

`code/main.py` 是面向 OneVision 风格 VLM 的课程与预算规划器。给定每个样本的词元预算，以及目标场景组合（例如 40% 单图、30% 多图、30% 视频），它会：

- 为每种场景分配分辨率、池化因子和帧数。
- 检查每种场景是否都能放入共享预算。
- 报告预期词元数、大语言模型 FLOPs，以及哪些场景的词元分配不足。
- 打印逐阶段训练计划。

可以用它规划 OneVision 微调，也可以对 VLM 部署的每请求成本进行合理性检查。

## 交付成果

本课会产出 `outputs/skill-onevision-budget-planner.md`。给定目标任务分布和单样本预算，它会输出 AnyRes 因子、逐帧池化、视频帧数与课程阶段权重。训练或微调统一场景 VLM 时都可以使用它。

## 练习

1. 你的产品支持 80% 单图、10% 多图（2～4 幅图像）、10% 视频（8～16 帧）。设计词元预算。因为不需要处理大量多图而节省出的预算，你会分配到哪里？

2. 阅读 LLaVA-OneVision 第 4.3 节（涌现能力）。提出一种课程可能解锁、但论文没有报告的第四种涌现技能。

3. 调换课程顺序——先训练多图，再训练单图，最后训练视频。预测哪些基准会退化，并解释原因。

4. 论文报告的视频基准每个样本只使用 8 帧训练。这能否在推理时泛化到 30 秒视频？词元预算与时间推理中，哪一个会先失效？

5. 把 24x24 个图像块双线性池化为 12x12，会使词元总量减少 4 倍。使用标准库 Python 实现池化，并验证每个 2x2 块的均值与双线性输出一致。

## 关键术语

| 术语 | 人们常说 | 实际含义 |
|------|-----------------|------------------------|
| OneVision 场景 | “单图、多图或视频” | 统一 VLM 处理的三种输入形态之一；预算在三者之间保持恒定 |
| 词元预算 | “每个样本有多少词元” | 大语言模型在每个训练/推理样本中看到的视觉词元总数，通常为 3000～4000 |
| 课程 | “训练顺序” | 为获得涌现式迁移而选择的阶段顺序（单图 → 多图 → 视频） |
| 双线性池化 | “缩减词元” | 对二维图像块网格应用双线性插值，在保留局部性的同时减少词元数量 |
| 涌现技能 | “没训练过也能做” | 由于课程组合而在推理时出现、却没有对应训练数据的能力 |
| AnyRes-k | “k 图块配置” | k 个固定分辨率子图块再加一张缩略图，常见 k ∈ {4, 9} |
| 任务迁移 | “跨场景泛化” | 通过共享骨干，让单图上学到的技能应用到视频（反之亦然） |
