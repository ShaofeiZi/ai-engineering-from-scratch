# 任意分辨率视觉：Patch-n'-Pack 与 NaFlex

> 真实图像并不是 224x224 的正方形。收据是 9:16，图表是 16:9，医学扫描可能达到 4096x4096，手机截图则是 9:19.5。2024 年之前 VLM 的做法——把所有图像缩放成固定正方形——会丢掉 OCR、文档理解与高分辨率场景解析赖以工作的信号。NaViT（Google，2023）证明，可以使用分块对角掩码，把不同分辨率的图像块打包进同一个 Transformer 批次。Qwen2-VL 的 M-RoPE（2024）彻底舍弃绝对位置表。LLaVA-NeXT 的 AnyRes 把高分辨率图像平铺为一幅基础图像加若干子图像。SigLIP 2 的 NaFlex 变体（2025）如今已成为开放 VLM 的默认编码器，使一个检查点可以服务所有宽高比。本课将端到端实现 patch-n'-pack。

**Type:** 构建
**Languages:** Python（标准库，图像块打包器 + 分块对角掩码）
**Prerequisites:** 第 12 阶段 · 第 01 课（ViT 图像块）、第 12 阶段 · 第 05 课（LLaVA）
**Time:** 约 120 分钟

## 学习目标

- 把一个批次中不同分辨率图像的图像块打包为单个序列，并构建分块对角注意力掩码。
- 针对具体任务，在 AnyRes 平铺（LLaVA-NeXT）、NaFlex（SigLIP 2）和 M-RoPE（Qwen2-VL）之间做出选择。
- 在不缩放图像的情况下，计算 OCR、图表与摄影任务的词元预算。
- 说出正方形缩放的三种失效模式：文字被压扁、内容被裁掉、在填充上浪费词元。

## 问题

Transformer 需要序列输入，而一个批次则由长度相同的多个序列堆叠而成。如果图像都是 224x224，每次都会得到 196 个图像块词元，不需要填充，问题就解决了。用 224 训练、用 224 推理，从此不必再考虑分辨率。

但现实并不配合。文档是纵向的（8.5x11 英寸，接近 2:3），图表截图是横向的（16:9），收据又高又窄（1:3），医学影像达到 2048x2048 或更大，移动设备截图则是 1170x2532（0.46:1）。

2024 年之前有三种方案，它们各自都会失败：

1. 缩放为固定正方形（224x224 或 336x336）。挤压会扭曲文字与人脸，缩小则会破坏图表标签与 OCR 内容。这在 LLaVA-1.5 之前一直是标准做法。
2. 裁剪为固定宽高比。这样会丢弃图像的大部分内容，而选择裁剪位置本身就是另一个视觉问题。
3. 填充到最长边。它消除了扭曲，却会让纵向图像把 50% 以上的词元浪费在填充上，而且所有这些填充词元仍要承担二次方注意力成本。

2024～2025 年的答案是：让 Transformer 直接处理图像原生分辨率下的图像块，并设法把异构批次打包成一个序列，不浪费计算量。

## 概念

### NaViT 与 patch-n'-pack

NaViT（Dehghani 等，2023）首次证明这种方法可以大规模运行。其思路完全是机械性的：

1. 对批次中的每幅图像，按选定图像块大小（例如 14）计算原生图像块网格。
2. 把每幅图像的图像块展平为各自长度可变的序列。
3. 把所有图像的图像块拼接成该批次的一条长序列。
4. 构建分块对角注意力掩码，使图像 A 的图像块只能关注图像 A 内部。
5. 携带每个图像块的位置信息（2D RoPE 或分数位置嵌入）。

一个包含三幅图像的批次——336x336（576 个词元）、224x224（256 个词元）和 448x336（768 个词元）——会变成一条包含 1600 个词元的序列，并带有 1600x1600 的分块对角掩码。没有填充，也没有浪费计算。Transformer 可以处理任意宽高比。

NaViT 还引入了训练期间的分数图像块丢弃——在整个批次中随机丢弃 50% 的图像块——既起到正则化作用，也能加速训练。SigLIP 2 继承了这种做法。

### AnyRes（LLaVA-NeXT）

LLaVA-NeXT 的 AnyRes 是一种务实的替代方案。给定高分辨率图像与只支持固定分辨率（CLIP 或 SigLIP 336）的编码器，将图像平铺：

1. 从预定义集合中选择最符合图像宽高比的网格布局——（1x1）、（1x2）、（2x1）、（1x3）、（3x1）、（2x2）等。
2. 按该网格切分完整图像；每个图块都变成 336x336 的裁剪图。
3. 另外生成一张缩略图：把整幅图像缩放到 336x336，作为全局上下文词元。
4. 用冻结的 336 编码器编码每个图块，再拼接图块词元 + 缩略图词元。

对于一幅 672x672 图像，采用 2x2 网格再加缩略图：4 * 576 + 576 = 2880 个视觉词元。代价高昂但效果很好——大语言模型既能看到局部细节，也能看到全局上下文。

当编码器被冻结且只支持一种分辨率时，AnyRes 是首选方案。但它会让大图像的词元数暴涨（一幅 1344x1344 图像使用 4x4 网格会产生 9216 + 576 ≈ 9800 个词元，足以占满 8k 大语言模型上下文的大部分空间）。

### M-RoPE（Qwen2-VL）

Qwen2-VL 引入了多模态旋转位置嵌入。它不使用 NaViT 的分数位置，也不采用 AnyRes 的图块 + 缩略图，而是让每个图像块携带三维位置（时间、高度、宽度）。查询/键旋转能够处理任意 H、W 与时间长度。

M-RoPE 原生支持动态分辨率，不需要重新训练。推理时可输入任意 HxW 图像；图像块嵌入器产生 H/14 x W/14 个词元，每个词元都有（t=0、r=行、c=列）位置，RoPE 以正确频率旋转注意力，至此完成。Qwen2.5-VL 与 Qwen3-VL 延续了这种设计。InternVL3 的 V2PE 采用了相同思想，只是为各模态使用不同编码。

与 AnyRes 不同，M-RoPE 在原生分辨率下需要 O(H x W / P^2) 个词元，没有成倍增加的图块开销。与 NaViT 不同，它仍要求一次前向传播只处理一幅图像；要在一个批次中处理不同分辨率，仍需在上层应用 patch-n'-pack。

### NaFlex（SigLIP 2）

NaFlex 是 SigLIP 2 检查点的原生灵活模式。单个模型在推理时可处理多种序列长度（256、729、1024 个词元）。内部训练使用 NaViT 风格的 patch-n'-pack，并为每个图像块使用绝对分数位置。它的卖点是：只需一个检查点，即可在推理时根据任务选择词元预算。

语义任务（分类、检索）使用 256 个词元，OCR 或图表理解使用 1024 个词元，无须重新训练。

### 打包掩码

分块对角掩码是大多数实现容易出错的地方。一个长度为 `N_total` 的打包序列覆盖图像 `i=0..B-1`，各图像长度为 `n_i`。掩码 `M` 的形状为 `(N_total, N_total)`；只有在两个索引落入同一幅图像的块内时才为 1，否则为 0。可以通过累计长度列表构建：

```
offsets = [0, n_0, n_0+n_1, ..., N_total]
M[i, j] = 1 iff there exists b where offsets[b] <= i < offsets[b+1] and offsets[b] <= j < offsets[b+1]
```

在 PyTorch 中，使用 `torch.block_diag` 或显式 gather 即可一行实现。FlashAttention 的变长路径（`cu_seqlens`）会完全跳过掩码，直接使用累计长度张量，在各序列内部执行注意力；对典型批次而言，它比分配稠密掩码快约 10 倍。

### 词元预算

根据任务选择策略：

- OCR / 文档：1024～4096 个词元。使用 1024 词元的 SigLIP 2 NaFlex，或 AnyRes 3x3 + 缩略图。
- 图表与用户界面：原生 384～448 分辨率下使用 729～1024 个词元。使用带最大像素数上限的 Qwen2.5-VL 动态分辨率。
- 自然照片：256～576 个词元就足够了。下游大语言模型已经能够看到充分信息。只在内容密度高的地方投入词元。
- 视频：空间池化后每帧 64～128 个词元，每秒 2～8 帧。第 12.17 课会详细介绍。

2026 年的生产规则是：为每类任务设置最大像素数上限，在该上限内按原生宽高比编码，将批次打包，并跳过填充。Qwen2.5-VL 正是通过 `min_pixels` 与 `max_pixels` 暴露这项调节能力。

## 投入使用

`code/main.py` 使用整数像素坐标，为一个包含不同图像尺寸的异构批次实现 patch-n'-pack。它会：

- 接收一组（H, W）图像尺寸。
- 在图像块大小为 14 时，计算每幅图像的图像块序列长度。
- 将它们打包成一条总长度为 `sum(n_i)` 的序列。
- 构建分块对角注意力掩码（为便于理解，使用稠密形式）。
- 比较打包、正方形缩放与 AnyRes 平铺的成本。
- 为混合批次（收据、图表、截图、照片）打印词元预算表。

运行它。最终得到的数字正是 2026 年每个开放 VLM 都使用 patch-n'-pack 的原因。

## 交付成果

本课会产出 `outputs/skill-resolution-budget-planner.md`。给定一个混合宽高比的工作负载（OCR、图表、照片、视频帧）与总词元预算，它会选择正确策略（NaFlex、AnyRes、M-RoPE 或固定正方形），并生成逐请求配置。为产品确定 VLM 规模时应使用这项技能——它可以防止延迟预算被悄然暴增十倍的词元量摧毁。

## 练习

1. 一张收据的分辨率是 600x1500（1:2.5）。图像块大小为 14 时，原生分辨率会产生多少词元？缩放为 336x336 的正方形后又会产生多少词元？实践中，哪种处理方式造成的 OCR 准确率损失更大？

2. 为长度分别为 256、576、729、1024 的四幅图像构建分块对角掩码。验证注意力矩阵是 2585x2585，并且恰好有 `256^2 + 576^2 + 729^2 + 1024^2` 个非零元素。

3. 对一幅 1792x896 图像，比较：（a）缩放成 336 的正方形后编码；（b）AnyRes 2x1 + 缩略图；（c）使用 M-RoPE 按原生分辨率处理。哪一种使用的词元最少？哪一种保留的细节最多？

4. 实现分数图像块丢弃：给定一条打包序列，均匀随机丢弃 50% 的词元，并相应更新分块对角掩码。测量掩码稀疏度的变化。

5. 阅读 Qwen2-VL 论文（arXiv:2409.12191）第 3.2 节。用两句话说明 `min_pixels` 与 `max_pixels` 控制什么，以及为什么两个边界都很重要。

## 关键术语

| 术语 | 人们常说 | 实际含义 |
|------|-----------------|------------------------|
| Patch-n'-pack | “NaViT 风格打包” | 把来自不同图像、长度各异的图像块序列拼接到一个批次维度 |
| 分块对角掩码 | “打包掩码” | 将每幅图像的图像块限制为只能关注自身、不能关注包中相邻图像的注意力掩码 |
| AnyRes | “LLaVA-NeXT 平铺” | 把高分辨率图像切成固定大小的图块网格，再加一张全局缩略图；用固定编码器处理每个图块 |
| NaFlex | “SigLIP 2 原生灵活模式” | 单个 SigLIP 2 检查点在推理时无需重新训练，即可覆盖 256、729、1024 三档词元预算 |
| M-RoPE | “多模态 RoPE” | 三维旋转位置编码（时间、行、列），无须位置表即可处理任意 H、W、T |
| cu_seqlens | “FlashAttention 打包” | FlashAttention 变长路径用来替代稠密分块对角掩码的累计长度张量 |
| min_pixels / max_pixels | “分辨率边界” | Qwen2.5-VL 的逐请求调节参数，用于限制极小或极大输入的词元数量 |
| 视觉词元预算 | “每幅图像多少词元” | 每幅图像输出的图像块词元概数；它决定大语言模型的提示词预算与注意力成本 |
