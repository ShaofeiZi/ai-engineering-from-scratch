# 原生稀疏注意力（DeepSeek NSA）

> 当上下文达到 64k 词元时，注意力会占据 70%～80% 的解码延迟。每家开放模型实验室都在设法解决这个问题。真正站稳脚跟的是 DeepSeek 的 NSA（ACL 2025 最佳论文）：三条并行注意力分支——压缩后的粗粒度词元、选择性保留的细粒度词元，以及负责局部上下文的滑动窗口——再通过学习得到的门控加以组合。它适配硬件（便于实现高效内核），可原生训练（在预训练中直接使用，而不是推理时临时外挂），并且在 64k 解码中比 FlashAttention 更快，质量则达到或超过完整注意力。本课会端到端构建这三条分支，并说明为何这种稀疏性可以端到端求导。

**Type:** 构建
**Languages:** Python（标准库）
**Prerequisites:** 阶段 7 · 12（KV 缓存、Flash Attention）、阶段 7 · 15（注意力变体）、阶段 10 · 16（差分注意力）
**Time:** 约 60 分钟

## 学习目标

- 准确说出 NSA 的三条注意力分支，以及每条分支捕获的内容。
- 解释为何此前的稀疏注意力方法只能用于推理，而 NSA 可以“原生训练”。
- 以压缩块大小与选择 top-k 为变量，计算 NSA 在 64k 上下文下相对于完整注意力节省的计算量。
- 使用标准库 Python 在短合成序列上实现三分支组合，并验证门控权重的行为。

## 问题

序列长度为 N 时，完整注意力需要 `O(N^2)` 时间与每层 `O(N)` 的 KV 缓存。上下文达到 64k 词元时，计算量与内存带宽需求都极其惊人。NSA 论文给出的理论测算显示：在 64k 上下文解码中，注意力占总延迟的 70%～80%。所有下游指标——TTFT、每秒词元数、每百万词元成本——都会被注意力成本主导。

稀疏注意力是显而易见的答案。此前的方法分为两类。固定模式稀疏（滑动窗口、跨步、块局部）会丢弃信息，在长距离召回任务上失效。推理时稀疏（KV 缓存剪枝、H2O、StreamingLLM）被应用于使用稠密注意力预训练的模型，只能取得一部分潜在加速，因为模型从未学习如何沿稀疏模式传递信息。

原生稀疏注意力（Yuan 等，DeepSeek + PKU + UW，ACL 2025 最佳论文，arXiv:2502.11089）把两方面结合起来：模型在预训练期间学习稀疏模式，同时算法适配硬件内核，推理时可以真正兑现计算节省。两年后，NSA 或它的直接后继者会成为所有前沿长上下文模型的默认注意力。

## 概念

### 三条并行分支

对于每个查询，NSA 会针对 KV 缓存的三种不同视图分别运行注意力：

1. **压缩分支。** 词元按大小为 `l`（通常为 32 或 64）的块分组，每块经由小型学习式 MLP 压缩为一个摘要词元。查询关注这些压缩词元，从而获得整个序列的粗粒度视图。

2. **选择分支。** 利用压缩分支的注意力分数，找出与当前查询最相关的 top-k 个块。读取这些块中的细粒度（未压缩）词元，再让查询关注其中全部词元。可以把压缩分支的注意力理解为选择过程的路由信号。

3. **滑动窗口分支。** 查询关注最近的 `W` 个词元（通常为 512），捕获另外两条分支可能漏掉、结构性较强的短距离模式（语法、局部共指）。

三条分支的输出通过学习得到的逐位置门控组合：

```
out = g_cmp * out_cmp + g_sel * out_sel + g_win * out_win
```

`g_cmp, g_sel, g_win` 是由查询上的小型 MLP 产生的门控权重。它们无须加总为 1，可以独立决定各分支的权重。

### 为什么它可以“原生训练”

选择步骤（top-k 块）是离散的，而离散操作会切断梯度流。此前的稀疏注意力工作要么跳过选择过程的反向传播（限制训练能力），要么使用连续松弛，却无法在推理时产生真正的稀疏性。

NSA 巧妙绕过了问题：压缩分支注意力本身就是作用于完整序列的可微粗粒度注意力。`top_k` 操作只是复用压缩分支中最高的注意力分数，决定要加载哪些细粒度块。梯度会流经压缩分支分数（同时影响压缩输出与选择逻辑），而被选块对最终输出的贡献同样可微。不可微的 top-k 操作在前向计算图上相当于无操作——它只控制从内存加载哪些块。

因此，NSA 可以端到端用于预训练。模型会学习如何通过三条分支共同路由信息，生成一种在推理时能够真正兑现加速的稀疏模式。

### 硬件友好的内核

NSA 内核针对现代 GPU 内存层级设计。外层循环按 GQA 组加载查询，内层循环按组获取相应的稀疏 KV 块，再在 SRAM 上运行注意力。由于同一查询组共享被选块（按查询组而非查询头选择），KV 加载成本可以在组内摊销，算术强度也保持较高水平。

论文报告称，其 Triton 内核在 64k 解码上比 FlashAttention 快 9 倍，而且加速比会随序列长度增长。前向与反向内核均已提供。

### 计算预算

令 `N` 为序列长度、`l` 为压缩块大小、`k` 为 top-k 选择数量、`w` 为滑动窗口、`b` 为被选块大小（通常等于 `l`）。

- 压缩分支：每个查询处理 `O(N/l)` 个键，因此总复杂度为 `O(N * N / l)`。
- 选择分支：每个查询处理 `O(k * b)` 个键，因此总复杂度为 `O(N * k * b)`。
- 滑动分支：每个查询处理 `O(w)` 个键，因此总复杂度为 `O(N * w)`。

总复杂度为 `O(N * (N/l + k*b + w))`。

当 `N = 64k, l = 64, k = 16, b = 64, w = 512` 时，每个查询的成本为 `1000 + 1024 + 512 = 2536 keys`；完整注意力则需 `64000 keys`，计算量减少 25 倍。

当 `N = 128k, l = 64, k = 16, b = 64, w = 512` 时，每个查询的成本为 `2000 + 1024 + 512 = 3536 keys`；完整注意力则需 `128000 keys`，计算量减少 36 倍。上下文越长，收益越大——这正是设计目的。

### 与其他方法相比

| 方法 | 可微？ | 真实推理加速？ | 长距离召回 |
|--------|---------------|----------------------|-------------------|
| 仅滑动窗口 | 是 | 是 | 失败 |
| 跨步/块稀疏 | 是 | 是 | 部分保留 |
| KV 剪枝（H2O、StreamingLLM） | 不适用（推理时） | 是 | 部分保留 |
| MoBA（Moonshot） | 部分 | 是 | 良好 |
| NSA | 是（原生） | 是（64k 时快 9 倍） | 与完整注意力相当 |

MoBA（Moonshot，arXiv:2502.13189）同期发表，采用了类似“三条路径优于一条”的思路，把 MoE 原理应用于注意力块。NSA 与 MoBA 是理解 2026 年长上下文预训练必须掌握的两种架构。

## 动手构建

`code/main.py` 在一段短合成序列上实现三条分支，并展示：

- 压缩 MLP（为便于教学，使用简单均值池化作为基线；真正的 NSA 使用学习式 MLP）。
- 由压缩分支分数驱动的 top-k 块选择。
- 对最近 `w` 个词元执行滑动窗口注意力。
- 门控组合。
- 与完整注意力对比的计算量输出。

### 第 1 步：把词元压缩成块

```python
def compress(K, l):
    n = len(K)
    n_blocks = (n + l - 1) // l
    out = []
    for b in range(n_blocks):
        start, end = b * l, min((b + 1) * l, n)
        block = K[start:end]
        summary = [sum(row[d] for row in block) / len(block) for d in range(len(K[0]))]
        out.append(summary)
    return out
```

### 第 2 步：压缩分支注意力

让查询对压缩后的键运行 Softmax 注意力。压缩分支的分数同时作为 top-k 选择信号。

### 第 3 步：选择 top-k 块

选出压缩块中得分最高的 `k` 个索引，加载这些块里的原始未压缩词元，再对它们运行注意力。

### 第 4 步：滑动窗口注意力

取最后 `w` 个词元，对它们运行标准注意力。

### 第 5 步：门控并组合

查询上的小型 MLP 会生成三个门控权重。最终输出是三条分支输出的加权和。

### 第 6 步：统计计算量

打印每条分支对每个查询关注的键数量及其总和，并与 `N`（完整注意力）比较。对于长度为 1024、`l = 32, k = 4, w = 128` 的合成序列，NSA 每个查询会看到 `32 + 128 + 128 = 288` 个键，而完整注意力会看到 1024 个——少 3.5 倍。

## 学以致用

NSA 已用于 DeepSeek 自己的长上下文预训练流水线。截至 2026 年 4 月，公开推理技术栈的集成状态如下：

- **DeepSeek 内部：** 原生支持；已发布权重使用 NSA 或其后继 DSA（DeepSeek Sparse Attention）。
- **vLLM：** 正在开发面向 DeepSeek-V3.x 权重的实验性 NSA 支持。
- **SGLang：** 已发布 NSA 基准；生产路径跟随 vLLM。
- **llama.cpp / CPU：** 不支持；在 CPU 吞吐量下，拆分内核的开销得不偿失。

适合采用 NSA 的情况：

- 目标上下文为 64k 以上、计算预算充足的预训练或继续训练任务。
- 推理 DeepSeek 自己的长上下文检查点，因为这些权重原生使用 NSA。

不适合采用 NSA 的情况：

- 服务一个已经预训练好的稠密注意力模型。没有继续训练，就无法事后加装 NSA。
- 上下文短于 16k。三分支开销会超过节省量。
- 批大小为 1 的交互式聊天。只有上下文很长时，延迟敏感的解码才能受益。

## 关键术语

| 术语 | 人们通常怎么说 | 实际含义 |
|------|----------------|------------------------|
| 压缩分支 | “粗粒度视图” | 在块平均后的键上运行注意力，每个查询处理 O(N/l) 个键，以获得全局上下文 |
| 选择分支 | “top-k 块” | 对压缩分支分数最高的 `k` 个块执行细粒度注意力 |
| 滑动窗口 | “局部上下文” | 对最近 `W` 个词元执行注意力，捕获短距离模式 |
| 原生可训练性 | “预训练时就启用稀疏性” | 稀疏模式在预训练期间学习，而不是在推理时临时外挂 |
| 压缩块大小 l | “粗粒度视图的分组大小” | 合并成一个摘要词元的词元数量；典型值为 32～64 |
| Top-k | “要保留的块” | 读取其中未压缩词元的最高分压缩块数量；典型值为 16 |
| 滑动窗口 W | “局部注意力半径” | 典型值为 512；更短会损害局部连贯性，更长则浪费计算 |
| 分支门控 | “如何混合三条分支” | 逐位置 MLP 的输出，用于为三条分支的贡献加权 |
| 硬件适配 | “内核友好的稀疏模式” | 选择能让实际 GPU 内核兑现理论加速的稀疏模式 |
| DSA | “NSA 的后继者” | DeepSeek Sparse Attention，即 DeepSeek 架构谱系中 NSA 之后的架构 |
