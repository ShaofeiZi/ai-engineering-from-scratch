# 推测解码与 EAGLE-3

> 阶段 7 · 第 16 课已经证明了数学原理：Leviathan 拒绝规则会精确保留验证模型的分布。本课从训练技术栈的角度介绍 2026 年的生产级推测解码。EAGLE-3 不再把草稿模型视为廉价近似，而是将其改造成一个专门设计的微型网络，使用验证模型自身的隐藏状态训练；它还加入训练时测试循环，使训练分布与推理分布对齐。最终结果是：端到端加速 3～6.5 倍，聊天任务的逐词元接受率超过 0.9，而且不牺牲输出分布。2026 年的每套生产推理技术栈都会默认提供它。

**Type:** 构建
**Languages:** Python（标准库）
**Prerequisites:** 阶段 7 · 16（推测解码数学）、阶段 10 · 12（推理优化）

## 学习目标

- 用一句话陈述 Leviathan 定理，并证明推测循环产生的样本与验证模型的分布完全相同。
- 梳理从普通推测解码（Leviathan，2023），到 EAGLE、EAGLE-2、EAGLE-3 的两年演进，并明确每一步消除了哪项限制。
- 根据接受率 `α` 与草稿模型相对验证模型的成本比 `c` 计算预期加速比，并为不同情形选择最佳草稿长度 `N`。
- 从零实现完整推测循环：起草、验证、拒绝后从残差分布采样、拒绝时回滚 KV 缓存，以及全部接受时输出奖励词元。

## 问题

一个 70B 模型在 H100 上进行自回归解码，速度可能只有每秒 35 个词元，而 GPU 离饱和还很远。瓶颈是内存带宽：每生成一个词元，都要从 HBM 加载 70B 权重，执行一步计算，再生成一个浮点结果；计算单元大部分时间都处于空闲状态。

推测解码把它转化为真正可以解决的吞吐量问题。廉价草稿模型通过 `N` 次小型前向传播提出 `N` 个词元，验证模型则针对前缀加全部 `N` 个草稿只运行一次。如果验证模型在位置 `i` 的分布与草稿相符——稍后会精确定义这种统计意义上的“相符”——就接受；否则拒绝，并从残差分布采样一个修正词元。一次大型模型前向传播不再只生成一个词元，而是最多接受 `N+1` 个词元。

关键定理由 Leviathan、Kalman 与 Matias（ICML 2023）提出：输出分布与直接从验证模型采样得到的分布完全相同。不是近似，而是完全一致。这正是推测解码能够用于生产的根本原因——它是纯粹的延迟优化，不牺牲质量。

阶段 7 · 第 16 课讲解了数学，本课则讲解训练技术栈。优质草稿模型带来的加速可比廉价草稿模型高 2 倍。EAGLE、EAGLE-2 与 EAGLE-3（Li 等，2024～2025）把“草稿 = 同族模型的较小版本”发展成一套精确的工程方法。2026 年的生产推理服务器默认使用 EAGLE-3。

## 概念

### 不变量：Leviathan 拒绝采样

令 `p(t)` 表示给定某个前缀时，草稿模型对下一词元的分布；令 `q(t)` 表示验证模型的分布。从 `d ~ p` 采样一个草稿词元，并以 `min(1, q(d) / p(d))` 的概率接受。若拒绝，则从残差分布 `(q - p)_+ / ||(q - p)_+||_1` 中采样。最终样本服从 `q`。无论 `p` 多差，这一点都成立——越差只会导致拒绝越频繁，输出仍然精确。

把 `N` 次这样的调用首尾相接，让验证模型对 `prefix + d_1 + ... + d_N` 只执行一次前向传播。验证模型会同时返回 `q_1, q_2, ..., q_{N+1}`。从左向右检查；若在位置 `j` 首次拒绝，就从 `residual(q_j, p_j)` 采样并停止；若全部接受，则从 `q_{N+1}` 额外采样一个奖励词元。

### 决定加速比的因素

令 `α` 表示每个草稿词元的预期接受率，`c = cost(draft) / cost(verifier)` 表示成本比。每次验证模型前向传播所接受的预期词元数为：

```
E[accepted] = (1 - α^(N+1)) / (1 - α)
```

每个已接受词元的预期总耗时为 `(N * c + 1) / E[accepted]`。对 `N` 最小化该表达式即可找到最佳点。若 `α = 0.8, c = 0.05`，最优 `N` 约为 5～7，加速比为 3.2 倍；若 `α = 0.95, c = 0.02`，最优 `N` 约为 8～10，加速比接近 5 倍。

最大的单一杠杆是 `α`。将 `α = 0.6`（普通草稿）提高到 `α = 0.9`（EAGLE-3），并固定 `N = 5` 时，每次验证模型前向传播接受的预期词元数会从 2.2 增至 4.1。同一个验证模型的吞吐量几乎翻倍。

### 两年演进

**普通推测解码（Leviathan，2023）。** 草稿模型是同一家族中独立训练的较小语言模型。接入简单，`α ≈ 0.6`，最佳加速比约为 2 倍。

**EAGLE-1（Li 等，2024）。** 草稿模型是一个微型 Transformer，通常只有一两层；它接收验证模型最后一层的隐藏状态，并直接预测下一词元。由于草稿能看到验证模型的特征表示，其分布更接近验证模型，`α` 提高到 0.7～0.8。

**EAGLE-2（Li 等，2024）。** 加入动态草稿树：不再提出一条包含 `N` 个词元的单一序列，而是生成一棵小型候选树，让验证模型通过一次前向传播（树注意力）为所有候选评分，再沿最高概率路径行进。每一步的草稿长度都可以自适应调整，已接受路径上的逐词元 `α` 提高到 0.85 以上。

**EAGLE-3（Li 等，2025，NeurIPS）。** 又做了两项改动。第一，彻底移除特征预测损失——EAGLE-1/2 训练草稿去匹配验证模型隐藏状态，这限制了增加数据所带来的收益；EAGLE-3 直接训练词元预测。第二，引入训练时测试（TTT）：训练草稿时，让它在多个步骤中把自身先前预测重新作为输入，与推理时的运行方式相同。这使训练分布与测试分布对齐，阻止误差累积。实测结果为：聊天任务最高加速 6.5 倍；在 H100 上使用 SGLang、批大小为 64 时，吞吐量提高 38%。

### KV 缓存回滚

一次验证会把验证模型的 KV 缓存向后扩展 `N` 个条目。如果在位置 `j` 拒绝，位置 `j-1` 之后的缓存内容已经错误。常见实现有两种：写入暂存缓冲区，接受后再提交（vLLM、TensorRT-LLM）；或者维护物理 KV 缓存与逻辑长度，在拒绝时截断。无论哪种方式，回滚成本都只是每层、每头的若干字节，相比前向传播成本可以忽略。

EAGLE-2 进行树搜索时，验证模型会使用符合树拓扑、而非因果关系的掩码运行注意力。工程实现比较繁琐，但计算本身仍是一次带自定义掩码的标准 Flash Attention 调用。

### 2026 年的草稿架构

| 策略 | 草稿类型 | `α` | 加速比 | 训练成本 |
|----------|-----------|-----|---------|---------------|
| 普通方案 | 独立小型语言模型 | 0.55～0.70 | 1.8～2.3 倍 | 无（复用已有小模型） |
| Medusa | 验证模型上的额外语言模型头 | 0.65～0.75 | 2～3 倍 | 约 1B SFT 词元 |
| EAGLE-1 | 隐藏状态上的单层 Transformer | 0.70～0.80 | 2.5～3 倍 | 约 60B 词元 |
| EAGLE-2 | EAGLE-1 + 动态草稿树 | 0.80～0.88 | 3～4 倍 | 约 60B 词元 |

## 动手构建

完整实现见 `code/main.py`。其中包含 Leviathan 推测循环的所有组成部分：一次起草 N 个词元、验证模型并行前向传播、逐位置拒绝、从残差分布采样、奖励词元、KV 回滚，以及通过实验证明输出分布与直接从 `q` 采样一致。

### 第 1 步：拒绝规则

```python
def accept(q_prob, p_prob, u):
    if p_prob <= 0:
        return True
    return u < min(1.0, q_prob / p_prob)
```

### 第 2 步：残差分布

```python
def residual(q, p):
    raw = [max(0.0, qi - pi) for qi, pi in zip(q, p)]
    s = sum(raw)
    if s == 0:
        return list(q)
    return [r / s for r in raw]
```

### 第 3 步：完整推测步骤

`spec_step` 函数先起草 `N` 个来自 `p` 的词元，再通过一次并行的 `q` 求值验证所有词元。它对每个草稿词元应用拒绝规则，在第一次拒绝时从残差分布采样修正词元。如果全部接受，就从 `q_{N+1}` 输出一个奖励词元。

### 第 4 步：KV 回滚记录

模拟器为每个工作进程跟踪逻辑 `kv_length`。接受 `k` 个草稿时，`kv_length += k`。如果在位置 `j` 拒绝，缓存此时已经写过 `j`，但逻辑长度会设为 `prefix_length + j + 1`——也就是修正词元之后的位置。后续读取会截断到逻辑长度。

### 第 5 步：Leviathan 检查

运行 50,000 个推测步骤，统计已接受词元的经验分布，再与从 `q` 直接采样 50,000 次的结果比较。卡方统计量应显著低于临界值。定理在实践中通过验证。

### 第 6 步：加速比与 α

以不同幅度扰动 `p`，使其偏离 `q`，从而扫描草稿质量。测量 `α`，再绘制每次验证模型调用的预期词元数随 `α` 和 `N` 变化的曲线。代码会打印一张表，展示 EAGLE-3 级草稿质量（`α ≈ 0.9`）如何让每次验证模型调用产出 4～5 个词元。

```bash
vllm serve meta-llama/Llama-3.3-70B-Instruct \
  --speculative-config '{
    "model": "yuhuili/EAGLE3-LLaMA3.3-Instruct-70B",
    "num_speculative_tokens": 5,
    "method": "eagle3"
  }'
```

根据 EAGLE-3 论文，在 H100 上以批大小 64 使用 EAGLE-3 的 SGLang，相比批大小同为 64 的普通解码，吞吐量约提高 1.38 倍。

适合使用推测解码的场景：

- 任何 p50 延迟比峰值吞吐量更重要的交互式聊天负载。
- 代码生成与结构化输出（JSON、SQL）。由于目标分布高度可预测，`α` 会超过 0.9。
- 长文本生成（数千个词元）。摊销后的加速会持续带来收益。

不适合使用的场景：

- 非常小的模型（< 3B）。草稿模型并不会比验证模型便宜多少。
- 微型、批大小为 1 的 CPU 部署。草稿模型的内存开销可能得不偿失。
- 温度极高、`α` 会大幅下降的创意采样。

## 关键术语

| 术语 | 人们通常怎么说 | 实际含义 |
|------|----------------|------------------------|
| Leviathan 规则 | “min(1, q 除以 p)” | 以 `min(1, q(d)/p(d))` 为概率执行伯努利接受/拒绝；拒绝后从残差采样，可精确保留验证模型分布 |
| 残差分布 | “q 减 p 的正部再归一化” | `(q - p)_+` 截断到零并重新归一化——拒绝时应采样的正确分布 |
| 接受率 α | “草稿正确的频率” | 拒绝规则下逐词元伯努利成功的期望概率；决定所有加速数学 |
| EAGLE-1 | “隐藏状态草稿” | 以验证模型最后一层隐藏状态为条件的微型 Transformer 草稿（Li 等，2024） |
| EAGLE-2 | “动态草稿树” | EAGLE-1 加候选续写树，并在一次验证模型传播中使用树注意力评分 |
| EAGLE-3 | “训练时测试” | 移除特征预测损失，直接训练词元预测，并在训练时把草稿自身输出重新送入草稿 |
| 训练时测试（TTT） | “暴露偏差修复” | 训练时以自回归方式运行草稿，使训练与测试输入分布匹配——计划采样的直接对应物 |
| KV 回滚 | “撤销被拒草稿” | 拒绝后把验证模型 KV 缓存重置到已接受前缀长度的记录操作 |
| 奖励词元 | “免费得到的那个词元” | 所有 `N` 个草稿均被接受时，无须额外验证成本即可从 `q_{N+1}` 再采样一个词元 |
| 树注意力 | “一次验证多个候选” | 使用符合草稿树拓扑的非因果掩码进行注意力计算；一次前向传播即可计算树中每个节点的 `q_i` |
