# 将指令遵循作为对齐信号

> 后续所有对 RLHF 的批评，都在反驳这条流水线的某个环节。在研究优化压力如何扭曲代理目标之前，你必须先看清这个代理目标。InstructGPT（Ouyang 等人，2022）确立了参考架构：先在指令—回答对上做监督微调，再用成对偏好排序训练奖励模型，最后针对奖励模型运行 PPO，并加入相对于 SFT 策略的 KL 惩罚。一个 13 亿参数的 InstructGPT 获得的偏好度超过了 1750 亿参数的 GPT-3。正是这一项结果，使 2026 年的每一家前沿实验室仍在交付具有 RLHF 形态的后训练流水线。

**Type:** 学习
**Languages:** Python（标准库，玩具三阶段流水线）
**Prerequisites:** 阶段 10 · 06（SFT）、阶段 10 · 07（RLHF）、阶段 10 · 08（DPO）
**Time:** 约 45 分钟

## 学习目标

- 说出 InstructGPT 流水线的三个阶段，以及每个阶段使用的损失函数。
- 解释为什么一个 13 亿参数的指令微调模型能在人类偏好评估中胜过未经对齐的 1750 亿参数 GPT-3。
- 说明第 3 阶段的 KL 惩罚要防范什么，以及移除它为何会让策略坍缩为寻模行为。
- 描述对齐税，以及 Ouyang 等人用来缓解它的 PPO-ptx 方法。

## 问题

预训练语言模型的工作是续写文本，而不是回答问题。让 GPT-3“编写一个反转列表的 Python 函数”，你往往会得到另一个问题，因为其大部分训练分布来自网页文本，而网页文本后面通常仍接着更多网页文本。模型的确在完成自己的工作——只是这项工作并不是我们想要的。

所有严肃实验室用来修正这一问题的代理信号都是人类偏好。把两个补全结果交给标注员，由标注员选择更好的一个，再让奖励模型学习标注员的选择。然后，强化学习循环推动策略生成奖励模型评分更高的输出。用三句话就能概括 InstructGPT 的完整论点，论文其余部分主要解决工程实现。

## 概念

### 阶段 1：监督微调（SFT）

收集提示—回答对，其中的回答应当符合一位善意人类的写法。Ouyang 等人使用了来自标注员和 OpenAI API 的 1.3 万条提示，再通过标准交叉熵损失在这些数据上微调基础模型。

SFT 带来的结果是：模型开始回答问题，而不是继续续写问题。它没有提供的是：当多个回答都看似合理时，标注员更偏好哪一个回答的信号。

### 阶段 2：奖励模型（RM）

针对每条提示，从 SFT 模型采样 K 个补全结果，由标注员对它们排序。训练一个奖励模型，为任意提示—回答对评分；对于 `y_w` 优于 `y_l` 的配对，损失为：

```
L_RM = -log sigmoid(r(x, y_w) - r(x, y_l))
```

这就是 Bradley-Terry 成对偏好损失。奖励模型通常从 SFT 模型初始化，只把语言模型头替换为输出标量的头。

奖励模型并不大：对于 1750 亿参数的 InstructGPT，60 亿参数就已经足够。它们也很脆弱——论文第 5 节的大部分内容都在讨论小规模实验中出现的奖励黑客行为。

### 阶段 3：带 KL 惩罚的 PPO

定义目标函数：

```
J(pi) = E_{x~D, y~pi(.|x)} [ r(x, y) ] - beta * KL(pi(.|x) || pi_SFT(.|x))
```

使用 PPO 最大化该目标。KL 项会阻止 `pi` 偏离 SFT 策略太远。没有这一项，优化器就会找到对抗样本——某些字符串之所以被奖励模型打出高分，是因为奖励模型从未见过它们，而不是因为人类真的更喜欢它们。

KL 系数 `beta` 是 RLHF 中最重要的单个超参数。它太低时会发生奖励黑客；太高时则相比 SFT 几乎没有改进。

### 对齐税

经过 RLHF 后，模型更受人类偏好，却会在标准基准（SQuAD、HellaSwag、DROP）上退步。Ouyang 等人把这种现象称为对齐税，并用 PPO-ptx 修复：把预训练梯度混入强化学习目标，避免模型遗忘那些从未获得奖励的下游任务能力。

```
J_ptx(pi) = J(pi) + gamma * E_{x~D_pretrain} [ log pi(x) ]
```

PPO-ptx 后来成为标准做法。Anthropic、DeepMind 和 Meta 都采用了某种变体。

### 实验结果

标注员在约 70% 的比较中，更偏好 13 亿参数的 InstructGPT（SFT + RM + PPO-ptx），而不是 1750 亿参数的基础 GPT-3。在来自生产流量的隐藏测试提示上，差距还会扩大。这个数字说明了两件事：

1. 对齐与能力是不同的维度。1750 亿参数模型具备更强能力；13 亿参数模型对齐得更好；标注员更偏好后者。
2. 能力下限由基础模型决定。你无法通过 RLHF，让基础模型掌握它从未见过的事实。

## 实际应用

`code/main.py` 会在玩具偏好数据上模拟三个阶段。基础“策略”是在动作 {A, B, C} 上有偏的硬币。阶段 1 的 SFT 模仿标注员在 200 条提示上的动作；阶段 2 根据 500 个成对排序拟合 Bradley-Terry 奖励模型；阶段 3 执行简化的 PPO 更新，并加入相对于 SFT 策略的 KL 惩罚。你可以观察奖励不断上升、KL 散度增大和策略发生漂移；也可以关闭 KL 项，观察奖励黑客如何在 50 个更新步骤内出现。

需要重点观察：

- `beta = 0.1` 与 `beta = 0.0` 时的奖励轨迹。
- 训练过程中 KL(pi || pi_SFT) 的变化。
- 最终动作分布与标注员偏好的对比。

2. 让奖励模型对动作 B 具有 +0.5 的偏置（模拟奖励缺陷）。使用 `beta = 0.1` 运行 PPO。KL 惩罚能阻止策略利用这一偏置吗？`beta` 取什么值时开始出现利用行为？

3. 阅读 Ouyang 等人论文（arXiv:2203.02155）的图 1。分别运行 1、5、20、100 个 PPO 步骤，并测量相对于 SFT 模型的偏好，从而重现标注员偏好曲线。

4. 论文第 4.3 节报告，13 亿参数 InstructGPT 约有 70% 的概率优于 1750 亿参数 GPT-3。为什么这一比例在隐藏的生产提示上，会比在标注员自己编写的提示上更高？

## 关键术语

| 术语 | 人们通常怎么说 | 实际含义 |
|------|-----------------|------------------------|
| SFT | “指令微调” | 阶段 1：在提示—回答对上使用交叉熵进行微调 |
| 奖励模型 | “RM” | 在（提示、回答）上输出标量的回归器，使用 Bradley-Terry 损失从成对标签训练得到 |
| Bradley-Terry | “成对偏好损失” | -log sigmoid(r_w - r_l)；把成对排序化为二分类问题 |
| KL 惩罚 | “正则项” | `beta * KL(pi \|\| pi_SFT)`——使强化学习策略保持在 SFT 锚点附近 |
| PPO-ptx | “混合预训练的 PPO” | 在 PPO 目标中加入一部分预训练对数似然，以抵消对齐税 |
| 对齐税 | “RLHF 退化” | RLHF 后，模型在 RLHF 未针对的标准基准上出现性能下降 |
| 标注员偏好 | “真实标签” | 人类排序的样本；RM 是这一信号的统计代理，而不是“人类价值观”的代理 |
